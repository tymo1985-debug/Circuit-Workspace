# Правила выдачи файлов (ZIP / commit)

Уровень: **ZIP/commit only**. Этот файл подгружается перед сборкой архива и
ни в какой другой момент. При обычной локальной правке он не нужен.

Общие правила рабочего режима — раздел «Рабочий режим» в `AGENTS.md`.
Подъём версий — `docs/rules/release.md`.

---

## 1. Перед сборкой архива

1. **Реклон.** Свежий `git clone --depth 1`, даже если клон делался в начале
   сессии: апстрим мог измениться, пока писался ответ.
2. **Дуальная проверка HEAD.** Оба источника, а не один:
   ```bash
   git ls-remote https://github.com/tymo1985-debug/Circuit-Workspace.git refs/heads/main
   curl -s https://github.com/tymo1985-debug/Circuit-Workspace/commits/main.atom
   ```
   GitHub API (`api.github.com`) часто отдаёт 403 — на него не опираться.
   Хэши обязаны совпасть. Не совпали — разбираться, а не собирать архив.
3. **База сравнения — `git show HEAD:<путь>`, никогда не рабочая копия.**
   В рабочей копии могут лежать непроверенные изменения; так уже было
   30.08.2026 (≈14 файлов с чужими правками посреди сессии).

## 2. Сверка с хабом — только при одном условии

Раньше это был пункт 4 раздела «Единственный источник правды» в `AGENTS.md`
и выполнялся при любой задаче, добавляя ~156 КБ контекста на каждую правку.
Вынесен сюда 30.08.2026 без изменения смысла.

**Условие срабатывания:** правка бралась из отдельного репозитория модуля
(`Assembly-Programm-`, `Circuit-Planner`, `Pioneer-School-Workspace`).
Эти репозитории могут быть устаревшими относительно монорепо и годятся
только как источник новой логики, но не как основа итоговых файлов.

Тогда — и только тогда:

1. Сверить построчным диффом, что в итоговый файл попала реальная новая
   логика, а не откат стилей/путей.
2. Проверить: (а) пути относительно корня монорепо; (б) CSS/стили монорепо
   не откачены версией из отдельного репо; (в) хабовые интеграции
   (`shared/*`, favicon, theme-color, `shared/nav.js`) сохранены во всех
   изменённых файлах.
3. Подтянуть `index.html` хаба и его интеграции (`shared/nav.js`,
   `shared/style.css`, `shared/version.js`) и убедиться, что модуль и хаб
   не разошлись.

Правка написана с нуля внутри монорепо — все три пункта пропускаются.

## 3. Обязательные проверки

- **Полный гейт:** `node scripts/check-all.mjs`, все 22 проверки, без
  сужения области. Коды: `0` — прошло; `1` — провал, выпускать нельзя;
  `2` — провалов нет, но часть проверок не выполнена (нет пакетов или
  истории git). Двойка намеренно не равна успеху: «не смогли проверить»
  и «проверили, всё хорошо» — разные вещи.
  Зависимости: `npm i jsdom jspdf acorn acorn-walk fake-indexeddb`.
  Клон `--depth 1` даёт пропуск проверки патч-бампа — это ожидаемо.
- **Живой прогон в Chromium** изменённых модулей (плюс хаб, если тронут
  `shared/*`): `scripts/live-run.mjs`, скриншот 430×900. Мокапы не
  заменяют прогон. Прогнать не удалось — сказать прямо и назвать проверку
  статической, не выдавая её за полную.
- Правка не касается кода вовсе (только документация) — живой прогон не
  нужен, но об этом сказать явно в отчёте.

## 4. Состав архива

- Один изменённый файл → отдать отдельно, без ZIP.
- Несколько → **один** ZIP только с изменёнными и новыми файлами, пути
  относительно корня монорепо.
- Нетронутые файлы внутрь не класть. Полный ре-зип репозитория — только по
  явному прямому запросу.
- **Удалений в архиве не бывает.** Файл надо удалить — отдельной строкой в
  тексте ответа:
  ```
  DELETE: path/to/file
  ```
  Алекс удаляет вручную в GitHub.
- Указать путь назначения каждого файла от корня монорепо. Папки в GitHub
  руками не создаются: путь вписывается в имя файла при загрузке.

## 5. Отчёт перед архивом

```
Read:    какие файлы пришлось открыть
Changed: какие изменены
Added:   какие созданы
Delete:  какие удалить (или «нет»)
```

## 6. После залива — пост-проверка (~10 секунд, обязательно)

Drag&drop папки целиком в GitHub может удалить файлы, которых нет внутри
перетаскиваемой папки: коммит выглядит как «залил обновление», а часть дерева
стёрта. Так уже ломался деплой (инцидент 06.08.2026, 8 файлов). Подробности
и рецепт восстановления — в `AGENTS.md`, раздел «Рабочий процесс с файлами».

```bash
git clone --depth 1 https://github.com/tymo1985-debug/Circuit-Workspace.git tmp && cd tmp
for f in shared/version.js */index.html service-worker.js \
         congress-project/service-worker.js circuit-planner/sw.js \
         pioneer-school/sw.js appointments/sw.js; do
  [ -e "$f" ] || echo "ПРОПАЛ: $f"
done
node scripts/check-versions.mjs
```

Пусто на выходе + «Версии согласованы» = залив прошёл целиком.
