# Правила выпуска и подъёма версий

Уровень: **release / version bump only**. Подгружается при подъёме версии
и ни в какой другой момент.

Сборка архива — `docs/rules/delivery.md`. Общий режим — раздел «Рабочий режим»
в `AGENTS.md`.

---

## 1. Версия объявляется ровно в одном месте

`shared/version.js` — единственный источник:

- `CW_VERSION` — версия оболочки хаба (в шапке + имя кэша SW);
- `CW_MODULES` — версии модулей для плиток.

В разметке `index.html` номеров версий нет вообще. Версия каждого модуля
должна быть видна в интерфейсе (топбар).

## 2. Цепочка подъёма

1. Поднять версию **внутри модуля**:
   - `congress-project/service-worker.js` → `APP_VERSION`
   - `circuit-planner/app.js` → `App.config.version`
   - `pioneer-school/js/app.js` + `pioneer-school/sw.js` → `APP_VERSION`
   - `appointments/sw.js` → `APP_VERSION`
2. То же значение — в `CW_MODULES`.
3. Поднять `CW_VERSION`.
4. `node scripts/check-versions.mjs` (он же в гейте и в CI — ловит
   расхождение раньше деплоя).
5. Запись в `CHANGELOG.md`: дата и краткое описание, только реально
   внесённые изменения.

Текущие версии смотреть в `shared/version.js` актуального клона, не по памяти
и не по записям в документации: записи устаревают тише кода.

## 3. Клиндарий — исключение в двух местах

- `circuit-planner/sw.js` версию **не хардкодит**: подключает
  `shared/version.js` через `importScripts` и берёт её из `CW_MODULES`.
  Побочный эффект намеренный — браузер при проверке обновления сверяет и
  импортированные скрипты, поэтому подъём версии в реестре сам инвалидирует
  кэш модуля.
- Клиндарий работает по stale-while-revalidate, остальные пять оболочек —
  cache-first. Патч-бамп ради доставки правки `shared/*` ему не требуется;
  остальным — требуется (см. ниже).

## 4. Патч-бамп при правке общего слоя

Тронут `shared/*` → патч-бамп **всех** модулей, кроме исключения выше.
Пять из шести оболочек cache-first: без бампа исправление не доедет до
вернувшегося пользователя — он останется на старом кэше и ошибка «не
воспроизводится» будет выглядеть как починенная.

Проверяет `scripts/check-shared-bump.mjs`. Ему нужна история git — на клоне
`--depth 1` проверка пропускается с кодом 2, это ожидаемо и не равно успеху.

## 5. Что нельзя терять при выпуске

- `settings.accentColor` **никогда** не удаляется из данных — он живёт в
  резервных копиях.
- Любой модуль, подключающий `shared/backup.js`, обязан подключать и
  `shared/version.js` — и в разметке, и в прекэше своего service worker'а.
  Без второго офлайн-копия теряет версии. Проверять эту пару вместе.
- Каждый новый файл модуля обязан попасть в `APP_SHELL_URLS` его
  service worker'а: онлайн всё работает, а офлайн модуль мёртв — класс
  ошибок бесшумный.
- Пороги в проверках — страховка от «разбор сломался», а не смысловое
  правило. Опускать порог можно только с явной записанной причиной (как
  `check-doclang.mjs`: 150 → 120 при легальном похудении словаря
  09.08.2026).

## 6. Порог размера AGENTS.md (решение 30.08.2026)

`scripts/check-context-budget.mjs` — в гейте с 30.08.2026, 23-я проверка.
Включена сразу после разрезания `AGENTS.md` (фаза 2): до него файл весил
413 КБ и гейт стал бы красным в первый же день.

- **> 16 КБ символов** — предупреждение, код возврата **0**. Именно 0, а не 2:
  двойка в гейте означает «проверка не выполнена», и смешивать с ней «файл
  растёт» нельзя — сигнал потеряется.
- **> 20 КБ символов** — провал, код 1.

**Меряются символы, не байты.** Контекст расходуется по символам, а кириллица
в UTF-8 занимает 2 байта на символ — байтовый порог урезал бы русский текст
вдвое против английского при той же реальной стоимости. Размер в байтах
печатается рядом справочно: `12.0K chars / 18.6 KB UTF-8 — OK`.

Проверка ловит ещё две вещи: новые чрезмерно большие `.md`/`.js` вне списка
`KNOWN_LARGE` и data-only файлы, не покрытые `.aiignore`. Обе — предупреждения.
Отсутствие самого `.aiignore` — провал: список «что не читать» потерян.
