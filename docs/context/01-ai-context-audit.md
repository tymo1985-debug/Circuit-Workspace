## 5. Разделение правил на уровни

Пять уровней. Каждый — отдельный файл; в `AGENTS.md` остаётся только таблица
«когда что подгружать».

### `always` → `AGENTS.md` (≈ 14 КБ)
Источник правды, стек, структура, правило версий, файловый обмен, точка входа
гейта, список «не читать», указатель.

### `module-specific` → `<модуль>/AGENTS.md` (2–4 КБ каждый)
Подгружается, только когда правка внутри этого каталога. Содержимое — см. §7.

### `shared-layer only` → `shared/AGENTS.md` (≈ 4 КБ)
Подгружается, только если тронут `shared/*`:
- патч-бамп всех модулей (пять из шести оболочек cache-first; исключение —
  Клиндарий со stale-while-revalidate для CSS);
- файл общего слоя, подключённый в разметке модуля, обязан лежать в прекэше
  его SW; пара `backup.js` → `version.js` — вместе;
- `matchOwn()` — свой кэш, не чужой;
- «спящих компонентов быть не должно»;
- прогон хаба вживую — **только здесь**, не при локальных правках модуля.

### `release/version bump only` → `docs/rules/release.md` (≈ 3 КБ)
Подгружается при подъёме версии:
- цепочка «версия внутри модуля → `CW_MODULES` → `CW_VERSION`»;
- `circuit-planner/sw.js` версию не хардкодит (importScripts);
- `node scripts/check-versions.mjs` + `check-shared-bump.mjs`;
- запись в `CHANGELOG.md`.

### `ZIP/commit only` → `docs/rules/delivery.md` (≈ 3 КБ)
Подгружается перед сборкой архива:
- реклон перед упаковкой (апстрим мог измениться);
- дуальная проверка HEAD: `git ls-remote` **и** `/commits/main.atom` (API часто
  отдаёт 403);
- **полный** `check-all.mjs` — все 22 проверки;
- живой прогон изменённых модулей (+ хаб, если тронут `shared/*`);
- ZIP только изменённых файлов, пути от корня монорепо, удалений в архиве нет;
- пункт 4 старого «Источника правды» (сверка с хабом) — **только** если правка
  бралась из отдельного репозитория модуля.

Таблица-маршрутизатор для `AGENTS.md`:

| Что трогаю | Что подгружаю |
|---|---|
| файл внутри одного модуля | `AGENTS.md` + `<модуль>/AGENTS.md` |
| `shared/*` | + `shared/AGENTS.md` |
| словарь / `data-i18n` | + `docs/journal/i18n.md` |
| CSS, токены, брейкпоинты | + `docs/journal/design-system.md` |
| PDF / печать | + `docs/journal/pdf-print.md` |
| SW, манифест, кэш | + `docs/journal/pwa-sw.md` |
| IndexedDB, бэкап, восстановление | + `docs/journal/db.md` |
| подъём версии | + `docs/rules/release.md` |
| сборка архива | + `docs/rules/delivery.md` |

### 5.1 Триггеры расширения области чтения

Таблица выше отвечает на вопрос «какой журнал открыть». Это **не то же самое**,
что «выйти за пределы своего каталога». Второй вопрос решается отдельным
закрытым списком из семи признаков — вне их область чтения остаётся в каталоге
модуля.

| Признак | Что подгружается сверх модуля | Какие проверки просыпаются |
|---|---|---|
| общая архитектура | `ARCHITECTURE.md` | — |
| shared layer (тронут `shared/*`) | `shared/AGENTS.md`, разметка всех потребителей | `check-shared-bump`, `check-shared-precache` |
| интеграция между модулями | корневой `index.html`, `shared/nav.js` | `check-hub-tiles` |
| версионирование | `docs/rules/release.md`, `shared/version.js` | `check-versions` |
| release / выдача архива | `docs/rules/delivery.md` | полный гейт, 22 проверки |
| service worker / cache | `docs/journal/pwa-sw.md`, `sw.js` модуля | `check-sw-cache-scope`, `check-shared-precache`, `check-sri` |
| общая схема данных | `docs/journal/db.md`, `shared/db.js`, `shared/backup.js` | `check-backup` |

Важно, чего в этом списке нет: **i18n, CSS и печать — не триггеры**. Правка
словаря Клиндария или его стилей остаётся локальной; подгружается профильный
журнал (`i18n.md`, `design-system.md`, `pdf-print.md`) и просыпаются профильные
проверки, но чужие модули и хаб при этом не открываются. Сегодняшний пункт 4
«Источника правды» стирает именно эту границу — он делает хаб обязательным
чтением при любой правке.

## 8. Безопасный постепенный split `circuit-planner/app.js` (план, не выполнять сейчас)

Ограничение: сборщика нет, `app.js` — один IIFE, всё живёт в замыкании,
файл прописан в прекэше `sw.js`. Значит дробить надо так, чтобы порядок
загрузки не имел значения и объект `App` собирался в одном месте.

**Механизм — реестр частей.** В `index.html` части подключаются **до**
`app.js`; каждая только регистрирует функцию, ничего не выполняя:

```js
// circuit-planner/ui/<часть>.js
(window.CPParts = window.CPParts || []).push(function (App) {
  Object.assign(App.ui, { /* методы */ });
});
```

В `app.js`, сразу после создания `App` и до `App.ui.bind()`:

```js
(window.CPParts || []).forEach(function (part) { part(App); });
```

Порядок скриптов при этом безразличен, `App` остаётся единственным объектом,
имена методов и точки вызова не меняются.

**Предусловие для частей, а не сам split:** четыре константы замыкания
(`VP_I18N_DICTS`, `DEFAULT_LETTER_TEMPLATE_HTML`, `DEFAULT_EMAIL_BODY_TEMPLATES`,
`LETTER_SUBJECT_PARTS`) должны переехать на `App.const`, иначе вынесенные
методы их не увидят. Это отдельный первый шаг, чисто механический.

**Порядок нарезки — от самого изолированного к связанному.** Один срез =
одна сессия = гейт + живой прогон Клиндария.

| № | Что выносим | Строки | ~строк | Почему безопасно |
|---|---|---|---:|---|
| 0 | inline `<style>` из `index.html` → `circuit-planner/style.css` | — | 37,6 КБ | JS не затронут; но нужен `check-css-vars` (область = страница) и запись в `APP_SHELL_URLS` |
| 1 | `ensureCalendarViewStyles` → `ui/calendar-styles.js` | 1882–2072 | 190 | чистая строка CSS, ноль зависимостей — пилот механизма |
| 2 | письма и композер → `ui/letters.js` | 2765–3260, 3443–3770, 3872–4282 | ≈ 1230 | замкнутая тема; требует шага «App.const» |
| 3 | календарь и служебный год → `ui/calendar.js` | 2072–2764 | ≈ 690 | опирается на `App.data`/`App.store`, не на соседей по `App.ui` |
| 4 | формуляр визита и документы визита → `ui/visit-form.js` | 3270–3442, 3776–3871 | ≈ 270 | локальная тема |
| 5 | события, напоминания, история → `ui/events.js` | 4285–4555 | ≈ 270 | локальная тема |

`App.ui.bind()` (387 строк, 4556–4943) **не трогаем** — он навешивает
обработчики на всё сразу и является самой связанной частью файла. Отдельная
задача после всех срезов.

После срезов 1–5 `app.js` ≈ 2800 строк вместо 5466; средняя правка UI открывает
файл на 200–1200 строк.

**Что обязано сопровождать каждый срез:** новый `<script>` в `index.html`,
новый путь в `APP_SHELL_URLS` файла `circuit-planner/sw.js`, патч-бамп
Клиндария, `node scripts/check-all.mjs`, живой прогон в Chromium
(`scripts/live-run.mjs`), обновление карты строк в `circuit-planner/AGENTS.md`.

**Риск:** метод, вынесенный из замыкания, тихо теряет доступ к локальной
переменной и падает только в рантайме — статический гейт этого не увидит.
Отсюда обязательность живого прогона на каждом срезе и правило «один срез —
одна выдача».

## 9. Какие глобальные проверки можно снять с локальных задач

Сейчас `scripts/check-all.mjs` — плоский список из 22 проверок без области
действия. Дескриптор проверки: `{ file, title, why, deps }` — поля `scope` нет.

**Предложение:** добавить в дескриптор `scope: [...]` и флаг `--scope=<путь>`.
Сами скрипты проверок **не менять** — меняется только `check-all.mjs`
(12,5 КБ, один массив и один фильтр). Полный прогон остаётся поведением
по умолчанию.

| Проверка | Когда действительно нужна |
|---|---|
| `check-versions` | подъём версии |
| `check-shared-bump` | тронут `shared/*` |
| `check-sri` | тронут `shared/vendor/*` или разметка со ссылками на него |
| `check-shared-precache` | тронут `shared/*` или разметка/`sw.js` модуля |
| `check-sw-cache-scope` | тронут любой `sw.js` / `service-worker.js` |
| `check-manifests` | тронут `manifest.json` |
| `check-hub-tiles` | тронут корневой `index.html` или `shared/version.js` |
| `check-breakpoints` | тронут CSS или CSS-строка в JS |
| `check-css-vars` | то же |
| `check-orphan-classes` | тронут CSS или разметка |
| `check-i18n-bridge`, `-coverage`, `-dupes`, `-html`, `-placeholders`, `-shadow`, `check-inline-lang-tables` | тронут словарь, `data-i18n`, языковая таблица в JS |
| `check-doclang` | тронуты Документы или их словарь |
| `check-escape` | тронут код, собирающий HTML строками |
| `check-lazy-pdf`, `check-print-ready` | тронут PDF/печать |
| `check-backup` | тронуты `shared/backup.js`, `shared/db.js`, схема данных |

Пример: правка одного CSS-правила в Назначениях —
`--scope=appointments` даёт 4 релевантные проверки вместо 22. Не только
контекст: `check-backup` тянет `fake-indexeddb`, `check-doclang` — `jsdom`
и `jspdf`; на итерации это лишние секунды и лишний вывод в контекст.

**Что при этом не ослабляем:** перед выдачей файлов и перед коммитом —
полный прогон всех 22. Правило «гейт зелёный до и после» сохраняется
дословно, сужается только итерационный цикл.

Аналогично живой прогон: сейчас предписан «изменённые модули плюс хаб, если
трогали `shared/*`». Формулировка уже правильная — но фактически из-за пункта 4
«Источника правды» хаб проверяют всегда. Пункт 4 переезжает в
`docs/rules/delivery.md` с оговоркой «только если правка бралась из отдельного
репозитория модуля», и хаб перестаёт участвовать в локальных задачах.

  ни одна не потребовала лезть в архив за фактом, который должен был остаться
  в ядре. Каждый такой случай — кандидат вернуть строку в `AGENTS.md`.
- **Полный гейт (22 проверки) и живой прогон** до и после — как обычно.
- **Риск:** низкий.
- **Эффект:** фиксация результата и защита от повторного разрастания —
  через полгода `AGENTS.md` без храповика снова будет 400 КБ.
- **Замер «до и после» — по трём типовым задачам**, в каждой считается сумма
  байт файлов из строки `Read:`:

  | Задача | Read сейчас | Read цель |
  |---|---:|---:|
  | правка одного CSS-правила в Назначениях | `AGENTS.md` + хаб `index.html` + `shared/style.css` + файл ≈ 575 КБ | `AGENTS.md` + `appointments/AGENTS.md` + файл ≈ 20 КБ |
  | добавить ключ в словарь Школы | `AGENTS.md` + `dict.js` (141 КБ) + `js/app.js` ≈ 622 КБ | `AGENTS.md` + `pioneer-school/AGENTS.md` + `i18n.md` + `grep` по словарю ≈ 90 КБ |
  | подъём версии модуля | `AGENTS.md` + `version.js` ≈ 420 КБ | `AGENTS.md` + `release.md` + `version.js` ≈ 25 КБ |

- **Нельзя потерять:** порог в `check-context-budget.mjs` — страховка от
  разрастания, а не смысловое правило; опускать или поднимать его можно только
  с явной причиной, записанной рядом (как порог `check-doclang.mjs`, опущенный
  со 150 до 120 при легальном похудении словаря). Проверка обязана быть
  прогнана на заведомо сломанном входе до того, как считаться готовой.
- **Отдельным patch/ZIP:** да, один-два файла.

## 12. Рабочий режим: minimal context / minimal patch (готовый текст)

Сокращение файлов снимает потолок расхода, но не задаёт поведение. Ниже —
блок правил, который делает локальность обязательной, а не возможной. Место —
`AGENTS.md`, сразу после «Файлового обмена»; в `CLAUDE.md` остаётся ссылка.

> ### Рабочий режим
>
> **Local task → local context → local patch.**
>
> 1. До чтения назвать минимальный набор файлов, нужный задаче. Список
>    расширяется по факту находки, а не «на всякий случай».
> 2. Глобальные документы (`CHANGELOG.md`, `docs/journal/*`, архив Done)
>    при локальной задаче не открываются. Профильный журнал — только по
>    таблице маршрутизации.
> 3. Data-only файлы — см. «❌ Что не читать». Правится генератор, не вывод.
> 4. Выход за пределы каталога модуля — только по одному из семи признаков
>    (см. «Триггеры расширения области»). Вне их хаб, `shared/*` и соседние
>    модули не читаются.
> 5. Полный аудит Workspace — только по явной просьбе Алекса.
> 6. Меняются только необходимые файлы. Файл не переписывается целиком, если
>    достаточно локальной правки. Косметические правки «заодно» не делаются.
> 7. В выдачу попадает только изменённое. Прочитанный, но не изменённый файл
>    в архив не кладётся никогда.
>
> **Отчёт перед каждой выдачей** — четыре строки, до архива:
>
> ```
> Read:    какие файлы пришлось открыть
> Changed: какие изменены
> Added:   какие созданы
> Delete:  какие удалить (или «нет»)
> ```
>
> Удаления в архив не кладутся — отдельной строкой `DELETE: path/to/file`
> в тексте ответа, файл Алекс удаляет в GitHub вручную. Это формализация
> уже действующего правила «архивы не содержат удалений».
>
> Если для мелкой задачи в `Read:` оказался длинный список несвязанных
> файлов — это дефект работы с контекстом. Объяснить в том же ответе, что
> заставило расширить чтение, и предложить правку правил, чтобы в следующий
> раз этого не потребовалось. Молчаливое расширение области — хуже самого
> расширения: оно не оставляет следа для исправления.

Строка `Read:` заодно даёт бесплатный замер: сумма байт перечисленных файлов —
это и есть расход контекста на задачу, и её можно сравнивать от задачи к задаче
без всякой инструментовки.
