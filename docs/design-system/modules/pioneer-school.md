# Школа пионеров (`pioneer-school`)

Макет: **`preview/pioneer-school.html`** · Версия на момент аудита: v1.6.0
Акцент: `#6a45c9` → `#9c3f9e` (фиолет → пурпур) · Знак: `school`

---

**1. Назначение экрана.** Управление школой пионерского служения: учащиеся, расписание уроков, замены, анкеты, формуляры, учебники, экспорт. Самый многосоставный модуль — **13 разделов**.

**2. Структура интерфейса.** Главная проблема — плоский список из 13 пунктов без группировки: `dashboard, anketa, assignment, registration, substitutes, students, textbooks, schedule, practical, review, afterschool, signlanguage, backup`. Найти нужный можно только перечитав весь список.

Предлагаемая группировка по смыслу:

| Группа | Разделы |
|---|---|
| **Школа** | Обзор, Учащиеся, Расписание, Замены |
| **Занятия** | Практика, Разбор, После школы, Жестовый язык |
| **Документы** | Анкета, Назначение, Регистрация, Учебники |
| **Данные** | Резервная копия |

Разделы не переименовываются и не объединяются — меняется только подача. Это правка разметки сайдбара, без изменения маршрутов.

**3. Заголовок, навигация, действия.** Шапка на всю ширину: знак, «Школа пионеров», версия, статус сохранения; справа — печать, настройки. Сайдбар с группами под шапкой. Счётчики (`24` учащихся, `2` замены) — в `.md-sidenav__badge`: они дают понять состояние, не заходя в раздел.

**4. Рабочие панели.** Экран «Обзор» — сводка из четырёх карточек (учащихся, анкет получено, занятий пройдено, замен) плюс таблица ближайших занятий. Сейчас обзор существует, но не даёт быстрого ответа «что горит».

Экран «Учащиеся» — таблица с фильтрами и плотным режимом. 24 записи в обычной плотности требуют прокрутки; в плотной помещаются целиком.

Экран «Анкета» — **визард с шагами** вместо одной длинной формы. Шаги: Личные данные → Служение → Здоровье → Проверка. Условные поля появляются переключателем (`.md-switch`), а не мгновенным раскрытием без объяснения.

**5. Иерархия действий.** На «Обзоре» основное — «Экспорт». На «Учащихся» — «Добавить», рядом контурный «Импорт». В визарде основное — «Далее», слева текстовое «Назад».

**6. Иконки.** `school`, `apps` (обзор), `group` (учащиеся), `calendar_month` (расписание), `person` (замены), `edit` (практика), `check` (разбор), `event` (после школы), `description` (документы), `mail` (назначение), `download`, `upload`, `print`, `settings`. Все в субсете.

**7. Пустой экран.** Разные для разных разделов: «Список учащихся пуст» с двумя кнопками — «Добавить» и «Импорт PDF» (у модуля есть импорт через pdf.js, о нём надо напоминать); «Расписание не составлено» с «Загрузить набор» (есть `data/seed-lessons.json`).

**8. Загрузка.** Импорт PDF — `.md-progress` с текстом «Разбор линий разметки, страница 2 из 5». Модуль определяет колонки по векторным линиям разметки; на многостраничном файле это заметно по времени.

**9. Ошибки и предупреждения.** Критично именно здесь: `.md-banner--warn` «Символы вне шрифта» с указанием поля. Урезанный шрифт **молча обрезает строку** — jsPDF обрывает весь вызов `text()` начиная с символа вне подмножества, без ошибки. От этого страхует `_sanitizeForFont()`, но пользователь должен видеть предупреждение, а не потерянный текст в готовом PDF.

**10. Узкий экран.** 13 разделов не помещаются в нижнюю навигацию — там 3 частых (Учащиеся, Расписание, Документы) + «Ещё» с полным списком. Таблицы → карточки. Визард анкеты на мобильном показывает только номер шага без подписей.

**11. Связь с хабом.** Фиолетово-пурпурный акцент. Важная деталь: акцент модуля `#6a45c9` **совпадает с сид-цветом всей палитры** — Школа визуально ближе всех к хабу, и это правильно, она самая «фирменная» из четырёх.

**12. Уникальное для модуля.**
- Визард анкеты.
- Карточки уроков с номером, темой и преподавателем.
- Редактируемая таблица с динамической системой колонок.
- Импорт PDF с определением колонок по линиям разметки.
- Экспорт в трёх форматах (PDF / XLSX / CSV).

## Границы: что нельзя трогать

| Что | Почему |
|---|---|
| `register.html` + `registrationSchema.js` | состав вопросов описан **дважды**, править нужно оба; в `TODO.md` есть задача рендерить одно из другого — до неё дизайн не лезет |
| `js/export/pdfFormExport.js` → `_finalizeForm` | `/DR` + `/DA` + `NeedAppearances` в AcroForm; без этого пользователь не сможет печатать кириллицу в готовой форме |
| `subset: false` при встраивании шрифта | иначе pdf-lib подрежет шрифт под уже использованные символы, и учащийся не введёт букву, которой не было в шаблоне |
| `_sanitizeForFont()` | страховка от молчаливого обрыва строки |
| `--sidebar-bg: #221947` | **можно и нужно менять** — это как раз источник гибрида; но только вместе с проверкой обеих тем |

## Порядок работ по модулю

Рекомендуется **начинать практическое внедрение именно с этого модуля** — обоснование в `07-integration.md`.

1. Снять `data-theme="light"`, подключить `shared/theme.js`.
2. Убрать хардкод `--sidebar-bg/ink/ink-soft` → токены поверхностей.
3. Сгруппировать 13 разделов в сайдбаре (разметка, маршруты не трогать).
4. `.btn-primary / .btn-secondary / .btn-text / .share-btn` → `.md-btn`.
5. `.data-table` / `.editable-table` → `.md-table` + расширения.
6. Шапка `route-header` → `.md-topbar-v2` + `.md-page__header`.
7. Анкета → визард `.md-stepper` (последним: затрагивает логику, а не только вид).
