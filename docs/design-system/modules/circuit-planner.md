# Клиндарий (`circuit-planner`)

Макет: **`preview/circuit-planner.html`** · Версия на момент аудита: v9.60.1
Акцент: `#4a3ab5` → `#12706f` (индиго → бирюза) · Знак: `calendar_month`

> **Самый рискованный модуль для переделки.** Монолитный `app.js` (307 КБ), инжектируемый CSS на `!important`, измерения из живого DOM, 28 уникальных хексов, PIN-слой, собственный выбор цвета акцента. Этот модуль трогаем **последним**.

---

**1. Назначение экрана.** Календарь служебного года: планирование посещений собраний, признаки недель, формуляр визита, форма S-302, письма собраниям. Работа идёт короткими сессиями, но регулярно, и часто с телефона.

**2. Структура интерфейса.** Шапка на всю ширину → сайдбар (Календарь / Собрания / Настройки + карточка признаков текущей недели) → рабочая область: панель месяца, сетка календаря, панель дня справа.

Сейчас сайдбар начинается от самого верха, и кнопка возврата в хаб оказывается внутри него — то есть в другом месте, чем в остальных модулях. После унификации шапка идёт поверх, возврат встаёт на общее место.

**3. Заголовок, навигация, действия.** В шапке: знак, «Клиндарий», версия, служебный год. Справа — поиск, напоминания, настройки. Листание месяцев и переключатель вида (Месяц / Два месяца / Список) — в `Toolbar` рабочей области, не в шапке: они относятся к содержимому.

**4. Рабочие панели.** Календарь + панель дня. Панель дня (`.md-sheet`) показывает карточку собрания, признаки (`Письмо`, `S-302`) и три действия: «Формуляр визита» (заполненная), «Письмо собранию» (контурная), «Редактировать» (текстовая).

Карточка признаков недели переезжает в сайдбар — сейчас эти флаги разбросаны по интерфейсу.

**5. Иерархия действий.** Основное — «Посещение» (добавить). В панели дня основное — «Формуляр визита»: это то, ради чего модуль открывают. Всё остальное второстепенно.

**6. Иконки.** `calendar_month`, `group` (собрания), `settings`, `add`, `search`, `notifications`, `mail`, `description` (S-302), `edit`, `close`. Все в субсете. Для листания назад нужен `chevron_left` — его нет; обход: `chevron_right` с поворотом на 180° через CSS.

**7. Пустой экран.** Пустой месяц: иконка `calendar_month`, «В сентябре посещений нет», объяснение — сначала нужно собрание в справочнике, кнопка «Добавить собрание». Важно вести именно туда: без записи в `events[]` посещение создать нельзя.

**8. Загрузка.** `.md-progress` при сборке PDF с текстом «Встраивание шрифтов Aptos, 1.2 МБ…». Четыре файла шрифтов Aptos занимают ~1.2 МБ; сейчас пользователь ждёт молча и жмёт кнопку второй раз.

**9. Ошибки и предупреждения.** `.md-banner--error` при незаполненной форме S-302 с указанием конкретного недостающего поля и кнопкой «Открыть» на карточку собрания. `.md-banner--info` в формуляре: «Язык формуляра берётся из настройки документа, а не из языка интерфейса» — это результат перехода на `shared/doclang.js` (v9.60.0), и его надо объяснить, иначе выглядит как баг.

**10. Узкий экран.** Нижняя навигация у модуля уже есть — сохраняется. Панель дня становится шторкой снизу. В сетке календаря события сжимаются до цветных полосок без текста.

**11. Связь с хабом.** Индиго-бирюзовый акцент в дорожке, знаке, сегодняшнем дне календаря, активном пункте навигации. Бирюза `#12706f` — тот же фирменный цвет, что `--md-tertiary` в общем слое, так что модуль связан с системой и через акцент, и через палитру.

**12. Уникальное для модуля.**
- **Сетка календаря** — остаётся собственным компонентом, в общую библиотеку не выносится.
- Панель дня с признаками.
- Карточка признаков недели (`flagLetter`, `flagS302`, приоритет).
- Встроенный выбор цвета акцента.
- PIN-слой.

## Границы: что нельзя трогать

| Что | Почему |
|---|---|
| `localStorage['service-year-planner-v9-4-2']` | смена ключа = потеря данных пользователей |
| `<style id="calendarViewStyles">` (`ensureCalendarViewStyles()`) | весь CSS календаря на `!important`, перекрывает базу; правки — **только внутрь блока** |
| `--topbar-h`, `--calendar-side-top` | меряются из живого DOM через JS, хардкодить нельзя |
| Существующий выбор цвета акцента пользователя | перезаписывать нельзя; менять можно только значение по умолчанию для новых |
| Разбиение PDF 70/30 «С кем» / «Вид служения» | под это свёрстан бланк |
| `localStorage['syp-pin-hash']` | PIN-слой; архитектурное решение по нему не принято |

## Отдельное предупреждение по разметке

**Разметку `circuit-planner/index.html` нельзя патчить наивным поиском `>ТЕКСТ<`.** Один такой проход уже испортил файл: получились теги вида `<label class="small<label data-i18n=…` и 78 паразитных пустых `<span>`; файл откатывали к апстриму. Любая массовая правка классов делается одним проходом с проверкой открывающего тега, а после — контроль регуляркой `<[a-z]+[^<>]*<[a-z]` (совпадений должно быть ноль).

## Порядок работ по модулю

Только после того, как три остальных модуля прошли миграцию и система устоялась.

1. Шапка → `.md-topbar-v2` (сайдбар пока не трогать).
2. Диалоги → `.md-dialog`, поля → `.md-field`.
3. Цвета внутри `calendarViewStyles` → `--status-*` (внутри блока, с сохранением `!important`).
4. Синхронизация темы с `shared/theme.js` через мост — по образцу `App.i18nBridge`.
5. Сайдбар и панель дня — в последнюю очередь, с прогоном в реальном браузере.
