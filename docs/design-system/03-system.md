## 1. Цвет

### 1.1 Поверхности **[есть]**

Иерархия строится поверхностью, а не тенью. В тёмной теме «выше» = светлее, в светлой = белее.

| Роль | Токен | Где |
|---|---|---|
| Фон приложения | `--md-surface-dim` | под всем |
| Рабочая область | `--md-surface-container` | полотно страницы |
| Карточка, шапка, сайдбар | `--md-surface-container-low` | контейнеры |
| Таблица | `--md-surface` | фон строк |
| Диалог, выделенная строка | `--md-surface-container-high` | всплывающее |
| Разделитель | `--md-outline-variant` | линии, границы |
| Второстепенный текст | `--md-on-surface-variant` | подписи |

Правило: **тень только у всплывающего** (диалог, шторка, FAB). Карточка и панель обходятся поверхностью и границей 1px. Причина: в тёмной теме тень почти не видна, и интерфейс, построенный на тенях, там разваливается.

### 1.2 Акценты **[есть]**

| Токен | Назначение |
|---|---|
| `--md-primary` | основное действие, фокус |
| `--md-secondary-container` | выбранное состояние (чип, пункт меню) |
| `--md-tertiary` | фирменная бирюза, редкие акценты |
| `--md-error` | ошибка |

### 1.3 Статусы **[есть]**

`--status-normal / important / critical / success` + парные `-bg`. Взяты из модели данных Клиндария (`normal / important / critical`) — не выдуманы, и потому применимы во всех модулях без натяжки.

Соответствие смыслов, единое для всего приложения:

| Смысл | Токен |
|---|---|
| Подтверждено, готово, получено | `success` |
| Ожидает ответа, нужно действие, скоро срок | `important` |
| Просрочено, ошибка, конфликт | `critical` |
| Черновик, не начато, нейтрально | `normal` |

### 1.4 Акцент модуля **[новое]**

`--cw-module`, `--cw-module-container`, `--cw-module-on-container`, `--cw-module-edge`.
Переключается атрибутом `data-module` на `<body>`. Значения — из градиентов `shared/brand/*.svg`, см. `02-direction.md`.

Применяется к: активному пункту навигации, дорожке под шапкой, знаку модуля, иконке пустого состояния, полосе выделенной строки, включённому переключателю.
**Не применяется** к: основной кнопке, статусам, тексту, поверхностям.

### 1.5 Фон приложения

- **Хаб:** `--cw-bg` + сетка-плата `.cw-board-bg` + радиальное свечение. Остаётся как есть.
- **Модуль:** `--md-surface-container`, ровный. Никаких текстур: под таблицей на сорок строк любой узор — помеха.
- **Документ:** `#fff` жёстко. В темах не участвует.

## 2. Типографика **[есть]**

Roboto, локальный, начертания **только 400 и 500**. Начертаний 600/700/800 в файле шрифта нет — браузер их синтезирует, и кириллица получается грязной. Если сейчас где-то в модуле стоит `font-weight: 800` (в Конгрессах такое есть), это именно такой случай.

| Класс | Размер | Применение |
|---|---|---|
| `.md-headline-small` | 24/32 | заголовок экрана |
| `.md-title-large` | 22/28 | заголовок раздела, месяц в календаре |
| `.md-title-medium` | 500 16/24 | заголовок карточки, название модуля в шапке |
| `.md-title-small` | 500 14/20 | заголовок строки списка |
| `.md-body-medium` | 14/20 | **основной текст интерфейса**: таблицы, формы |
| `.md-body-small` | 12/16 | подписи, версия, время сохранения |
| `.md-label-large` | 500 14/20 | подпись кнопки |

Правила:
- Не больше **трёх** уровней размера на одном экране.
- Числа в таблицах — `font-variant-numeric: tabular-nums`, выравнивание вправо.
- Максимум ширины читаемого текста — `--cw-reading-max` (76ch). Абзац во всю ширину монитора не читается.

## 3. Форма и пространство

### 3.1 Скругления **[есть]**

Две шкалы сосуществуют намеренно и **не смешиваются внутри одного компонента**:

- `--cw-radius-sm/md/lg` (8/14/20) — фирменная, хаб и плитки.
- `--md-radius-xs…full` (4/8/12/16/28/999) — рабочая, модули.

| Что | Радиус |
|---|---|
| Поле ввода | `xs` 4px |
| Чип, кнопка-иконка | `sm` 8px |
| Таблица, панель | `md` 12px |
| Карточка, секция формы | `lg` 16px |
| Диалог, шторка | `xl` 28px |
| Кнопка, значок, поиск | `full` |

### 3.2 Отступы **[новое]**

`--cw-space-1…8` = 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64.
Сейчас в коде встречаются 13 разных значений вперемешку.

| Ступень | Применение |
|---|---|
| 1 · 4px | внутри строки, между иконкой и текстом |
| 2 · 8px | между кнопками |
| 3 · 12px | ячейка таблицы, между полями в ряду |
| 4 · 16px | между блоками |
| 5 · 24px | внутри карточки и секции формы |
| 6 · 32px | между секциями |
| 7 · 48px | пустое состояние |
| 8 · 64px | низ страницы |

### 3.3 Геометрия оболочки **[новое]**

`--cw-topbar-h: 64px`, `--cw-sidebar-w: 264px`, `--cw-rail-w: 80px`, `--cw-content-max: 1280px`.

Отдельно важно: Клиндарий сейчас **меряет** `--topbar-h` из живого DOM через JS. Общий токен даёт ему постоянное значение — измерение можно будет убрать (но только после проверки, см. `07-integration.md`).

### 3.4 Плотность **[новое]**

`data-density="compact"` на контейнере ужимает `--cw-row-h` 48→36px, паддинг ячейки 12/16→6/10, высоту контролов 40→32.

Нужен: программе конгресса (40 строк), списку учащихся (24 записи), спискам братьев в Назначениях. Переключатель — в панели фильтров, состояние сохраняется на модуль.

### 3.5 Слои **[новое]**

`--cw-z-sticky: 10` → `topbar: 20` → `drawer: 30` → `fab: 40` → `modal: 50` → `toast: 60`.
Сейчас: 10, 10, 20, 2000 — без карты.

## 4. Состояния

### 4.1 Интерактивные **[есть]** + **[новое]**

| Состояние | Как |
|---|---|
| Наведение | слой `currentColor` 8% (`.md-state-layer`) |
| Фокус с клавиатуры | `3px solid --md-primary`, отступ 2px — **[новое]**, единый |
| Нажатие | слой 12% |
| Выбрано | `--md-secondary-container` или `--cw-module-container` |
| **Недоступно** | **[новое]** 38% непрозрачности, `cursor: not-allowed`, событий нет |
| **Загрузка** | **[новое]** `data-loading="true"` — кольцо вместо подписи |

Единый фокус важнее, чем кажется: сейчас три разных, и обход интерфейса с клавиатуры выглядит как обход трёх разных сайтов.

### 4.2 Состояния данных **[новое]**

| Ситуация | Компонент | Обязательно содержит |
|---|---|---|
| Ничего не создано | `.md-emptystate` | иконка, заголовок, объяснение, **кнопка действия** |
| Фильтр ничего не нашёл | `.md-emptystate` | иконка поиска, **кнопка сброса фильтра** |
| Идёт загрузка | `.md-skeleton` / `.md-progress` | форма будущего содержимого |
| Долгая операция | `.md-progress` + текст | что именно происходит |
| Постоянная проблема | `.md-banner` | что не так + что сделать |
| Результат действия | `.md-snackbar` | + отмена, если действие обратимо |

Различие «пусто» и «не найдено» — не педантизм: в первом случае нужна кнопка «создать», во втором она бесполезна и сбивает.

## 5. Формы

- Поле — Outlined text field, высота 56px, плавающая подпись.
- У `<select>` подпись **статичная сверху**: псевдокласс `:placeholder-shown` спецификацией для `<select>` не определён и работать там не будет. Это уже учтено в `shared/style.css` (`.md-field-select`).
- Ошибка: красная рамка + текст под полем. Только красной рамки недостаточно — она не объясняет, что не так.
- Обязательное поле — звёздочка в подписи, не цветом.
- Секция формы (`.md-formsection`) — заголовок + пояснение + сетка полей. Сетка 2 колонки, на узком экране 1.
- Переключатель (`.md-switch`) — для мгновенно применяемых настроек. Чекбокс — для выбора, который подтверждается кнопкой. Смешивать нельзя: пользователь должен понимать по виду, применилось уже или ещё нет.
- Длинная форма разбивается визардом (`.md-stepper`), а не бесконечной прокруткой. Актуально для анкеты Школы.

## 6. Таблицы

- База — `.md-table` **[есть]**, расширения **[новое]**: `--sticky` (шапка не уезжает), `--cards` (на узком экране строка становится карточкой).
- Числа вправо, `tabular-nums`.
- Выделенная строка — **полоса акцента слева 3px** плюс лёгкая заливка. Заливка целиком делает текст в строке хуже читаемым.
- Строки-разделы (утро/день в Конгрессах) — фон `--md-surface-container`, начертание 500.
- Действия строки — кнопки-иконки, выровнены вправо, максимум три; остальное в «ещё».
- Ширины колонок задаются в процентах и `table-layout: fixed` — иначе таблица прыгает при вводе.
- **Мобильный:** `--cards` берёт заголовки из `data-label` у `<td>`. Разметку менять не нужно, только добавить атрибут.

## 7. Сообщения

Три носителя, три роли. Путать их — самая частая ошибка:

| Носитель | Роль | Живёт |
|---|---|---|
| `.md-banner` | состояние данных: «три задания без участника» | в потоке страницы, постоянно |
| `.md-snackbar` | результат действия: «удалено», «сохранено» | 4–6 секунд, снизу |
| `.md-dialog` | требует решения: «удалить конгресс?» | до ответа |

У баннера четыре тона: `--error / --warn / --success / --info`.
У снекбара с обратимым действием **обязательна** кнопка отмены.
У деструктивного диалога основная кнопка — красная, но рядом всегда предлагается безопасная альтернатива («сделать копию»).

## 8. Навигация и возврат в хаб

- Шапка модуля `.md-topbar-v2` — 64px, липкая, на всю ширину. Слоты: возврат → знак и название → версия и статус → действия.
- **Возврат в хаб — крайний левый слот, всегда.** Обычная ссылка на `index.html`, не `history.back()`: Школа пишет маршруты в `location.hash`, и `history.back()` увёл бы на предыдущий экран модуля. Ощущение «вернулся туда, где был» даёт хаб — он восстанавливает позицию прокрутки из `sessionStorage`.
- Боковая навигация `.md-sidenav` — под шапкой, 264px, с группировкой заголовками.
- На узком экране сайдбар уходит в `.md-bottomnav` (до 4 пунктов + «ещё»).
- Панель **действий** (`.md-toolbar`) и панель **фильтров** (`.md-filterbar`) — разные вещи и разделены. Сейчас в Конгрессах они слиты в одну строку из десяти кнопок.

## 9. Адаптивность

| Порог | Что происходит |
|---|---|
| ≥ 1240px | хаб: 4 колонки плиток; модуль: сайдбар + широкая рабочая область |
| 900–1240px | сайдбар остаётся, боковые панели сворачиваются |
| 720–900px | сайдбар → нижняя навигация, боковая панель → шторка снизу |
| < 720px | таблицы → карточки, форма в одну колонку, шапка теряет подстроку |

Сенсорная цель — не меньше 44px (уже соблюдается для `.cw-home-btn`).

## 10. Темы

- Оба набора токенов **уже написаны**. Задача — не рисовать светлую тему, а перестать её жёстко задавать.
- `shared/theme.js` **[новое]**, ключ `cw-theme`, значения `auto | light | dark`, по умолчанию `auto` = `prefers-color-scheme`.
- Хаб по умолчанию тёмный, но корректен и в светлой.
- Клиндарий: свой переключатель **сохраняется**, синхронизируется с общим — по образцу того, как `App.i18nBridge` синхронизирует язык. Существующий выбор цвета акцента у пользователя **никогда не перезаписывать**.
- Печать и документы в темах не участвуют. Правило: всё внутри `@media print` и любой лист документа — вне системы тем.
