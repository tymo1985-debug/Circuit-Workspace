# 07 · План внедрения, риски и границы

---

## 1. Принципы перехода

1. **По одному модулю за раз.** Никогда не два параллельно: если что-то сломалось, должно быть очевидно, где.
2. **Оформление отдельно от логики.** Сначала цвета и классы, потом структура разметки, и только потом — поведение. Три разных типа риска не смешиваются в одном заливе.
3. **Старое не удаляется, пока новое не проверено.** `.cw-home-fab`, старые селекторы в `nav.js`, локальные классы модуля живут параллельно весь переход.
4. **Каждый шаг самодостаточен.** После любого шага приложение работает целиком. Не бывает состояния «половина модулей мигрирована, приложение сломано».
5. **Бамп версии на каждом шаге,** иначе вернувшийся пользователь увидит старый кэш SW. Чек-лист выпуска — в `AGENTS.md`.

## 2. Рекомендация: с какого модуля начать

### Начинать с **Назначений** (`appointments`)

| Критерий | Назначения | Конгрессы | Школа | Клиндарий |
|---|---|---|---|---|
| Атрибутов `class` в разметке | **74** | 228 | 171 | 320 |
| Строк собственного CSS | **176** | 32 (минифиц.) | 523 | 219 (inline) |
| Общих классов уже используется | **10** | 0 | 0 | 21 |
| Экранов / разделов | **1** | 1 + диалоги | 13 | 3 + модалки |
| Нужны иконки вне субсета | **нет** | да (`expand_more`) | нет | да (`chevron_left`) |
| Логика завязана на CSS | **нет** | печать | экспорт PDF | календарь, `!important` |

**Почему именно он:**
- Один экран — весь результат виден сразу, без обхода тринадцати разделов.
- Уже использует 10 общих классов: переход не с нуля, а «дожать начатое».
- Не собирает PDF, не имеет своего календаря, не хранит критичных ключей `localStorage`.
- Все нужные иконки уже в субсете — пересборка шрифта не требуется.
- Если система окажется неудобной, откат стоит один файл CSS и одну разметку.

**Единственная тонкость** — это единственный модуль, где `shared/style.css` подключён **перед** своим CSS. При переходе на общие классы порядок нужно выровнять и проверить визуально, а не переворачивать вслепую (задача уже стоит в `TODO.md`).

### Дальше — **Школа пионеров**

Второй по очереди, потому что даёт максимальный видимый эффект: 13 разделов, самый заметный гибрид (жёстко тёмный сайдбар в светлой теме), самая большая выгода от группировки навигации. И при этом её CSS — обычный файл на 523 строки, без `!important` и инжекции.

### Затем — **Конгрессы**

Средний риск: логика печати завязана на CSS (`#printArea`, `@media print`), но эта часть чётко отделена и просто не трогается.

### **Клиндарий** — последним

Причины в `modules/circuit-planner.md`. Коротко: монолитный `app.js` 307 КБ, CSS календаря инжектируется и построен на `!important`, размеры меряются из живого DOM, разметку уже один раз испортили массовым патчем. К моменту, когда очередь дойдёт до него, система будет проверена на трёх модулях.

## 3. Порядок работ

### Фаза 0 · Общая тема (до любого модуля)

Самая дешёвая правка с самым большим эффектом.

| Файл | Что |
|---|---|
| `shared/theme.js` | **новый.** Ключ `cw-theme`, значения `auto \| light \| dark`, по образцу `shared/doclang.js` |
| `shared/i18n/common.js` | подписи переключателя темы |
| `index.html` (хаб) | переключатель темы рядом с языком |
| `appointments/index.html` | снять `data-theme="light"`, подключить `theme.js` |
| `congress-project/index.html` | то же |
| `pioneer-school/index.html` | то же |
| `circuit-planner/` | мост к своему переключателю — **не в этой фазе**, отдельно |

**Проверка:** переключить тему на хабе → зайти в каждый модуль → тема та же. Плюс прогон обеих тем на каждом экране: где-то вылезет хардкод, который аудит не поймал.

**Риск:** три модуля никогда не показывались в тёмной теме. Ожидаемо всплывут нечитаемые места. Это не повод откладывать — это ровно то, что нужно найти.

### Фаза 1 · Расширение общего слоя

Разделы 4–6 из `proposed/cw-ui.css` переносятся в `shared/style.css` **как добавление в конец файла**. Ни одна существующая строка не меняется.

Правило из шапки самого файла: *«раздел 2 менять нельзя без проверки — от него зависят index.html хаба и всех модулей»*. Раздел 2 не трогаем вообще.

**Проверка:** все существующие экраны выглядят точно так же, как до правки. Новые классы никем не используются — визуальных изменений быть не должно ноль.

### Фаза 2 · Пилот на Назначениях

Порядок внутри модуля — в `modules/appointments.md`.

### Фаза 3 · Расширение `shared/nav.js`

`.md-topbar-v2__lead` добавляется **первым** в список селекторов, остальные остаются после него. Мигрированные и не мигрированные модули работают одновременно.

### Фазы 4–6 · Школа → Конгрессы → Клиндарий

По схеме, отработанной на пилоте.

### Фаза 7 · Уборка

Только когда все четыре модуля мигрированы: удаление осиротевших локальных классов, выравнивание порядка подключения CSS, возможное упрощение `nav.js`.

`.cw-home-fab` **не удаляется никогда** — он запасной вариант для будущих модулей с нестандартной шапкой, и это прямо оговорено в `shared/style.css`.

## 4. Что нельзя менять без отдельной проверки

### Категорический запрет

| Что | Последствие нарушения |
|---|---|
| `localStorage['service-year-planner-v9-4-2']` | потеря данных пользователей Клиндария |
| Средний стоп градиента в `shared/brand/icon-source.svg` (`#6a45c9`, 45%) | это сид всей MD3-палитры; логотип и токены разъедутся |
| Существующий выбор цвета акцента у пользователя Клиндария | менять можно только значение по умолчанию для новых |
| `subset: false` при встраивании шрифта в pdf-lib | учащийся не сможет ввести букву, которой не было в шаблоне |
| `/DR` + `/DA` + `NeedAppearances` в `_finalizeForm` | кириллица в заполняемых полях PDF перестанет отображаться |

### Только вместе с визуальным прогоном

| Что | Почему |
|---|---|
| `#printArea`, `.planPrint`, `.planTable`, `.letter-page` | бумага, свёрстана под печать |
| Вёрстка `.letter` в Назначениях | у модуля нет PDF-экспорта — предпросмотр **и есть** печатный результат |
| `dialog[open]{display:none!important}` в `@media print` | фикс дублирования диалогов при печати |
| Всё внутри `<style id="calendarViewStyles">` | `!important` везде, перекрывает базу |
| `--topbar-h`, `--calendar-side-top` | меряются из живого DOM, хардкодить нельзя |
| Порядок подключения CSS в любом модуле | меняется победитель каскада |
| Субсет `material-symbols-outlined-subset.woff2` | пересборка требует бампа версии SW, иначе пустые квадраты |

### Не дизайнерские задачи (не трогать под видом редизайна)

- Переводы шаблонов писем Конгрессов для `ru`/`de` — сейчас копии украинского, задача в `TODO.md`.
- Дублирование структуры анкеты (`register.html` + `registrationSchema.js`) — архитектурная задача.
- Вычитка терминологии носителями в uk/en/pl/de.
- PIN-слой Клиндария — архитектурное решение не принято.

## 5. Риски

| Риск | Вероятность | Смягчение |
|---|---|---|
| Тёмная тема вскроет нечитаемые места в трёх модулях | **высокая** | это цель фазы 0, а не побочный эффект; прогон каждого экрана в обеих темах |
| Массовая замена классов испортит разметку | средняя | только Python с `re.compile(r'class=(["\'])((?:(?!\1\|\$\{).)*)\1')`; наивный `sed` ломает омонимы (`icon-btn`, `modal-card`) |
| Разметка Клиндария сломается при патче | **высокая, если патчить наивно** | один проход по исходной строке с проверкой открывающего тега; после — контроль `<[a-z]+[^<>]*<[a-z]`, совпадений должно быть ноль |
| Разный порядок CSS даст разный результат в модулях | средняя | выравнивать только после миграции всех, с визуальным прогоном |
| Пересборка субсета иконок → пустые квадраты | средняя | бамп `APP_VERSION` модуля обязателен |
| Потеря файлов при drag&drop в GitHub | **уже случалась** (инцидент 06.08.2026, 8 файлов) | пост-проверка из `AGENTS.md` после каждого залива |
| Дизайн-система «поедет» снова через полгода | средняя | см. раздел 6 |

## 6. Как не допустить повторного расхождения

1. **Ни одного хекса в коде модуля.** Исключение — бумага документов, и оно проговаривается в комментарии рядом.
2. **Новый визуальный элемент сначала в `preview/components.html`,** потом в модуле. Если элемента нет в галерее — его не существует.
3. **Правило второго применения:** компонент попадает в общий слой при появлении во **втором** модуле, не в первом. Календарь остаётся своим.
4. **Проверка перед заливом** — grep на хексы в изменённых файлах:
   ```bash
   grep -nE '#[0-9a-fA-F]{3,8}\b' <файл> | grep -v 'print\|letter-page\|planPrint'
   ```
   Непустой вывод — повод объяснить каждую строку.
5. **Три контрольных вопроса** из `02-direction.md` — при любом изменении интерфейса.
6. **`AGENTS.md` — источник правды по границам.** Раздел «Известные технические ловушки» читается до, а не после.

## 8. Что нужно от Алекса перед фазой 0

Три решения:

1. **Тема по умолчанию для модулей** — `auto` (системная) или `light` (как сейчас)? Рекомендация — `auto`.
2. **Остаётся ли хаб тёмным всегда** или тоже следует общей теме? Рекомендация — следует, но с тёмной как значением по умолчанию.
3. **Переключатель темы Клиндария** — оставить свой с синхронизацией (как язык через `App.i18nBridge`) или заменить общим? Рекомендация — оставить и синхронизировать: механизм уже отработан на языке.
