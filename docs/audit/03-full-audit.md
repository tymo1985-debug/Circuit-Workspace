## 1. Находки

### P0 — влияет на спокойную работу уже сейчас

#### P0-1. Соседнее приложение на том же origin стирает все кэши Circuit Workspace

- **Где.** `https://tymo1985-debug.github.io/Current-Exchange/sw.js` (живой деплой проверен). Обработчик `activate`: `keys.filter(key => key !== CACHE).map(caches.delete)`.
- **Почему.** GitHub Pages аккаунта — **один origin** для всех репозиториев. Cache Storage общий на origin. Каждый раз, когда Current-Exchange устанавливается или выходит его новая версия, он удаляет кэши хаба и всех семи модулей. Данные (IndexedDB) не страдают, но **офлайн-запуск Circuit Workspace перестаёт работать целиком**, пока приложение не откроют снова с сетью — а ленивые части (ПДФ-стек) восстанавливаются только при первом использовании онлайн.
- **Доказательство.** Воспроизведено в Chromium: кэши `circuit-workspace-shell-…`, `syp-static-…`, `journal-cache-…` → после одного визита в Current-Exchange остался только `glass-currency-v2.8.0`; затем офлайн хаб, Клиндарий и Журнал — `net::ERR_FAILED`. Service-Timer на том же origin ведёт себя правильно (удаляет только по своему префиксу).
- **Предложение.** (а) В Current-Exchange — удалять только свои кэши по префиксу `glass-currency-` (одна строка, другой репозиторий). (б) Записать в `AGENTS.md` инвариант origin: «любое приложение на `tymo1985-debug.github.io` удаляет только свои кэши по префиксу и никогда не вызывает `localStorage.clear()`/`indexedDB.deleteDatabase` для чужих имён». (в) Защита со своей стороны — см. P1-5.
- **Риск правки.** Минимальный.

#### P0-2. Хранилище не запрошено как постоянное (`navigator.storage.persist()` нет нигде)

- **Где.** Весь проект — ни одного вызова `persist()`/`estimate()`.
- **Почему.** Без запроса данные origin находятся в режиме «best-effort»: при нехватке места браузер вправе удалить IndexedDB и localStorage **целиком**, без вопроса. На origin лежат многолетние данные Клиндария, Журнала, Архива — и это единственная копия, кроме ручных резервных файлов. Общий origin с другими приложениями увеличивает объём и частоту обращений к хранилищу.
- **Доказательство.** `grep` по `storage.persist|storage.estimate` — 0; в замере `navigator.storage.persisted() === false`.
- **Предложение.** Запросить `persist()` при старте хаба; в карточке «Резервные копии» показать состояние («постоянное / может быть очищено браузером») и занятый объём из `estimate()`.
- **Риск правки.** Низкий; в Firefox браузер может показать вопрос пользователю.

### P1 — ближайший релиз

#### P1-1. Клиндарий: после деплоя новый `index.html` работает со старыми скриптами

- **Где.** `circuit-planner/sw.js`, ветка навигации (≈ стр. 327–339): при наличии кэша ответ берётся из кэша, а фоновая ревалидация кладёт свежий документ в `CACHE_RUNTIME` текущей (старой) версии. `matchOwn()` читает runtime раньше static — со второго открытия отдаётся НОВЫЙ документ, тогда как скрипты и стили по правилу `offlineFirst` остаются старыми.
- **Почему.** Это ровно та «смесь поколений», которую комментарий в `offlineFirst` объявляет недопустимой (падение `CWSender.ready is not a function`), — только через документ. Новый `index.html` может подключить новый файл (`ui/route-legs.js` и т.п.): он придёт из сети новым рядом со старым `app.js`, а офлайн — не придёт вовсе. Ошибка плавающая, «лечится повторным открытием» — самая дорогая для диагностики.
- **Доказательство.** Воспроизведено: прогрев → изменение `index.html` и `app.js` на сервере → два открытия без применения обновления → в странице есть новый маркер HTML (`true`) и нет нового маркера JS (`false`), активный worker прежний.
- **Предложение.** Документ — релизный файл: не ревалидировать его в фоне (как уже сделано для script/style), новый документ приходит только с новым worker'ом. Заодно убрать неиспользуемую `navigationPreload` в кэшированной ветке (сейчас каждая навигация делает лишний сетевой запрос).
- **Риск правки.** Средний (service worker): только с `live-update-pipeline.mjs` и офлайн-прогоном.

#### P1-2. Клиндарий: установка worker'а не атомарна

- **Где.** `circuit-planner/sw.js`, `install`: каждый файл прекэша в `try/catch`, ошибка пропускается.
- **Почему.** Новая версия устанавливается и активируется с неполным кэшем (обрыв сети при обновлении, заливка через веб-интерфейс несколькими коммитами). Онлайн это незаметно, офлайн — отсутствуют файлы. Остальные шесть оболочек используют атомарный `addAll`.
- **Предложение.** Провал установки при любом недоставленном файле прекэша (как у соседей). Делать в одной фазе с P1-1.
- **Риск правки.** Средний (SW).

#### P1-3. Резервная копия остаётся на том же устройстве

- **Где.** `shared/backup.js` — только скачивание файла; Web Share в резервных копиях не используется.
- **Почему.** Индикатор возраста копии считает «сделано», когда файл скачан в «Загрузки» того же телефона. Потеря/сброс устройства = потеря и данных, и копии.
- **Предложение (продуктовое решение).** Кнопка «Отправить копию» через `navigator.share({files})` (Диск, почта, мессенджер), и считать «копией вне устройства» только её.
- **Риск правки.** Низкий.

#### P1-4. Гейт не защищает живой сайт

- **Где.** `.github/workflows/release-gate.yml` запускается на push, но отдельного деплоя через Actions нет — по составу workflow GitHub Pages публикует ветку независимо от результата.
- **Почему.** Стейджинга нет; красный гейт обнаруживается после выкладки. Заливка через веб-интерфейс может прийти несколькими коммитами, и каждый промежуточный становится живым.
- **Предложение (решение по процессу).** Pages через Actions с `needs: [static-and-data, chromium-release]` — сайт обновляется только после зелёного гейта.
- **Риск правки.** Низкий для данных; меняется процесс выкладки.

#### P1-5. Нет самопроверки офлайн-готовности

- **Почему.** После P0-1 (или очистки браузером) пользователь узнаёт о пустых кэшах только офлайн, в поле.
- **Предложение.** Хаб при старте онлайн проверяет наличие кэша каждого модуля нужной версии; при отсутствии — просит worker перезаполнить прекэш и показывает статус «готово к офлайн-работе».
- **Риск правки.** Средний (SW, межмодульно).

### P2 — плановая надёжность

#### P2-1. Конфликт зеркала `CWState` не показывается и молча удаляется

- **Где.** `shared/state.js`: при `stale-mirror`/`lineage-conflict`/`legacy-mirror` выставляется `recoveryState`, но `recovery()` не читает ни один модуль; первая успешная запись делает `lsDel(mirrorKey)` (≈ стр. 248).
- **Почему.** Зеркало с несохранённой правкой (вкладка закрылась, пока соседняя писала) уничтожается без следа — тот самый «бесшумный отказ», против которого построен слой.
- **Предложение.** Отложить конфликтное зеркало под отдельный ключ и показать «найдены несохранённые изменения от …: открыть / отбросить».
- **Риск правки.** Средний (данные).

#### P2-2. «Сегодня» вычисляется по UTC

- **Где.** `congress-project/js/utils.js:9` (`letterSentDate`, предложение архивации, имя файла), `pioneer-school/js/utils/dateUtils.js:15` (`submittedDate`), `appointments/js/app.js:150, 684` (дата письма — на бумаге).
- **Почему.** С 00:00 до 02:00 (летом; зимой до 01:00) по Берлину/Праге/Варшаве ставится вчерашняя дата.
- **Предложение.** Одна функция локальной даты в общем слое + проверка гейта, запрещающая `toISOString().slice(0,10)` для «сегодня».
- **Риск правки.** Низкий.

#### P2-3. Маршрут R7 применяет черновик и без снимка

- **Где.** `circuit-planner/ui/route.js` `applyDraft()`: `checkpointNow(...).catch(() => null).then(записать)`.
- **Почему.** Подтверждение обещает откат через историю, но при сорванном снимке запись всё равно идёт. В A5 правило строже: «без копии — ничего не трогаем».
- **Предложение.** Тот же контракт, что в A5: снимок не создался → не применять, сказать почему.
- **Риск правки.** Низкий.

#### P2-4. Каждое обновление хаба перекачивает ≈ 18,6 МБ

- **Где.** Имена всех семи кэшей модулей содержат версию хаба (`…-hub-0.42.35`) — решение конвейера обновления от 24.09 против смешения кэшей.
- **Почему.** Замер: хаб 1,0 · Клиндарий 5,7 · Школа 5,3 · Конгрессы 2,0 · Журнал 1,75 · Документы 1,2 · Архив 0,9 · Назначения 0,8 МБ. Любой патч-бамп хаба (их 35 за серию 0.42) заново скачивает всё. На мобильной сети это дорого и повышает шанс сорванного обновления.
- **Предложение (архитектурное решение).** Варианты: общий кэш неизменяемых файлов (`vendor/`, шрифты) с ключом по содержимому; реже поднимать версию хаба; разделить «версию оболочки» и «версию реестра». Решать отдельно, с аудит-документом.
- **Риск правки.** Высокий (SW/кэш) — только после решения.
- **Разбор вариантов (07.10.2026):** `docs/audit/04-update-cost.md` — замеры, отброшенный путь через ETag, рекомендация A; ждёт решения.

#### P2-5. Схема IndexedDB: новый индекс на существующем хранилище не появится

- **Где.** `shared/db.js` `onupgradeneeded` создаёт только отсутствующие хранилища; индексы — только у новых.
- **Почему.** Ловушка будущего: добавить индекс в `STORES` у старого хранилища + поднять `DB_VERSION` — у существующих пользователей индекса не будет, `byIndex()` упадёт `NotFoundError`. Сейчас дефекта нет.
- **Предложение.** В обработчике дозаводить недостающие индексы существующих хранилищ (`event.target.transaction.objectStore(name)`), плюс проверка гейта.
- **Риск правки.** Средний (схема) — только вместе со следующим подъёмом схемы.

#### P2-6. Ошибки на телефоне не видны

- **Где.** Глобальный `window.onerror` есть только у Конгрессов; в остальных модулях сбой оседает в консоли.
- **Почему.** Работа идёт с телефона без DevTools; «кнопка ничего не сделала» не диагностируется.
- **Предложение.** `shared/errors.js`: кольцо последних N ошибок (`error` + `unhandledrejection`), ненавязчивый значок и «Скопировать диагностику» (версии модулей, браузер, ошибки) в карточке хаба.
- **Риск правки.** Низкий.

#### P2-7. Долг перевода виден каждому не-русскому пользователю

- **Где.** 15 ключей только `ru`: весь баннер обновления (`update.*`, 7 ключей, `shared/i18n/common.js`) и 8 ключей Конгрессов; плюс жёстко вписанные строки в Конгрессах (`tasks.js` «Собрание / группа», «Удалить участника»; `batch-pdf.js`; `main.js` «Ошибка JavaScript»).
- **Предложение.** Передать носителю (правило — не заполнять «очевидным» переводом); строки из кода — в словарь.
- **Риск правки.** Низкий.
