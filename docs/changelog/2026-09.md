## 2026-09-04 — Hub: исправлен ложный «Нет соединения» в проверке обновлений

**Версии:** хаб `0.41.24 → 0.41.25`. Патч-бамп общего слоя (правка
`shared/update.js`, `shared/i18n/common.js`) для cache-first оболочек:
Конгрессы `4.46.45 → 4.46.46`, Школа `1.14.23 → 1.14.24`, Назначения
`5.5.62 → 5.5.63`, Документы `1.10.13 → 1.10.14`. Клиндарий не тронут —
собственного кода не касалось, версия осталась `9.94.10`.

**Причина.** `waitForOutcome()` после `reg.update()` ждала появления
`waiting` в пределах таймаута и при его истечении возвращала единственный
булев результат — `found`. Отсутствие нового release (нормальный, самый
частый исход) давало `found=false` неотличимо от реальной сетевой ошибки:
оба варианта попадали в один и тот же список `unreachable`, и обработчик
кнопки хаба трактовал любую непустую `unreachable` как «Нет соединения».

**Исправление.** Модель состояний регистрации разделена на три:
`updateFailed` (сам `reg.update()` реально отклонился — единственная
причина попасть в `failed`), `hasWaiting` (найден воркер — `ready`),
`noUpdate` (успешный `update()`, воркера нет — не попадает никуда, это
норма). `checkAll()` возвращает `{ready, failed}` вместо `{ready,
unreachable}`. Обработчик кнопки в хабе (`index.html`) различает три исхода:
все проверены и апдейта нет → «Установлена последняя версия»; часть реально
не проверилась (`failed`, но не все) → нейтральное «Не удалось проверить
некоторые модули. Попробуйте ещё раз» (новый ключ `update.partial`, ru-only,
долг перевода); полный отказ (`getRegistrations()` сам отклонился) →
«Нет соединения». Таймаут ожидания `updatefound` сам по себе больше не
считается ошибкой ни в одном случае.

Проверено симуляцией (мок registrations, Node): все `noUpdate` → пустые
`ready`/`failed`; смешанный набор (`noUpdate` + `updateFailed` +
`hasWaiting`) → корректное разделение по трём спискам. Живой Chromium-прогон
не выполнялся (см. ограничение среды предыдущего release).

**Версии:** хаб `0.41.25 → 0.41.26`. Патч-бамп общего слоя (правка
`shared/update.js`, `index.html`) для cache-first оболочек: Конгрессы
`4.46.46 → 4.46.47`, Школа `1.14.24 → 1.14.25`, Назначения
`5.5.63 → 5.5.64`, Документы `1.10.14 → 1.10.15`. Клиндарий не тронут —
`9.94.10`.

**Причина.** `applyAll()` резолвился одинаково при успешной активации и при
timeout — хаб не мог отличить полный успех от частичного. Отдельно: при
переходе в модуль сразу после Hub apply `watch()` видел ещё не долетевшую
до пустоты запись `reg.waiting` и мгновенно показывал «Доступно обновление —
открыть Hub», хотя activation уже шла.

**Исправление.** `applyAll()` возвращает `{results:[{scope,status}],
allActivated}` — `status` одно из `activated`/`timedOut` на каждый scope;
хаб показывает partial-уведомление, если `allActivated=false`, вместо
молчаливого success. `watch()` в silent-режиме перед показом баннера ждёт
bounded grace period (`confirmStaleWaiting`, ~2.5с): слушает `statechange`
уже существующего waiting-воркера и перепроверяет `reg.waiting`, не запуская
новый `reg.update()`. Если worker активировался в течение grace period —
баннер не показывается.

Проверено моками (Node): переход в модуль сразу после apply — баннер не
появляется; устойчивый waiting без apply — баннер появляется; один scope не
активировался в timeout — хаб получает partial, а не success.

## 2026-09-20 — Phase F: безопасное удаление легаси-ключей Клиндария и Конгрессов

Главные легаси-ключи Клиндария (`service-year-planner-v9-4-2`) и Конгрессов
(`congress-pwa-v34-speakers`) больше не остаются постоянным входом миграции

дважды: подтверждённой записью канона И проверкой его формы. Существование
канонической строки (`remote.migrated()`) само по себе НЕ является условием
удаления — оно доказывает лишь, что строка есть, а не что она пригодна:
`normalizeApp()` Клиндария намеренно всеяден и превращает любой JSON-мусор
в валидное на вид пустое состояние без единой ошибки, поэтому подтверждённая
запись (`writeOutcome()==='written'`) тоже сама по себе недостаточна.

**Конгрессы** (`congress-project/js/state.js`, `load()`): легаси-строка
парсится и проверяется существующей `isValidState()` ДО попытки записи в
канон — непригодная форма не пишется и не удаляется вовсе. После записи
легаси-ключ удаляется только при `writeOutcome()==='written'`. Для уже
мигрировавших установок (канон существовал до этой сессии) легаси убирается
отдельным путём — только когда САМ канонический payload заново проходит
`isValidState()`.

**Клиндарий** (`circuit-planner/app.js`): добавлен новый минимальный
предикат `App.store.isValidPersistedState()` — три структурных инварианта,
которые `normalizeApp()` иначе тихо подставил бы дефолтом
(`Array.isArray(events)`, `Array.isArray(entries)`, `serviceYears` — объект).
`{}` и `{"foo":"bar"}` не проходят ни одной проверки. Перенос переведён с
безусловного `remote.write()` на подтверждённый `remote.writeOutcome()`;
удаление ключа — тот же двупутный алгоритм, что у Конгрессов.

В обоих случаях: `REFUSED`/`FAILED`/недоступная или не успевшая открыться за
таймаут база — легаси не удаляется ни при каких условиях, никакого отката к
записи в прежний ключ как в запасной путь не появилось. `shared/state.js` не
тронут. `-history`/`-backups`/`-accent` и Phase E backup/restore — вне

## 2026-09-22 — Журнал J6: поиск и архив

Схема не менялась: ни хранилищ, ни индексов, ни подъёма `DB_VERSION`.

**Поиск** — `CWJournal.search.run(query, { includeArchive, resolveCommunity,
labelVisit })`: только чтение, по требованию, в памяти — узлы и записи
читаются один раз за прогон. Сохранённого индекса, истории запросов и кэша
открытого текста нет нигде (граница J8); запрос не попадает ни в хэш, ни в
историю браузера, ни в localStorage — живёт в памяти экрана. Нормализация:
регистр, `ё ≡ е`, латинские диакритики, `ß→ss`, `ł→l`; `й/ї/ґ` не
сворачиваются. Несколько слов — «И»; хотя бы одно слово должно быть в
собственном тексте (у посещения — в подписи/датах), остальные могут
совпасть с контекстом район › собрание › группа. Ранг: поле целиком →
начало поля → подстрока → свежее `updatedAt` → id. Название, номер, адрес
и контакт из CWDirectory участвуют только в памяти; без справочника
работает локальная подпись узла. Строка с `sec` текстом не ищется —
только считается («защищённые записи не искались: N»).

Экран «Поиск» (эталоны 07-search-m/d): поле с очисткой, фильтры со
счётчиками, группы «Визиты / Записи и проекты / Задачи / Районы и
собрания», отрывок с подсветкой (`<mark>` + `textContent`, пользовательский
текст не проходит через `innerHTML`), крошки контекста, пустое состояние и
«ничего не найдено». Архивный контекст по умолчанию исключён и
открывается фильтром «Архив». Устаревший ответ отбрасывается по номеру
прогона. Кнопка поиска в шапке ставит фокус в поле.

(`journal-node-use-lifecycle`), меню дерева переведены на цикл. Посещение —
прежние `visits.archive/unarchive`. Архивность «в контексте» (узел, предок,
посещение-источник) вычисляется при чтении и не пишется; выполненная
задача и закрытый перенос архивом не являются. `CWJournal.archive.list()`
— только напрямую архивные узлы и посещения, новые сверху; легаси-узел без
`archivedAt` не теряется; объект с архивным предком помечен. Экран
«Архив»: вкладки, дата архивации, «Восстановить» (только выбранный объект,
без каскада), переход к объекту; удаления нет.

`check-journal-db.mjs` переведён на цикл архива узла. Неиспользуемые
