# Аудит: правленый текст письма не применяется (26.08.2026)

Разбор дефекта, найденного 25.08.2026 при заливке подписей резервных копий.
Читать до правки кода. Порядок разделов: что наблюдается → механизм → кого
задевает → что решено чинить и в каком порядке → что осталось открытым.

## 1. Наблюдаемое поведение

Установка Конгрессов, где пользователь правил текст приглашения, печатает
письмо **системным** текстом. Правка при этом цела и лежит в
`settings.templates` нетронутой. Ошибок в консоли нет, предупреждений нет,
интерфейс ничего не сообщает.

Проверено живым прогоном на ТЕЛЕ письма (не на списке писем и не по коду):
засеян легаси-ключ с маркерной строкой, открыто письмо участнику — в письме
системная формулировка, маркера нет.

## 2. Механизм: две сцепленные причины

### 2.1 Перенос не выполняется (Конгрессы)

`js/main.js` запускает две НЕСВЯЗАННЫЕ цепочки промисов:

```
initState().then(() => { load(); initMobile() })
self.CWTemplates?.init?.().then(() => adoptTemplates())
```

Вторая стабильно приходит первой — шесть загрузок из шести. `adoptTemplates()`
читает `S()`, то есть `store.st.settings`, а `store.st` в этот момент ещё
дефолтный: `load()` не отработал. Правленых шаблонов там нет, `jobs` пуст,
функция молча возвращает `false`. Второй попытки нет: цепочка одноразовая,
`catch` не срабатывает (исключения не было), в консоли пусто.

Клиндарий тем же дефектом НЕ задет: его `adoptDocuments()` вызывается из
`App.init()`, а `App.init()` стоит в `.then()` загрузчика состояния — то есть
заведомо после `load()`.

### 2.2 Страховочный откат недостижим (ОБА модуля)

Это причина крупнее первой, и найдена она была второй.

Фаза 2б оставила в каждом читающем методе путь отката в настройки модуля.
Над ним в обоих модулях стоит комментарий, обещающий ровно ту защиту, которой
здесь не хватило: «пока перенос не выполнен, действует прежний источник, иначе
пользователь получит системный текст вместо своего и не заметит подмены».

Откат написан в предположении, что общий слой ответит пустотой:

```
Конгрессы:  let main = CWTemplates.text(CTX, lang);
            if (main && main.body) return {...};   // иначе — настройки
Клиндарий:  const found = CWTemplates.text(this.docCtx(...), this.docLang());
            if (found && found.body) return found.body;   // иначе — настройки
```

Но `CWTemplates.text()` устроен так:

```
var tpl = storage.byContext(contextOrId) || effective(contextOrId);
```

а `effective()` при отсутствии пользовательской записи возвращает СИСТЕМНЫЙ
шаблон (`builtinById`) с пометкой `scope:'system'`, `custom:false`. Тело у него
непустое всегда. Значит `found.body` истинно всегда, и до строки с настройками
исполнение не доходит НИКОГДА — ни в Конгрессах, ни в Клиндарии.

**Слой под откатом научился отдавать системный текст вместо пустоты уже после
того, как откат был написан.** Гарантия исчезла молча, а комментарий остался и
читается как действующая.

### 2.3 Почему это не всплыло раньше

- У Клиндария перенос отрабатывает, поэтому пользовательская запись в хранилище
  есть и `byContext()` находит именно её. Дыра там латентная: она вскроется,
  если перенос когда-нибудь не выполнится (ошибка записи, недоступная база
  в момент переноса).
- У Конгрессов перенос не отрабатывает — и дыра вскрыта прямо сейчас.
- Ни один статический чек такого не ловит: код синтаксически корректен, ключи
  на месте, версии согласованы. Это дефект достижимости, а не структуры.

## 3. Кого задевает

| Состояние установки | Сегодня |
|---|---|
| Конгрессы, текст письма правился, переноса не было | **письмо системное, правка игнорируется** |
| Конгрессы, текст письма не правился | системное письмо — верно, так и задумано |
| Конгрессы, перенос когда-то прошёл | письмо из хранилища — верно |
| Клиндарий, перенос прошёл | письмо из хранилища — верно |
| Клиндарий, перенос не прошёл (сбой записи) | латентно то же, что у Конгрессов |

Данные при этом НЕ потеряны ни в одном случае: `settings.templates` и
`settings['letterTemplate' + suffix]` лежат на месте и уезжают в резервные
копии. Речь о том, что они не применяются, а не о том, что их нет.

## 4. Что решено чинить и в каком порядке

Порядок выбран по возрастанию необратимости. Первый шаг возвращает правильное
письмо сам по себе, ничего никуда не перенося.

**Шаг 1 — достижимость отката (обратимо, оба модуля).** Признак «правил
пользователь» уже есть в API и не используется: `text()` отдаёт `custom`, а
`byContext()` всегда проходит через `effective()`, поэтому `custom === true`
равносильно «в хранилище есть пользовательская запись». Новый порядок чтения:

1. пользовательская запись в хранилище (`custom`) — если есть;
2. правленый текст в настройках модуля (прежнее место) — если есть;
3. системный текст.

Системный текст перестаёт перехватывать очередь у настроек. Для установки, где
перенос прошёл, поведение не меняется: настройки после переноса удалены, и
шаг 2 пуст.

**Шаг 2 — сам перенос (Конгрессы).** `adoptTemplates()` переводится за
`load()`. `CWTemplates.init()` при этом по-прежнему стартует сразу и параллельно
— запуск модуля его не ждёт, это свойство фазы 2 сохраняется.

**Шаг 3 — третья подпись копии.** `makeBackup()` в `adoptTemplates()` до сих
пор получал русский литерал. После шага 2 ветка становится исполняемой, и
подпись впервые станет видимой, поэтому ключ заводится тем же заходом.

## 5. Решения, принятые по ходу

**Признак — `custom`, а не «пусто ли в настройках».** Обратный порядок
(настройки важнее хранилища) вернул бы устаревший текст тем, кто уже перенёсся
и потом правил письмо в «Документах».

**Клиндарий чинится симметрично, хотя у него дыра латентная.** Инвариант
записан в его же коде и нарушен; оставить нарушение после того, как оно
описано, значит гарантировать возврат к нему.

**Перенос НЕ делается идемпотентно-повторяемым в этом заходе.** Соблазн
«пробовать при каждом запуске, пока не выйдет» есть, но это меняет характер
необратимой операции и требует своего разбора. Сейчас достаточно того, что она
выполняется в правильный момент.

## 6. Осталось открытым

- **Регистр третьей подписи.** Литерал был со строчной буквы, соседние подписи
  — с прописной. Ни один пользователь этой строки не видел (ветка не
  исполнялась), поэтому при заведении ключа взят вид соседей. Отменяется одной
  ячейкой словаря.
- **Перевод третьей подписи** — 1 ключ × 4 языка, ждёт носителя. Запасной
  вариант русский, регрессии нет.
- **Кандидат в гейт:** «страховочная ветка недостижима». Класс сломался пока
  один раз, поэтому по правилу отбора в `check-all.mjs` не вносится; условие
  включения — в `IDEAS.md`.
