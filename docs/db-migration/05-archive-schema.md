# Архив — проект схемы и контракта

Дата: 05.10.2026. Продолжение `04-archive-audit.md` (все вопросы аудита
закрыты Алексом 28.09.2026). Кода в этом документе нет. Он фиксирует форму
хранилища, конверта и обязанностей до первой строки кода.

---

## 1. Поправка к аудиту: кто строит конверт

В §4 аудита контракт был записан как `register({ list, preview, archive,
restore })`, то есть Архив вызывает код модуля. **Так не получится.** Модули —
отдельные страницы (`href`, без iframe, `index.html:1078`). Страница Архива не
видит ни `App` Клиндария, ни `store` Конгрессов, и прочитать чужой блоб
`state` она может только как непонятный JSON.

Поэтому обязанности делятся иначе:

| Кто | Что делает |
|---|---|
| **Модуль-источник** (Клиндарий, Конгрессы) | Строит конверт из своего блоба, пишет его через `CWArchive.put()`, показывает предложение «отправить в архив», позже восстанавливает. Блоб других модулей не трогает. |
| **Общий слой** `shared/archive.js` (`CWArchive`) | Единственная точка входа в хранилище: запись, чтение, список, удаление. Внутренности модулей ему неизвестны. |
| **Модуль Архив** (`archive/`) | Только показ, поиск, группировка по годам, удаление конверта по подтверждению. Чужие блобы не читает и не пишет. |

## 2. Хранилище `CWDB.archive` (v7)

```js
archive: { keyPath: 'id', indexes: ['module', 'serviceYear', 'entity', 'archivedAt'] },
```

- `DB_VERSION` 6 → 7. Апгрейд **чисто аддитивный**: общий `onupgradeneeded`
  создаёт только отсутствующие хранилища (`shared/db.js:109`), это тот же путь,
  что был у Журнала при 5 → 6. Существующие хранилища не трогаются.
- Понизить версию IndexedDB невозможно, поэтому шаг необратим по схеме, но не
  по данным: в новом хранилище до первой архивации пусто.
- Потолок версии `backup.js` берёт из `CWDB.DB_VERSION` сам, отдельной правки
  не нужно.

## 3. Конверт

```js
{
  id:              'circuit-planner:serviceYear:2025',  // = module:entity:sourceId
  module:          'circuit-planner' | 'congress-project',
  entity:          'serviceYear' | 'congress',
  sourceId:        '2025' | '<id конгресса>',
  serviceYear:     2025,          // CWServiceYear.forDate(), год НАЧАЛА
  title:           '2025/2026',   // замороженная подпись для списка
  archivedAt:      ISO,           // последняя запись
  firstArchivedAt: ISO,           // первая запись, не двигается никогда
  revision:        1,             // +1 при повторной архивации
  format:          1,             // версия формы конверта
  sourceVersion:   '9.x.y',       // версия модуля в момент архивации
  display:         { sections: [ { heading, rows: [ { date, title, note, tags[] } ] } ] },
  summary:         { visits: 34, letters: 12 },   // для списка без разбора payload
  payload:         { ... },       // данные модуля для восстановления
  docRefs:         ['circuit-planner:entry:abc', ...]  // ссылки на CWDocs
}
```

Решения, которые здесь зафиксированы:

1. **`id` детерминированный** (`module:entity:sourceId`). Повторная архивация
   того же объекта — это `put()` поверх, а не второй конверт: `revision`
   растёт, `firstArchivedAt` сохраняется. Отдельный индекс для дубликатов не
   нужен. Префикс модуля в ключе — тот же приём, что у `snapshots`, и он даёт
   бэкапу отбор по префиксу (§5).
2. **`display` замораживается при архивации.** Модуль сам раскладывает свои
   данные в строки для показа. Архиву не нужно знать устройство блоба, и
   старый конверт останется читаемым после любой будущей смены схемы модуля.
   Это тот же принцип, что у `CWDocs`: `body` хранится уже подставленным.
3. **`payload` — только для восстановления.** Архив его не читает.
4. **Письма не копируются.** `docRefs` — плоские `entityKey` существующих
   снимков `CWDocs` (`module:entity:id`). Архив показывает их через
   `CWDocs`, второй копии письма нет.
5. **Конверт самодостаточен.** Название собрания, цвет и адрес копируются в
   `payload`/`display` на момент архивации: справочник могут переименовать или
   очистить, а архив должен показывать, как было.

## 4. Единица архивации по модулям

| Модуль | Единица | Откуда год | Что в `payload` |
|---|---|---|---|
| Клиндарий | **весь служебный год** | ключ `serviceYears[year]` | `serviceYears[year]` (недели, S-302, заметки) + `entries[]` в границах `CWServiceYear.bounds(year)` + замороженные копии событий, на которые они ссылаются |
| Конгрессы | **один конгресс** | `CWServiceYear.forDate(congress.date)` | объект из `st.congresses[]` целиком (задания, участники, `seriesId`, поля письма) |

**Почему год у Клиндария.** Блоб уже разложен по годам
(`serviceYears[year].weeks`), S-302 и недели живут внутри года, и сам
Алекс описал Архив «по служебным годам». Архивация отдельных визитов
раздробила бы год на десятки конвертов. Это моё предложение, Алекс может
поменять его до шага A3: схема (§2–3) от единицы не зависит.

Конгресс без даты в архив не отправляется: год не определить.
Кнопка показывает причину.

## 5. Резервное копирование (тот же заход, что и схема)

| Реестр `shared/backup.js` | Что добавить |
|---|---|
| `'archive'` (новый модуль) | `sharedStores: { DB: ['archive', 'documents'] }`. Хранилище целиком, слиянием. `documents` нужны для показа писем по `docRefs`. |
| `'circuit-planner'` | `{ store: 'archive', prefix: 'circuit-planner:' }` |
| `'congress-project'` | `{ store: 'archive', prefix: 'congress-project:' }` |
| Полная копия хаба | ничего: `circuit-workspace-db` уходит целиком |

Зачем префикс у модулей-источников. Когда позже включится удаление оригиналов
(A5), часть данных модуля будет жить только в Архиве. Копия одного Клиндария
без его конвертов восстановилась бы «без прошлых лет», без единой ошибки. Это
тот же класс отказа, что уже был с `cw-sender`. Ключи у модулей не
пересекаются, восстановление сливает по ключу, поэтому чужое не затирается.

**Поправка при исполнении A1 (05.10.2026).** Строка `'archive'` в реестре
переезжает на шаг A2, вместе со страницей модуля. Таблица копий на главной
строится из `Object.keys(CWBackup.MODULES)`, и строка без страницы и без
`CW_MODULES` показала бы там модуль, которого нет. Данных это не касается: до
A3 хранилище пусто, полная копия хаба везёт базу целиком, а префиксы
источников введены в A1. `CWArchive.SOURCES` — закрытый список, и
`check-backup.mjs` сверяет его с префиксами реестра: новый источник без строки
в копиях проверка не пропустит.

`scripts/check-backup.mjs`:
- реестр `archive` объявлен (с A2);
- копия Клиндария везёт только `circuit-planner:*` из `archive`;
- восстановление копии модуля не стирает конверты соседа.

## 6. `CWArchive` (shared/archive.js) — поверхность API

```
init()                         → Promise; без базы — честный отказ, не пустой список
put(envelope)                  → проверка формы, revision/firstArchivedAt, запись
get(id) / has(id)
list({ module?, serviceYear? }) → без payload (лёгкие строки для списка)
years()                        → служебные годы, где есть конверты
remove(id)                     → только по явному подтверждению в UI
```

Отказ записи **не глотается**, в отличие от `CWDocs.save()`. Там письмо уже
ушло адресату, а здесь пользователь должен знать, что архивация не случилась.

## 7. PIN Клиндария

PIN не меняется (решение Алекса). Пока `localStorage['syp-pin-hash']` задан,
раздел Клиндария в Архиве открывается только после ввода того же PIN с той
же функцией хэша (`App.ui.pinHash`, `circuit-planner/app.js:2722`). Хранение
хэша, его ключ и логика самого модуля не меняются. Как повторить проверку
без копии кода (вынос функции в `shared/` или чтение в Архиве), решается на
шаге A2 после чтения `pinHash`.

## 8. Чего здесь сознательно нет

- **Удаления оригинала и восстановления.** Пока конверт — копия, восстанавливать
  нечего. Это отдельный необратимый шаг A5 по «четырём правилам необратимого
  переноса» (`docs/journal/documents.md`): бэкап → конверт → проверка
  чтением → только потом удаление из блоба.
- **Автоархивации.** Модуль только предлагает: закончившийся служебный год у
  Клиндария, конгресс с прошедшей датой. Отклонённое предложение не
  повторяется навязчиво.
- **Школы и Журнала** (решение Алекса). Школа сможет зарегистрироваться тем же
  конвертом с `module: 'pioneer-school'`, когда до неё дойдёт задача В.

| Шаг | Что | Модель |
|---|---|---|
| **A1** ✓ | `CWDB` v7 + `shared/archive.js` + префиксы источников в реестре бэкапа + `check-backup.mjs`. Без UI. Сделан 05.10.2026, хаб 0.42.17. | Opus 5.5 High |
| **A2** ✓ | Модуль `archive/`: строка `archive` в реестре копий (§5), плитка «Архив», просмотр по годам, PIN-барьер для Клиндария, ссылки на письма. Вкладка архива в Документах называется «Документы» (5 языков). Сделан 05.10.2026, хаб 0.42.18. | Sonnet 5 High |
| **A3** | Клиндарий: «Отправить год в архив» + предложение для закончившегося года. | Sonnet 5 High |
| **A4** | Конгрессы: «В архив» у конгресса + предложение для прошедших. | Sonnet 5 Medium |
| **A5** | Удаление оригинала после архивации и восстановление из Архива. Необратимо, отдельное подтверждение. | Opus 5.5 High |

Пока оригинал не удаляется, правка старого года в Клиндарии после архивации
делает конверт устаревшим. Модуль сравнивает отпечаток и предлагает
«обновить архив», повторная запись идёт `put()` поверх (§3, п. 1).

## 10. Как закрыт PIN-барьер на A2 (05.10.2026)

Вариант «вынести `pinHash` в `shared/`» отвергнут: он правит код Клиндария и
его PIN, а §7 запрещает менять логику модуля. Принято: хэш повторён побайтно в
`archive/js/pin.js`, расхождение с `App.ui.pinHash` стережёт
`scripts/check-archive-module.mjs` (достаёт функцию из `circuit-planner/app.js`
и сравнивает на наборе PIN). Закрытый раздел не попадает в список, годы,
поиск и в сообщение «архив пуст»; состояние «открыто» живёт в памяти страницы.

Ключ `doc.tab_archive` общий: его же показывают Школа и Конгрессы для своих
архивов документов. Поэтому Документы получили отдельный ключ
`doc.tab_documents`, а прежний ключ и его значение не менялись.
