Схема не менялась: ни хранилищ, ни индексов, ни подъёма `DB_VERSION`.

**Проект** — строка `journalEntries` с `type:'project'`, только через новый
`CWJournal.projects`. Владелец — район (`nodeId = circuitId`), оба поля и
`type` неизменяемы. Текст пользователя — только `title` (обязателен) и

## 2026-09-22 — Журнал J6: поиск и архив

Схема не менялась: ни хранилищ, ни индексов, ни подъёма `DB_VERSION`.

**Поиск** — `CWJournal.search.run(query, { includeArchive, resolveCommunity,
labelVisit })`: только чтение, по требованию, в памяти — узлы и записи
читаются один раз за прогон. Сохранённого индекса, истории запросов и кэша
открытого текста нет нигде (граница J8); запрос не попадает ни в хэш, ни в
историю браузера, ни в localStorage — живёт в памяти экрана. Нормализация:
регистр, `ё ≡ е`, латинские диакритики, `ß→ss`, `ł→l`; `й/ї/ґ` не
сворачиваются. Несколько слов — «И»; хотя бы одно слово должно быть в
собственном тексте (у посещения — в подписи/датах), остальные могут
совпасть с контекстом район › собрание › группа. Ранг: поле целиком →
начало поля → подстрока → свежее `updatedAt` → id. Название, номер, адрес
и контакт из CWDirectory участвуют только в памяти; без справочника
работает локальная подпись узла. Строка с `sec` текстом не ищется —
только считается («защищённые записи не искались: N»).

Экран «Поиск» (эталоны 07-search-m/d): поле с очисткой, фильтры со
счётчиками, группы «Визиты / Записи и проекты / Задачи / Районы и
собрания», отрывок с подсветкой (`<mark>` + `textContent`, пользовательский
текст не проходит через `innerHTML`), крошки контекста, пустое состояние и
«ничего не найдено». Архивный контекст по умолчанию исключён и
открывается фильтром «Архив». Устаревший ответ отбрасывается по номеру
прогона. Кнопка поиска в шапке ставит фокус в поле.

**Архив** — `status`/`archivedAt`, не хранилище. Узел: новые
`nodes.archive()` / `nodes.unarchive()` (восстановление физически удаляет
`archivedAt`); прямой патч статуса через `nodes.update` отклоняется
(`journal-node-use-lifecycle`), меню дерева переведены на цикл. Посещение —
прежние `visits.archive/unarchive`. Архивность «в контексте» (узел, предок,
посещение-источник) вычисляется при чтении и не пишется; выполненная
задача и закрытый перенос архивом не являются. `CWJournal.archive.list()`
— только напрямую архивные узлы и посещения, новые сверху; легаси-узел без
`archivedAt` не теряется; объект с архивным предком помечен. Экран
«Архив»: вкладки, дата архивации, «Восстановить» (только выбранный объект,
без каскада), переход к объекту; удаления нет.

Новая проверка `check-journal-search-archive.mjs` в гейте;
`check-journal-db.mjs` переведён на цикл архива узла. Неиспользуемые
ключи `j.placeholder.*` удалены.

**Версии:** Журнал `0.7.0 → 0.8.0`; патч-бамп общего слоя: хаб

## 2026-09-22 — Журнал J5: задачи и перенос «на следующее посещение»

Схема не менялась. **Перенос** — `CWJournal.carry`: запись посещения
(заметка, наблюдение, вопрос, задача) помечается «На след. визит» в
посещении-источнике; это та же строка `journalEntries`, между посещениями
она не копируется и не переподчиняется (`fields.visitId` остаётся
источником). Открытый пункт несёт `carryKey = '<nodeId>:open'`; закрытый —
поля НЕТ физически: закрытие переписывает запись целиком через
`mutate()` общей базы (`replaceEntry`), `null`/`''`/`false` не пишутся.
История — `touches[]`: `{ visitId, at, action }`, `raised | kept |
deferred | closed`, без текста пользователя. В более позднем посещении того
же узла пункт входящий: «Закрыть», «Оставить открытым», «Перенести дальше».
Поднятый в самом посещении пункт входящим для него не считается — он
в строке «Помечено на следующее посещение», которая теперь настоящая.
Решение принимается только в открытом посещении; посещение, на которое
ссылается история переноса, не удаляется (`journal-visit-has-carry`).

**Задачи** — единый цикл todo `CWJournal.tasks` для задач посещений и
самостоятельных задач узла (район, собрание, группа, предгруппа):
создание, правка текста, необязательный срок (`dueDate`, верхнее
индексируемое поле; снятие срока удаляет поле), выполнение/возврат,
удаление без связей. `visitRecords.complete/reopen` делегируют этому циклу.
Задача завершённого или архивного посещения — только чтение и на экране
«Задачи» (правило в слое данных). Порядок: открытые — со сроком раньше,
ранний срок первым, затем создание; выполненные — свежие первыми. Экран
«Задачи» стал рабочим: «Открытые/Выполненные», контекст район › узел
(и сезон посещения), явный выбор области при создании.

Общий фасад `CWJournal.entries` больше не создаёт, не правит и не удаляет
задачи (`journal-task-use-facade`) и не трогает `carryKey`/`touches`
(`journal-carry-use-facade`). Контрольные прогоны: без этих стражей — 8
провалов обхода; закрытие через слияние с `carryKey: null` — 4 провала.

Эталон `05-carryover-m.jpg`: поле «Комментарий к решению» не заведено —
текст в `touches[]` стал бы вторым каналом открытого текста вне `body`
(граница J8). Попутно: `[hidden]` внутри модуля теперь всегда скрывает —
общие `.md-banner/.md-btn/.md-field` перебивали его (пустой баннер переноса
и кнопка удаления в диалоге задачи были видны).

Новый гейт `scripts/check-journal-carry-tasks.mjs`. Проверки J2 для
индексов `carryKey`/`type` заводят строки на уровне `CWDB`: общий фасад
такие строки больше не создаёт.

**Версии:** Журнал `0.6.0 → 0.7.0`; хаб `0.41.44 → 0.41.45`; патч-бамп
кэш-фёрст оболочек из-за правки `shared/version.js`: Конгрессы

## 2026-09-22 — Журнал J4b: записи посещения

Редактор экрана посещения стал настоящим: заметки, наблюдения, вопросы и

записи можно только в открытом посещении: завершённое и архивное — только
чтение, правило держит слой данных (`journal-visit-readonly`). Порядок —

неактивны. «Итоги визита» показывают реальное число открытых и выполненных

## 2026-09-22 — Журнал J4a: посещения и экран посещения

Посещение — строка `journalEntries` с `type:'visit'` (пятого хранилища нет,
схема не менялась), доступ только через новый `CWJournal.visits`. Родитель —
собрание, группа или предгруппа; `type/nodeId/circuitId` неизменяемы; даты
`dateFrom/dateTo` в формате `YYYY-MM-DD`, окончание не раньше начала,
пересечение посещений одного узла допускается. Статус: `open ↔ completed`,
любой → `archived` с `archivedAt` (возврат к прежнему статусу) — только
через `complete/reopen/archive/unarchive`, не через `update()`. Удаление
отказывает, пока у посещения есть записи (`fields.visitId`, контракт для
J4b) или связи — безопасная альтернатива архив.
Граница держится в самом слое данных: общий фасад `CWJournal.entries`
посещения не мутирует — `add({type:'visit'})`, `update()` и `remove()`
посещения отклоняются с `journal-visit-use-facade` (без молчаливого
перенаправления), так что обойти инварианты через официальный фасад нельзя.
Чтение через `entries.*` не ограничено.

Маршрут: `#districts/<c>/congregation/<n>/visits` (вкладка «Посещения») и
`…/visit/<v>` (экран посещения). Разбор вынесен в `journal/js/route.js` —
чистая функция под тестом; роутер один. Неизвестное или чужое посещение и
неполный хвост маршрута ведут к вкладке «Посещения» собрания, битые id
района/собрания — к списку районов.

Вкладка «Посещения» собрания стала рабочей: реальный список (новые сверху),
пустое состояние, FAB «Визит» с диалогом дат. Экран посещения по эталонам
`04-visit-m/-d.jpg`: крошки район → собрание → сезон, заголовок «Визит —
весна 2028» и диапазон дат (производные от `dateFrom`, не хранятся),
