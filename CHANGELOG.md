## 2026-09-02 (второй заход) — Документы: variable picker перетаскивается на desktop

**Версии:** Документы `1.7.2 → 1.8.0` (minor — новый функционал). Version-only
патч-бамп (правка `shared/version.js` требует его у cache-first оболочек,
подтверждено `check-shared-bump.mjs` с `CW_BUMP_BASE=HEAD`): хаб
`0.41.9 → 0.41.10`, Конгрессы `4.46.31 → 4.46.32`, Школа пионеров
`1.14.9 → 1.14.10`, Назначения `5.5.48 → 5.5.49`. Клиндарий не в списке —
stale-while-revalidate, бамп не требуется.

Селектор переменных на desktop теперь открывается справа над preview-зоной
(редактор слева остаётся максимально открытым) и может быть перетащен
мышкой/Pointer Events за шапку «Переменные» в любое удобное место экрана.

- **Позиционирование.** Нативный `<dialog>` остаётся модальным через
  `showModal()` без изменений — desktop-режим (`≥1201px`, тот же порог, что
  уже определяет wide для split-view) снимает браузерное центрирование
  (`margin:0`) и держит `left`/`top` через JS
  (`computeDefaultVarsDialogPos()`/`applyVarsDialogPos()` в
  `documents/js/app.js`). Дефолтная позиция вычисляется от фактической
  ширины диалога и текущего `window.innerWidth`, не хардкодом.
- **Drag.** `pointerdown`/`pointermove`/`pointerup` с `setPointerCapture()`
  на `.vars-dialog__head`; клик по кнопке закрытия (`e.target.closest
  ('button')`) не инициирует drag; поиск/список физически вне шапки, туда
  pointerdown не долетает вовсе. `cursor: grab`/`grabbing` — визуальная
  подсказка.
- **Последняя позиция сессии.** `varsDialogPos` — простая переменная в
  замыкании (не персистится между перезагрузками страницы, по утверждённому
  плану — не требуется на этой фазе). `null`, пока пользователь не двигал
  диалог; после `pointerup` хранит последнюю зажатую в границы позицию.
  Следующее открытие использует её вместо дефолтной.
- **Clamp.** Общая `clampVarsDialogPos()` не даёт окну уехать полностью за
  viewport (минимум 80px шапки остаётся видимым с любой стороны) —
  переиспользуется и на `pointerup`, и на `resize`, и на пересечении
  wide/mobile порога.
- **Mobile не тронут.** `isWide()` проверяется заново на каждый
  `pointerdown`, а не один раз при навеске — переход wide→mobile во время
  открытого диалога не оставляет «залипший» обработчик. При пересечении
  порога в mobile-сторону inline `left`/`top` явно очищаются
  (`dlg.style.left = ''`) — иначе их специфичность перебила бы CSS
  bottom-sheet раскладку целиком. `varsDialogPos` при этом не обнуляется —
  при возврате на wide последняя позиция восстанавливается.

Split-view, пропорции колонок, breakpoint 1201, preview rendering,
caret-fix, поиск/список picker'а, multiple insertion, variable mappings,
i18n, template engine — не тронуты. HTML не менялся вовсе: существующая
разметка `.vars-dialog__head`/`#varsDialogClose` оказалась пригодна как
drag-handle без изменений.

## 2026-09-02 — Документы: кнопка переменной и перекрытие picker — реальные CSS-причины найдены и исправлены

**Версии:** Документы `1.7.1 → 1.7.2` (патч — исправление дефекта). Version-only
патч-бамп (правка `shared/version.js` требует его у cache-first оболочек,
подтверждено `check-shared-bump.mjs` с `CW_BUMP_BASE=HEAD`): хаб
`0.41.8 → 0.41.9`, Конгрессы `4.46.30 → 4.46.31`, Школа пионеров
`1.14.8 → 1.14.9`, Назначения `5.5.47 → 5.5.48`. Клиндарий не в списке —
stale-while-revalidate, бамп не требуется.

Прошлая правка (восьмой заход, 01.09.2026) поменяла JS-логику
(`view === 'edit'` вместо `viewEdit.hidden`), но реальный браузерный тест
показал: оба дефекта остались. Диагностика по требованию Алекса —
«сначала не правь код» — показала, что JS был верен с самого начала, оба
бага были чисто CSS-каскадными и не проявлялись ни в изолированной
JS-симуляции (jsdom), ни в статичном скриншоте без взаимодействия.

- **Кнопка «+ Вставить переменную» оставалась видимой на Preview.**
  `setView()` действительно ставил `insertVarBtn.hidden = true` — но
  `.md-btn { display: inline-flex }` (`shared/style.css`) — авторское
  CSS-правило, побеждающее браузерный UA-стиль `[hidden]{display:none}` в
  каскаде независимо от совпадающей специфичности внутри origin (тот же
  класс бага, что раньше был у `.vars-dialog`). Подтверждено реальным
  WebKit-рендерером на изолированном тесте: jsdom дал ложноотрицательный
  результат, его модель специфичности не воспроизводит этот пограничный
  случай браузеров. Fix — локально в Documents (осознанно не расширяя scope
  на `shared/style.css` ради одной кнопки):
  `#insertVarBtn[hidden] { display: none; }`.
- **Карточки picker заезжали под поле поиска.** Первая гипотеза (нет
  непрозрачного фона на шапке) оказалась неполной: добавление `background` +
  `z-index` не устранило баг при повторной проверке тем же WebKit-тестом.
  Настоящая причина — отсутствие `flex-shrink: 0` на `.vars-dialog__head`/
  `.vars-dialog__search`: при ограниченной `max-height` у диалога (обычный
  случай — переменных много) браузер сжимает любой flex-item со свободным
  `flex-shrink` по умолчанию, и шапка/поиск теряли часть визуальной высоты
  вместо того, чтобы остаться нетронутыми, пока сжимается только список.
  Баг воспроизводился даже БЕЗ скролла, в первом кадре — дело было не в
  scroll-behaviour, а в flex-геометрии. Fix: `flex-shrink: 0` на шапке/
  поиске, `flex: 1 1 auto` на `.vars-dialog__list` — список остаётся
  единственным `overflow-y: auto`, ничего в scroll-структуре не менялось.
  Background на шапке оставлен как дополнительная защита.

Split-view, пропорции колонок, breakpoint, preview rendering, caret-fix,
variable mappings, aliases, template engine, `shared/style.css` — не
тронуты.

На desktop (широкий экран) вкладка «Текст» редактора шаблонов теперь
показывает редактор и живой предпросмотр рядом, а не по очереди через
переключение вкладок.

- **Только на wide, только на «Тексте».** Вкладка «Предпросмотр» по-прежнему
  показывает готовый документ на всю ширину; «Страницы» не тронуты вовсе.

- **Порог — `1201px`**, не заново введённое число, а уже одобренная парная

- **Existing `renderPreview()` переиспользован как есть**, без второго
  движка предпросмотра. Новый только вызывающий код: debounce (~200мс) на

  лишнего не считается. Одиночная вставка переменной через picker обновляет
  предпросмотр сразу, без debounce (не поток событий, а разовое действие).
- **`setView()` расширен**, не переписан: prежняя взаимоисключающая ветка
  осталась нетронутой для mobile; для wide добавлены отдельные условия —
  «Текст» показывает редактор и предпросмотр одновременно, «Предпросмотр»
  прячет редактор. Класс на общем контейнере переключает CSS Grid в две
  колонки; `hidden`-атрибуты остаются единственным источником правды о
  видимости, CSS ничего не решает поверх них.
- **Resize** между узким и широким окном обрабатывается через `matchMedia` (тот
  же паттерн, что уже используется в `shared/theme.js` для системной тёмной
  темы) — переход в любую сторону мгновенно пересчитывает раскладку и, если
  нужно, обновляет предпросмотр.
- Variable picker, caret-fix, `insertToken()`, шаблонизатор, переводы,
  разметка HTML — не тронуты.

## 2026-09-01 (шестой заход) — Документы: закрытый dialog переменных больше не торчит на странице

**Версии:** Документы `1.6.0 → 1.6.1` (патч — исправление дефекта, не новый
функционал). Version-only патч-бамп (правка `shared/version.js` требует его
у cache-first оболочек, подтверждено `check-shared-bump.mjs` с
`CW_BUMP_BASE=HEAD`): хаб `0.41.5 → 0.41.6`, Конгрессы `4.46.27 → 4.46.28`,
Школа пионеров `1.14.5 → 1.14.6`, Назначения `5.5.44 → 5.5.45`. Клиндарий не
в списке — stale-while-revalidate, бамп не требуется.

Два дефекта после реального теста на живом деплое.

- **Закрытый `<dialog>` селектора переменных оставался виден снизу
  страницы** на Text и на Preview, на desktop и на mobile. Причина: правило
  `.vars-dialog { ...; display: flex; ... }` (`documents/css/styles.css`)
  задавало `display: flex` БЕЗУСЛОВНО, для любого состояния диалога, а не
  только для открытого. Авторский CSS побеждает браузерный UA-стиль
  `dialog:not([open]){display:none}` в каскаде — и закрытый диалог никогда
  не возвращался к `none`. Правило `.vars-dialog[open]{display:flex}` рядом
  ничего не решало: базовое правило выше уже держало `display:flex`
  постоянно. Исправлено: `display:flex` перенесён строго под
  `.vars-dialog[open]`, добавлено защитное `.vars-dialog:not([open])
  {display:none}`. Подтверждено `getComputedStyle` через jsdom на обоих
  состояниях и обоих viewport (desktop/mobile).
- **Кнопка «+ Вставить переменную» оставалась видимой на вкладке
  «Предпросмотр»**, где вставлять уже некуда — Preview не редактируется.
  `setView()` (`documents/js/app.js`) теперь скрывает кнопку на всех
  вкладках кроме «Текст» и закрывает диалог переменных, если он был открыт
  при уходе с «Текста».

`showModal()`/`close()`, picker layout, поиск, caret-fix, i18n, variable
mappings, aliases, template engine — не тронуты.
