(30.08.2026, фаза 2 аудита контекста): файл читался целиком и стоил

## 2026-09-04 — Клиндарий: карта собраний (desktop-only)

**Версии:** Клиндарий `9.94.7 → 9.94.8`. Version-only патч-бамп общего слоя
(правка `shared/version.js` сама прекэшируется всеми cache-first модулями):
хаб `0.41.21 → 0.41.22`, Конгрессы `4.46.42 → 4.46.43`, Школа
`1.14.20 → 1.14.21`, Назначения `5.5.59 → 5.5.60`, Документы
`1.10.10 → 1.10.11`. Функциональных правок в этих пяти модулях нет.
Подтверждено `check-shared-bump.mjs` с `CW_BUMP_BASE=HEAD`.

Экран «Собрания и события» получил кнопку «Показать карту» рядом со
List/Cards — отдельный open/close-переключатель, НЕ третий
`eventsViewMode` (он остаётся строго `list`/`cards`). При открытии на
desktop список/карточки слева, карта справа (`grid`, порог переиспользует
уже одобренный `1181px`, новый breakpoint не заводился); повторный клик
скрывает карту. Leaflet подключён **module-local**
(`circuit-planner/vendor/leaflet.js` + `leaflet.css`, npm `leaflet@1.9.4`,
без сборки) — не `shared/vendor/`, чтобы будущие апдейты библиотеки не
задевали cache-first-модули и их каскад. Маркеры — `L.circleMarker()`, без
PNG-иконок. Клик по маркеру открывает тот же редактор события, что и
List/Cards (`App.actions.openEventEditorFor`, вынесен из инлайн-обработчика
без изменения поведения). `fitBounds` по всем событиям с `lat`/`lng`;
события без координат не получают маркер и не ломают карту; если
координат нет вовсе — плейсхолдер «Нет собраний с координатами». OSM tiles
— только runtime, не прекэшируются; при офлайн-сбое тайлов — ненавязчивый
оверлей «Карта недоступна офлайн» внутри map-pane, List/Cards продолжают
работать. `leaflet.js`/`leaflet.css`/`ui/map.js` добавлены в SW
APP_SHELL_URLS (cache-first, как шрифты). Mobile-карта в этой фазе не
делалась. Модель event и `shared/*` (кроме `version.js`, release-метаоперация
выше) не менялись.

i18n: 3 новых ключа (`cp.show_map`, `cp.map_no_coords`,
`cp.map_offline_notice`) сразу на всех 5 языках (ru/uk/en/pl/de), долг
перевода = 0.

Live browser test: NOT TESTED — Chromium недоступен в среде подготовки
патча, требуется прогон перед деплоем.

## 2026-09-03 (двенадцатый заход) — Документы: реальная причина mobile-разрыва в библиотеке, editor header переведён на grid

**Версии:** Документы `1.10.5 → 1.10.6`. Version-only патч-бамп: хаб
`0.41.15 → 0.41.16`, Конгрессы `4.46.37 → 4.46.38`, Школа `1.14.15 → 1.14.16`,
Назначения `5.5.54 → 5.5.55`. Клиндарий не тронут.

- **Библиотека:** найдена подтверждённая причина большого пустого разрыва
  между поиском и «Шаблон для типа задания» на mobile —
  `.doc-search{flex:1 1 280px}` даёт `flex-basis:280px`, а
  `flex-direction:column` (мобильный toolbar) разворачивает главную ось
  вертикально: те же 280px становятся высотой поля вместо ширины. Fix —
  `flex-basis:auto` только в `@media(max-width:600px)`.
- **Редактор:** `.ed__head` переведён на CSS Grid на всех ширинах (был
  flex + `flex-basis:100%` на языковом меню — это ломало desktop, перенося
  Restore/Save на отдельную строку). Grid с именованными областями даёт
  фиксированное место каждому элементу независимо от порядка в DOM.
  `#edLangMenu` перемещён внутрь `.ed__head` (тот же id, то же содержимое).

`documents/js/app.js` не тронут.



**Версии:** Документы `1.10.4 → 1.10.5` (патч — UX-перестройка без изменения
данных/логики). Version-only патч-бамп (правка `shared/version.js` требует

  (`opacity:0`) поверх иконки на всю площадь — вся зона кликабельна и
  открывает тот же нативный picker, что и раньше.
  **`#docLang`** (язык документа по умолчанию) перенесён туда же, рядом,

  `initDocLangSelect()`, не менялось), без прозрачной подложки. Итоговый
  порядок в шапке: `[UK ▾] [🌐]`. Смысл обоих контролов сохранён через
  `title`/`aria-label` (существующие ключи `hub.language_label`,
  `doc.doclang_label`), видимый текстовый `<label>` убран из рабочей
  области.
- **«Шаблон для типа задания»** теперь сразу рядом с полем поиска в
  тулбаре библиотеки — `.doc-toolbar__spacer` и `.doc-lang-field` (пустой
  после переноса) убраны как более не нужные.
- Фильтры (`Все / Конгрессы / Клиндарий / Школа пионеров / Изменённые`) —
  отдельная группа, не тронуты.
- Mobile (≤600px, зарегистрированная точка `phone`): `.doc-toolbar`
  переходит в колонку — поиск и кнопка шаблона получают `width:100%` и
  стоят одна под другой вместо горизонтальной тесноты. Шапка сама уже была
  готова к сужению actions (`shared/style.css`, `.md-topbar-v2__actions`),
  новых точек не заводилось.

Desktop/mobile раскладка подтверждена статическим CSS-анализом и полным
gate-прогоном; реального browser-run в этой фазе не было (см. ограничения

**Версии:** Документы `1.10.3 → 1.10.4` (патч — два визуальных исправления,
не новый функционал). `shared/*` в этой фазе не менялся — версии остальных
модулей не пересчитывались заново.

Реальный тест v1.10.3 показал два визуальных дефекта, оба чисто CSS,
`documents/js/app.js` не тронут вовсе — подтверждено побайтовым сравнением
с прошлой доставкой.

- **Панель языкового меню уезжала за левый край экрана.** `.md-menu__panel`
  (`shared/style.css`) по умолчанию `right:0` — растёт влево от правого
  края триггера, что верно для меню в конце строки (например, «Вставка» в
  тулбаре). Но `#edLangMenu` стоит отдельным блоком у левого края страницы,
  и рост влево от узкой кнопки «UK ▾» уводил панель ~150px за границу
  viewport — видна была только тонкая полоска, все пункты UK/RU/DE/PL/EN
  недоступны. Fix локален: `#edLangMenuPanel { left: 0; right: auto; }` —
  `shared/style.css` и меню «Вставка» не тронуты. Подтверждено реальным
  WebKit-рендерером на desktop и mobile (390px) — все 5 языков полностью
  видны в обоих случаях, без horizontal overflow.
- **«Восстановить оригинал» и «Сохранить» не были на одной линии.** После
  переноса save-статуса под кнопку (прошлая фаза, B1) `.ed__save-group`
  (кнопка + статус + gap) стала выше простой кнопки `#resetBtn` —
  `.ed__head { align-items: center }` центрировал `#resetBtn` по этой
  увеличенной высоте строки, визуально сдвигая его ниже верхнего края
  «Сохранить». Fix точечный: `#resetBtn` и `.ed__save-group` получили
  `align-self: flex-start` — выравниваются по верхнему краю строки, не
  трогая `align-items` самого `.ed__head` и поведение остальных элементов.
  Подтверждено реальным WebKit-рендерером: обе кнопки на одной линии на
  desktop; mobile wrap-поведение (перенос «Сохранить» на новую строку при
  недостатке ширины) сохранено без изменений.

i18n: новых ключей не потребовалось, 119 ключей без изменений, долг
перевода = 0.

RTE, 5 языков, lazy migration, Restore per-language, preview, variable
picker, Insert menu, взаимное закрытие меню — не тронуты (JS не менялся
в этой фазе).

## 2026-09-02 (девятый заход) — Документы: статус сохранения переехал к кнопке «Сохранить»

**Версии:** Документы `1.10.2 → 1.10.3` (патч — UX-улучшение по утверждённой
визуализации, не новый функционал). `shared/*` в этой фазе не менялся —

Финальный UX-аудит (пункт B1) нашёл: статус сохранения жил в шапке хаба,
рядом с номером версии модуля, далеко от кнопки «Сохранить» — пользователь
не видел результат действия в поле зрения самого действия.

- **Новый `#editorSaveStatus`** — тот же переиспользуемый shared-компонент
  `.md-savestatus` (`shared/style.css`, раздел 5.11 — уже используется
  Конгрессами и Назначениями в topbar), второй экземпляр внутри
  `.ed__head`, в `.ed__save-group` рядом с `#saveBtn`. Новый визуальный
  примитив не создавался.
- **Старый `#saveStatus` в topbar остался** — он обслуживает несвязанные
