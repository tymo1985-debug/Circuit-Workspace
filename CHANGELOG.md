## 2026-09-24 — Журнал 0.12.0 и Документы 1.11.0: письма проекта района (J9b)

В карточке проекта Журнала — «Создать письмо» и раздел «Документы проекта».
Второго механизма документов нет: текст — `CWTemplates`, язык —
`CWDocLang`, архив — `CWDocs`, карточки истории — `CWDocsView`, печать —
`CWPrint`. Новый системный шаблон `sys.journal.project.letter` (контекст
`journal.project.letter`, формат text) минимален: тема `{{project.title}}`,
текст `{{project.body}}`; новое пространство переменных `project`. Правка в
композере — только для этого письма; сам шаблон правится в «Документах».
Снимок в архив (`ref {journal, project, id}`) — только печать и «Сохранить
в архив»; просмотр, смена языка и копирование не пишут. `journalLinks` для
документов не заводятся; удаление проекта историю писем не удаляет.

Граница J8 — правило слоя данных (`CWJournal.documents`): защищённый проект
письма не получает ни заблокированным, ни разблокированным; проект со
снимками в архиве защитить нельзя, пока они не удалены; архив недоступен —
защита проекта отказывает — через новый строгий `CWDocs.listStrict()`
(терпимый `list()` при сбое базы отдаёт `[]` и для этого решения не годится).
«Защита ∥ снимок» — не гонка, а сериализация одной транзакцией IndexedDB:
снимок пишется новым `CWDocs.saveGuarded()` одним `CWDB.batch` с предусловием
на строку проекта (та же, без `sec`, не в архиве), защита и первая настройка —
одним пакетом с новым предусловием `expectNone` «у проекта нет снимков».
Кто закоммитил первым, тот и прав; уборки задним числом нет. Архивный проект — только
чтение: история писем видна, новое письмо не собирается. Отказ архива (`CWDocs.save()` → null) не выдаётся за
«сохранено»; при печати — «отправлено на печать, в архив не сохранено».
Композер при каждом открытии перечитывает шаблоны (`CWTemplates.reload()`):
правка в «Документах» видна без перезагрузки Журнала.

«Документы»: Журнал в фильтрах библиотеки и архива; глубокие ссылки
`#template/<id>` и `#archive/<module>/<entity>/<id>` (кривая ссылка — обычный
запуск). Копия Журнала везёт `templates` и `documents` и сливает их; набор
замены J8 прежний — четыре хранилища Журнала.

## 2026-09-23 — Журнал 0.11.0 и Клиндарий 9.95.0: связь посещения с Клиндарием (J9a)

Посещение Журнала связывается с настоящей записью Клиндария. Связь — одна
строка `journalLinks` `journal:entry/<посещение> → cw:circuit-planner/entry/<id>`
(rel `external`): ни дат, ни заголовка, ни названия собрания Журнал не
хранит — всё берётся живым при отрисовке. Кандидаты ранжируются по
собранию (id события = id справочника, только у визитов), пересечению и
близости дат (±14 дней) и типу визита; связь пишется только явным выбором.
У посещения не больше одной такой связи, и это держит ключ: связь —
«слот» с постоянным id на посещение, перепривязка — `put` в тот же ключ,
поэтому две вкладки не оставят двух строк. Прочие внешние связи и связи
проектов не трогаются. Мост обновляет название и по `CWDirectory.onChange()`. Правила «только чтение» закрытого/архивного посещения и запрет
удаления посещения со связями — прежние. Удалённая запись Клиндария связь
не стирает: чип показывает «Запись Клиндария не найдена», её можно
перепривязать или снять; запись с тем же id снова разрешается.

Общий слой: `shared/planner.js` (`CWPlanner`) — публичная граница
Клиндария только для чтения. Читает канон `state/circuit-planner`,
отдаёт замороженные копии `{id, eventId, start, end, title, name, visitType,
communityId}`, ничего не пишет и не кэширует на диске; обновляется по
маячку `cw-state-rev:circuit-planner` (соседняя вкладка) и при возврате из
bfcache, без опроса. Журнал блоб Клиндария не разбирает.

Клиндарий: глубокая ссылка `#calendar?entry=<id>` открывает календарь на
месяце записи с её карточкой; id — по белому списку символов, неизвестная
запись — обычный запуск, PIN не обходится. Ярлыки PWA не изменились.
