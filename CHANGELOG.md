## 2026-09-24 — Журнал 0.13.1: защита записей не затирает параллельную правку (J8-H1)

Три пути J8 пишут строку `journalEntries` целиком из копии, прочитанной до
асинхронного шифрования: защита и первая настройка (`protectOp`), снятие
защиты (`unprotect`) и правка защищённого текста (`writeProtectedText`).
Предусловие было по отдельным полям (`sec`/`title`/`body`/`updatedAt`); если
соседняя вкладка меняла статус, срок, перенос, `fields` или любое другое поле
в ту же миллисекунду, старая копия молча её затирала. Теперь все три пути
пишут через один помощник Журнала `guardedPut()`: строка в базе обязана
совпасть со снимком ЦЕЛИКОМ — те же поля и ни одного нового (общий фасад
записей допускает и произвольные поля, поэтому не по списку). Не совпало —
пакет отказывает с прежней ошибкой `journal-protected-conflict`, чужая
строка не тронута.

Общий слой: `CWDB.batch` получил необязательный флаг `exact: true` у
предусловия (`match` — полный снимок записи, сравнение без учёта порядка
ключей). Без флага семантика прежняя. `DB_VERSION` = 6, формат шифрования,
хранилища, копия и контракты J9a/J9b/J9c не менялись.

Новая проверка гейта — `check-journal-protection-race.mjs`: часы заморожены,
гонки в одну миллисекунду воспроизводятся детерминированно; на прежнем коде
она падает. Патч-бамп кэш-фёрст оболочек (правка общего слоя): Конгрессы
4.46.77, Школа 1.14.53, Назначения 5.5.92, Документы 1.11.2; хаб 0.41.55.
Клиндарий не менялся.

## 2026-09-24 — Журнал 0.13.0: задачи для общего To Do (J9c)

видит задачи Журнала, — без переноса данных: задачи остаются строками
`journalEntries` (type `todo`), правила — в `CWJournal.tasks`.

Общий слой `shared/todo.js` (`CWTodo`) — только чтение: поставщики по
модулям (`register`), `init/refresh/status/list/get/urlFor/subscribe`.
Контракт задачи: `key` (module:id), `module`, `id`, `ref`, `status`
(open|done), `dueDate`, `text`, `protected`, `mutable`, `origin`, `url`;
замороженные копии, ничего не хранится. Единственный поставщик — Журнал
(`journal/js/todo-provider.js`) через `CWJournal.integration`: сырые строки
без раскрытия J8 — у защищённой задачи `text` = null и при разблокированном
Журнале, `sec` наружу не выходит; одна строка todo — одна задача, перенос и
связи проектов не копируются; `mutable` — по жизненному циклу посещения.

Ссылка на задачу — `#tasks/<id>` (`CWJournalRoute.build.task`): экран
«Задачи», нужная вкладка, строка подсвечена; защищённая закрытая —
обычная разблокировка; нет задачи или кривой хвост — просто «Задачи».
Свежесть без опроса: уведомление в вкладке после каждой записи задач,
`BroadcastChannel('cw-journal')` для соседних (сообщение без данных), bfcache
и `refresh()`; в хранилищах браузера следа нет. После первого `init()` ни
один сигнал не теряется: чтение идёт «насосом» с флагом dirty — сигнал или
новый поставщик во время чтения дают ещё один проход, пачка сигналов
сливается в один; до `init()` мост ленив. Новых хранилищ нет,
`DB_VERSION` = 6, копия Журнала прежняя.

Новая проверка гейта — `check-journal-todo-integration.mjs`. Патч-бамп

Граница J8 — правило слоя данных (`CWJournal.documents`): защищённый проект

«Защита ∥ снимок» — не гонка, а сериализация одной транзакцией IndexedDB:
снимок пишется новым `CWDocs.saveGuarded()` одним `CWDB.batch` с предусловием
на строку проекта (та же, без `sec`, не в архиве), защита и первая настройка —
одним пакетом с новым предусловием `expectNone` «у проекта нет снимков».
Кто закоммитил первым, тот и прав; уборки задним числом нет. Архивный проект — только
чтение: история писем видна, новое письмо не собирается. Отказ архива (`CWDocs.save()` → null) не выдаётся за
«сохранено»; при печати — «отправлено на печать, в архив не сохранено».
Композер при каждом открытии перечитывает шаблоны (`CWTemplates.reload()`):
правка в «Документах» видна без перезагрузки Журнала.

«Документы»: Журнал в фильтрах библиотеки и архива; глубокие ссылки
`#template/<id>` и `#archive/<module>/<entity>/<id>` (кривая ссылка — обычный

## 2026-09-23 — Журнал 0.11.0 и Клиндарий 9.95.0: связь посещения с Клиндарием (J9a)

Посещение Журнала связывается с настоящей записью Клиндария. Связь — одна
строка `journalLinks` `journal:entry/<посещение> → cw:circuit-planner/entry/<id>`
(rel `external`): ни дат, ни заголовка, ни названия собрания Журнал не
хранит — всё берётся живым при отрисовке. Кандидаты ранжируются по
собранию (id события = id справочника, только у визитов), пересечению и
близости дат (±14 дней) и типу визита; связь пишется только явным выбором.
У посещения не больше одной такой связи, и это держит ключ: связь —
«слот» с постоянным id на посещение, перепривязка — `put` в тот же ключ,
поэтому две вкладки не оставят двух строк. Прочие внешние связи и связи
проектов не трогаются. Мост обновляет название и по `CWDirectory.onChange()`. Правила «только чтение» закрытого/архивного посещения и запрет
удаления посещения со связями — прежние. Удалённая запись Клиндария связь
не стирает: чип показывает «Запись Клиндария не найдена», её можно
перепривязать или снять; запись с тем же id снова разрешается.

Общий слой: `shared/planner.js` (`CWPlanner`) — публичная граница
Клиндария только для чтения. Читает канон `state/circuit-planner`,
отдаёт замороженные копии `{id, eventId, start, end, title, name, visitType,
communityId}`, ничего не пишет и не кэширует на диске; обновляется по
маячку `cw-state-rev:circuit-planner` (соседняя вкладка) и при возврате из
bfcache, без опроса. Журнал блоб Клиндария не разбирает.

Клиндарий: глубокая ссылка `#calendar?entry=<id>` открывает календарь на
месяце записи с её карточкой; id — по белому списку символов, неизвестная
запись — обычный запуск, PIN не обходится. Ярлыки PWA не изменились.

Новая проверка гейта — `check-journal-planner.mjs`. `DB_VERSION` = 6.

## 2026-09-23 — Журнал 0.10.0: защита записей (J8)

Явно защищённый текст Журнала хранится только зашифрованным: проект —
название и описание, задача, запись посещения и пункт переноса — текст.
Парольная фраза → PBKDF2-SHA256 (600 000, соль 16 байт) → KEK →
AES-256-GCM-обёртка случайного DEK; записи — AES-256-GCM, новый iv на каждое
шифрование, AAD с id записи. В базе, связях, `journalMeta`, копиях и
предохранительном снимке — только шифротекст (`sec`) и крипто-материал
(`crypto:v1`); фраза, KEK и DEK не сохраняются нигде. Инвариант «`sec` и
открытый текст вместе не хранятся» держит `js/data.js` на каждой записи.
Метаданные (выполнено, срок, архив, перенос) меняются без ключа, `sec` —
байт в байт. Старт и перезагрузка — всегда заблокировано; блокировка —
кнопкой и на `pagehide`. Только парольная фраза: PIN, passkey и таймер в
J8 не входят. Поиск по защищённому тексту — только разблокированным и
только в памяти.

Общий слой: `CWDB.batch()` — атомарный пакет заранее вычисленных операций
по нескольким хранилищам (сейф и первая строка — одной транзакцией).
`shared/backup.js`: четыре хранилища Журнала при восстановлении копии модуля
заменяются одним набором (слияние двух сейфов давало бы нечитаемую смесь),
`communities` по-прежнему сливается; `inspect()` до записи проверяет форму
защищённых данных и полноту набора; исправлен давний дефект `writeDb()` —
синхронный отказ `put()` теперь прерывает транзакцию, а не фиксирует уже
сделанный `clear()`. Хаб различает повреждённую копию (`backup.damaged`) и

Схема не менялась: ни хранилищ, ни индексов, ни подъёма `DB_VERSION`.

**Проект** — строка `journalEntries` с `type:'project'`, только через новый
`CWJournal.projects`. Владелец — район (`nodeId = circuitId`), оба поля и
`type` неизменяемы. Текст пользователя — только `title` (обязателен) и
`body` (пустое описание — поля нет). Цикл: `active ↔ completed`
(`complete/reopen`), любой → `archived` c `archivedAt`; `unarchive`
возвращает прежний статус и физически удаляет `archivedAt` и
`statusBeforeArchive`. Архивный проект — только чтение. Общий фасад
`entries.*` проект не создаёт, не правит, не удаляет
(`journal-project-use-facade`). Удаление — только без связей; каскада нет.

**Связи** — `CWJournal.links` стал доменным фасадом: канонические URN
(`journal:node|entry/<id>`, `cw:<module>/<kind>/<id>`), существование
локального конца, запрет самосвязи и связи двух внешних концов, `rel` из
набора. Строка — только `id/from/to/rel/createdAt`, без подписей и текста
(граница J8). Дубликат не создаётся: повтор возвращает id существующей
строки; id детерминирован от тройки, поэтому и параллельный двойной клик
даёт одну строку. Связь проекта — всегда проект → цель (`covers` для
собрания/группы, `relates` для посещения/записи/задачи, `external` для
`cw:`), только в пределах района. Связь с посещением или его записью
меняется только пока посещение открыто — правило держит слой данных
(`journal-visit-readonly`). Прогресс «N из M», счётчики и история проекта
вычисляются при отрисовке и нигде не хранятся.

**Экран проекта** (эталоны 06-project-m/d): `#districts/<c>/project/<p>` —
описание (строки «## » и «- » показываются заголовком и списком, хранится

«Завершить / В архив». Точки входа: секция «Проекты района» на экране
района, блок в Обзоре (стал реальным), «Связанные проекты района» на
экране собрания, поиск. Кнопка «Связать» в редакторе посещения
активирована: выбор проектов района для сохранённой записи, отметка
