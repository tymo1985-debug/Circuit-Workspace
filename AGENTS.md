## Что это

Circuit Workspace — PWA-хаб, объединяющий инструменты для организации
районного служения под одним интерфейсом и общим слоем данных. Стартовый
экран (`index.html`) показывает плитки модулей; клик открывает модуль внутри
того же приложения.

Модули хаба:
- **Конгрессы** (`congress-project/`) — планирование программ конгрессов,
  генерация писем участникам.
- **Клиндарий** (`circuit-planner/`) — календарь посещений собраний,
  заполнение форм S-302, генерация писем.
- **Школа пионеров** (`pioneer-school/`) — управление школой пионерского
  служения (студенты, расписание уроков, формуляры, экспорт).

Четвёртый модуль, «Формуляр посещения», **сознательно исключён** — его
функционал полностью поглощён Клиндарием (более новая и полная реализация).
Отдельная интеграция не требуется и не планируется.

## ⚠️ Единственный источник правды

Монорепо: **`https://github.com/tymo1985-debug/Circuit-Workspace.git`**

Отдельные репозитории модулей (`Assembly-Programm-`, `Circuit-Planner`,
`Pioneer-School-Workspace`) могут быть устаревшими относительно монорепо.
Они годятся **только** как источник новой логики/фичи конкретного модуля,
но никогда не как основа итоговых файлов — иначе есть риск откатить
хабовые интеграции (nav.js, MD3-стили, version.js) более старой версией.

**Перед КАЖДОЙ подготовкой файлов на скачивание:**
1. Свежий `git clone --depth 1` монорепо — использовать как базу.
2. Если правка бралась из отдельного репо модуля — сверить построчным диффом,
   что в итоговый файл попала только реальная новая логика, а не откат стилей/путей.
3. Перед выдачей архива проверить: (а) пути относительно корня монорепо;
   (б) CSS/стили монорепо не откачены версией из отдельного репо;
   (в) хабовые интеграции (`shared/*`, favicon, theme-color, `shared/nav.js`)
   сохранены во всех изменённых файлах.
4. При работе с одним модулем — всё равно подтянуть и проверить `index.html`
   хаба и его интеграции (`shared/nav.js`, `shared/style.css`,
   `shared/version.js`), чтобы модуль и хаб не разошлись.
5. Если сессия длинная — реклонировать перед самой сборкой архива, а не только
   в начале ответа (апстрим мог измениться, пока писался ответ).

## Стек

Vanilla HTML/CSS/JS, без фреймворков и сборки (кроме точечного использования
esbuild/npm-скриптов при генерации ассетов, см. «Наработанные приёмы»).
IndexedDB как целевой общий слой данных (`shared/db.js`), localStorage —
легаси-хранилище внутри модулей. Хостинг — GitHub Pages, офлайн — Service
Workers. PDF — jsPDF + jspdf-autotable. Много языков: RU/UK/EN/PL (+DE в
части контекстов).

## Версии и версионирование (правило, не текущий снимок)

`shared/version.js` — единственный источник версий на стороне хаба:
- `CW_VERSION` — версия оболочки хаба (в шапке + имя кэша SW).
- `CW_MODULES` — версии модулей для плиток; в разметке `index.html` номеров
  версий нет вообще.

**Чек-лист выпуска модуля:** поднять версию внутри модуля →
(`congress-project/service-worker.js: APP_VERSION`,
`circuit-planner/app.js: App.config.version`,
`pioneer-school/js/app.js` + `sw.js: APP_VERSION`) → обновить то же значение
в `CW_MODULES` → поднять `CW_VERSION`.

Версия каждого модуля должна быть видна в интерфейсе (топбар).

Текущие версии — смотреть в `shared/version.js` актуального клона, не полагаться
на память: на момент последней проверки хаб был v0.7.6, Конгрессы v4.19.0,
Клиндарий v9.60.0, Школа пионеров v1.6.0 — но это снимок на дату проверки,
не факт на будущее.

- `shared/db.js` (IndexedDB: communities/people/meetings/roles) **существует**,
  но реально используется пока только хабовым `index.html` — ни один модуль
  ещё не переведён на него. Congress Project и Клиндарий по-прежнему хранят
  данные в собственном localStorage под собственными ключами.
- MD3-визуальный слой — **внедрён** во всех трёх модулях и в хабе, слит с
  фирменной палитрой `--cw-*` (сид-цвет `#6a45c9`), все исходные имена
  переменных/классов сохранены.
- PIN-защита Клиндария (`localStorage['syp-pin-hash']`) — всё ещё существует
  как отдельный слой модуля, архитектурное решение (оставить рядом с единым
  входом хаба или заменить им) **не принято**.
- Локализация: общий слой (`shared/i18n.js` + `shared/i18n/common.js`)
  **внедрён в хабе и в Клиндарии**. Клиндарий подключён через мост
  `App.i18nBridge` (см. ниже) — свой язык он по-прежнему хранит в
  `app.settings.language`, мост лишь синхронизирует его с `cw-lang`.
  Конгрессы (v4.19.0, 244 ключа) и Школа пионеров (v1.6.0, 317 ключей)
  подключены полностью: 5 языков, свой переключатель языка в шапке.
  **Интерфейс переведён везде; документы — нигде** (см. открытые задачи).

## Локализация (общий слой)

Разрешение языка, по убыванию приоритета:

1. `localStorage['cw-lang:<module>']` — локальный выбор внутри модуля.
   Пишется ТОЛЬКО когда пользователь сам сменил язык в этом модуле.
2. `localStorage['cw-lang']` — язык, выбранный в хабе.
3. `navigator.language` → 4. `'ru'`.

Отсюда наследование: нет ключа модуля — модуль идёт за хабом; есть —
живёт своим языком; `CWI18n.resetToHub()` удаляет ключ и возвращает
наследование.

Языки экосистемы: **ru / uk / en / pl / de** (список — `LANGS` в
`shared/i18n.js`). Добавление языка = строка в `LANGS` + переводы;
логика не меняется.

Где что лежит: строка, нужная больше чем одному месту (названия модулей,
«Сохранить», статусы) → `shared/i18n/common.js`; специфика модуля →
`<module>/i18n/dict.js`. Название модуля существует ровно в одном ключе
`module.<id>.title` — и для плитки хаба, и для шапки модуля. Поле `title`
в `CW_MODULES` (`shared/version.js`) — только запасной вариант, не источник.

Разметка переводится атрибутами `data-i18n`, `data-i18n-title`,
`data-i18n-aria-label`, `data-i18n-placeholder`; `innerHTML` намеренно не
поддерживается (перевод не должен уметь вставлять разметку). Динамические
экраны подписываются через `CWI18n.onChange(fn)`.

Подключение модуля (фазы 2–4):
```html
<script src="../shared/i18n.js"></script>
<script src="../shared/i18n/common.js"></script>
<script src="i18n/dict.js"></script>
...
CWI18n.init({ module: 'congress-project' });
```
Скрипты локализации подключать в `<head>` (как в хабе), иначе при
неруском языке на кадр мелькает русская разметка. В Клиндарии это
обязательно ещё и потому, что `app.js` идёт с `defer` — мост должен
застать `CWI18n` уже готовым.

### Мост Клиндария (`App.i18nBridge`, образец для остальных модулей)

Модуль с уже существующим механизмом языка не переписывается под общий
слой — к нему добавляется мост. Ключевое решение: отличить «пользователь
осознанно выбрал русский» от «русский стоял по умолчанию» в старых данных
невозможно, поэтому при первом запуске после обновления существующая
установка **засеивает** свой текущий язык в `cw-lang:circuit-planner`.
Пользователь не видит вообще никаких изменений; наследование включается
только для новых установок и по явному выбору «Как в Circuit Workspace»
(значение `__hub` в селекте языка).

«Была ли установка новой» определяется по `App.store.lastWrittenPayload`
сразу после `store.load()` — отсюда и место вызова `adopt()` в `init()`.

Немецкого интерфейса у Клиндария нет (словари `I18N` — ru/uk/en/pl),
поэтому язык хаба `de` отображается на ближайший доступный `en`
(`NEAREST` в мосте). Появятся немецкие словари — добавить `'de'` в
`SUPPORTED`, больше ничего.

Мост вызывает `CWI18n.init({ module, apply: false })`: разметка модуля
пока без `data-i18n`, перевод делает собственный `renderAll()`, от общего
слоя нужно только разрешение языка.

### Конгрессы (полное подключение, образец для Школы пионеров)

Модуль без собственного механизма языка подключается иначе, чем Клиндарий:
никакого засева, язык целиком живёт на общем слое (`cw-lang:congress-project`
→ `cw-lang`). В данных модуля язык интерфейса не хранится намеренно — он не
часть программы конгресса и не должен попадать в экспорт и резервные копии.

Границы, которые НЕЛЬЗЯ размывать (описаны и в шапке `i18n/dict.js`):
- **Язык интерфейса ≠ язык писем.** Письма берут язык из `settings.language`
  (uk/ru/de) в настройках письма. Секретарь может работать в польском
  интерфейсе и рассылать украинские письма — это нормальный рабочий случай.
- **Шапки печатного плана не переводятся** («Час», «Ведучий / Промовець»,
  «Підтв.»). Это готовый документ, который уже раздают людям; менять его
  язык вместе с языком интерфейса нельзя.
- **Статусы заданий — данные.** В хранилище они остаются русскими строками
  (`STATUSES` в `state.js`), у `<option>` добавлен `value` с каноническим
  значением, переводится только подпись (`tStatus()` в `js/i18n.js`).
  Незнакомое значение показывается как есть — пользователь мог завести своё.
  Справочники (собрания, докладчики, типы/виды) не переводятся по той же причине.

Технические детали, о которые легко споткнуться:
- В `render.js` и `tasks.js` переменная задачи называется `t` и перекрывает
  импорт `t()` — там перевод зовётся через псевдоним `tr_`.
- `initI18n(render)` вызывается ДО `load()`: `load()` внутри вызывает
  `render()`, и язык должен быть известен раньше первой отрисовки.
- Обращение к глобали пишется как `self.CWI18n?.…`: голое `CWI18n?.…`
  бросает ReferenceError, если общий слой не подключён.
- Номер версии убран из разметки — берётся из `CW_MODULES` (`#moduleVersion`),
  как в хабе.

### Школа пионеров (v1.6.0)

Модуль на обычных глобальных скриптах, поэтому перевод — глобальная функция
`T(key, vars)` из `js/i18n.js` (короткое имя намеренно: в `app.js` оно
встречается сотни раз). Скрипты локализации подключаются ДО модулей: `T()`
зовут уже на этапе объявления констант (`DEFAULT_COLUMNS` и т.п.).
`PSI18n.init(rerender)` поднимается до первого `showRoute()`, перерисовку
при смене языка делает тот же `showRoute`.

**Подписи столбцов учащихся — самое хрупкое место.** Столбцы лежат в
IndexedDB (`studentColumns`), у эталонных есть `labelKey`. Приоритет задан
в `Students.label()`: переименовал пользователь (`renamed: true`) — его текст
показывается как есть и переводом не затирается НИКОГДА; не переименовывал —
подпись берётся по `labelKey`. `migrateColumnLabels()` проставляет `labelKey`
существующим установкам по совпадению с эталонной подписью; не совпало —
столбец помечается `renamed` и остаётся неприкосновенным. Дубль этой логики
в `js/i18n.js` был удалён: у него приоритет был обратный, перевод не
применился бы вообще.

**Значения в базе не переводятся**: ключи опций (`yes`, `listed`, `braille`)
остаются как есть, переводятся только подписи (`labelKey` у опций).

Справочные требования (гл.1 п.5, гл.2) в `anketa.js` сделаны ГЕТТЕРАМИ, а не
массивами: массив вычислился бы один раз при загрузке скрипта и остался бы на
языке, который был при старте.

### Клиндарий на общих слоях (sender + doclang)

С v9.60.0 модуль больше не хранит данные отправителя у себя: имя, адрес,
телефон и почта живут в `shared/sender.js` (`localStorage['cw-sender']`).
При первой загрузке после обновления `App.shared.adopt()` переносит прежние
`settings.senderName/Address/Phone/Email` в общий слой через `CWSender.adopt()`
(запишет только если общая запись пуста — порядок открытия модулей не важен)
и удаляет свои копии. Поля настроек читают и пишут общий слой, подписка
`CWSender.onChange` перерисовывает настройки, если данные поменяли в соседнем
модуле.

Язык документа: `CWDocLang.init({ module: 'circuit-planner', langs: ['uk','ru','en','pl','de'] })`,
и прежнее поведение засеивается через `CWDocLang.adopt(settings.language)` —
раньше формуляр и письмо шли за языком интерфейса, теперь это независимая
настройка. Фолбэк формуляра визита: `event.formLanguage || CWDocLang.get()`.
Словарей формуляра (`VP_I18N_DICTS`) всего два — ru/uk; остальные языки
visit-pdf сводит к ru сам, поэтому расширенный список `langs` безопасен.

Проверено сценарием: существующая установка с `senderName`/`language: uk` →
данные переехали, копия в модуле удалена, язык документа стал `uk`, смена
языка интерфейса на `pl` язык документа не двигает.

## Рабочий процесс с файлами (правило Алекса, обязательное)

1. Алекс описывает задачу.
2. Claude называет конкретные файлы, нужные для анализа/правки.
3. Алекс присылает эти файлы или ссылку на репозиторий/коммит.
4. Claude возвращает **только** изменённые/новые файлы:
   - один файл изменён → отдать отдельно;
   - несколько файлов → ZIP только с ними, относительные пути сохранены,
     ничего лишнего/нетронутого внутрь не класть.
5. Изменения предлагаются, разбираются и подтверждаются Алексом **до**
   выгрузки архива — архив не готовится заранее «на всякий случай».
6. Полный ре-зип всего репозитория — только по явному прямому запросу на
   полный экспорт/аудит, никогда по умолчанию.
7. Автономное исполнение всех фаз без остановки — только когда Алекс
   явно об этом просит («выполни все фазы без остановки», «Weiter» после
   явного запроса на автономность и т.п.).
8. Деплой: распаковать ZIP → drag&drop файлов в репозиторий на GitHub →
   commit → GitHub Actions деплоит за 20–40 сек.

## Известные технические ловушки

- **jsPDF + кириллица в AcroForm combo box**: список опций выпадающего
  списка в PDF ломает кириллицу через побайтовое усечение `charCode % 256`.
  Обход — использовать обычные текстовые заполняемые поля вместо combo box
  для любого кириллического контента (актуально и для `s302-form.js`
  Клиндария, и для бывшего Формуляра посещения).
- **Интерактивные PDF-формы с кириллицей — только через pdf-lib, не jsPDF.**
  Причина: у поля есть ссылка на шрифт по имени, но само имя должно быть
  объявлено в словаре `/DR` самой AcroForm. Без `/DR` просмотрщик не знает,
  чем рисовать текст, который ВВОДИТ пользователь (содержимое, заданное при
  создании, при этом рисуется нормально — отсюда ложное впечатление, что всё
  работает). У jsPDF задать `/DR` нельзя; у pdf-lib — можно:
  `acroForm.dict.set(PDFName.of('DR'), ...)` + `/DA` + `NeedAppearances`.
  Реализация: `pioneer-school/js/export/pdfFormExport.js` (`_finalizeForm`).
  Второй обязательный нюанс: шрифт встраивать с `subset: false` — иначе
  pdf-lib подрежет его под уже использованные символы, и пионер не сможет
  напечатать буквы, которых не было в шаблоне.
- **Урезанный шрифт молча обрезает строку.** Если в текст попадает символ вне
  подмножества шрифта (напр. «·» U+00B7), jsPDF обрывает весь вызов `text()`
  начиная с этого символа — без ошибки и без предупреждения. В
  `pioneer-school/js/export/pdfExport.js` от этого страхует `_sanitizeForFont()`.
- **Возврат в хаб — только через `shared/nav.js`, не через `history.back()`.**
  Школа пионеров пишет маршруты в `location.hash`, поэтому `history.back()`
  из модуля уводит на предыдущий экран модуля, а не в хаб. Кнопка возврата —
  обычная ссылка на `index.html`; ощущение «вернулся туда, где был» даёт сам
  хаб: `index.html` сохраняет `window.scrollY` в `sessionStorage['cw-hub-scroll']`
  на `pagehide`/`visibilitychange` и восстанавливает при загрузке
  (`history.scrollRestoration = 'manual'`, иначе браузер и скрипт конфликтуют).
- **Слот кнопки возврата ищется по селекторам, порядок важен.** `shared/nav.js`
  перебирает `.topbar .topbar-title-row` (Клиндарий) → `header.topbar`
  (Конгрессы) → `.topbar` → `.sidebar .brand` (ШПС) и вставляет `.cw-home-btn`
  в первый найденный. Не нашёл ничего — откатывается к прежнему FAB
  `.cw-home-fab` (оставлен в `style.css` намеренно, не удалять). Новый модуль
  с нестандартной шапкой задаёт слот сам: `window.CW_HOME_SLOT` +
  `window.CW_HOME_SLOT_MODE` ('prepend' | 'before'). Разметку модулей при этом
  править не нужно — подключения `<script src="../shared/nav.js" defer>` достаточно.
- **localStorage-ключ Клиндария** `service-year-planner-v9-4-2` — менять
  нельзя категорически, риск потери данных пользователей.
- **CSS календаря в Клиндарии**: инжектируемый блок
  `<style id="calendarViewStyles">` (создаётся в `ensureCalendarViewStyles()`)
  использует `!important` везде и перекрывает базовые правила — любая правка
  CSS календаря должна идти именно в этот блок. `--topbar-h` и
  `--calendar-side-top` меряются из живого DOM через JS, не хардкодить.
- **PDF-колонки формы посещения**: разбиение 70/30 для «С кем» / «Вид
  служения».
- **Иконка хаба завязана на MD3-палитру**: средний стоп градиента в
  `shared/brand/icon-source.svg` (`bgGrad`, 45% — `#6a45c9`) является
  seed-цветом всей MD3-палитры `shared/style.css` (это прямо написано в
  шапке файла стилей). Менять цвет иконки хаба нельзя, не пересчитав
  палитру, — иначе логотип и токены разъедутся.
- **Иконки модулей — единая геометрия, разный фон**: у всех иконок общий
  каркас (viewBox 680, квадрат x/y=20 w/h=640, `rx=150`, тот же стеклянный
  слой и блик `M 20 60 Q 20 20 60 20 …`), различается только градиент фона и
  центральный символ. Исходники — `shared/brand/<module>-icon-source.svg`.
- **Мелкие размеры рисуются отдельным символом**: у 16/32 px свой
  упрощённый вариант символа (толще штрихи, меньше деталей) — простое
  уменьшение детального SVG замыливается в кашу.
- **maskable-иконка ≠ обычная**: для `purpose: maskable` нужен отдельный
  файл без скруглений и без прозрачных углов, символ ужат до ~72% (safe
  zone). Раньше `circuit-planner/manifest.webmanifest` указывал
  `purpose: "any maskable"` на обычную скруглённую иконку — Android обрезал
  бы её повторно; исправлено на отдельный `icons/icon-maskable-512.png`.
- **Замена иконок требует инвалидации кэша SW**: Конгрессы и Школа кэшируют
  по `APP_VERSION` — без поднятия версии вернувшийся пользователь увидит
  старую иконку. У Клиндария `CACHE_STATIC` без версии, но SW фоново
  ревалидирует статику (комментарий в `sw.js`), поэтому там бампа не нужно.
- **Цветовые темы Клиндария**: у модуля есть встроенный color-picker акцента;
  существующий выбор цвета пользователя никогда не перезаписывать — менять
  можно только дефолт для новых пользователей.
- **Клиндарий локализован полностью (фаза 5 закрыта, v9.59.0).** Словарь
  переехал из `app.js` (объект `I18N`, ~39 КБ) в `circuit-planner/i18n/dict.js`
  под префиксом `cp.`; ключи вызовов не менялись — префикс подставляет сама
  `App.utils.t()`. Разметка размечена атрибутами `data-i18n` (249 ключей),
  статический перевод делает `CWI18n.apply(document, App.utils.lang())` из
  `localizeStaticTexts()`. Язык передаётся явно: у модуля свой (мост держит
  его в согласии с хабом), и `de` отображается на ближайший доступный.
  Все три позиционные заплатки убраны: `themeSelect.options[0..1]`,
  `exportModal [data-export-type] strong/span[0..1]` и поиск абзаца через
  `textContent.includes('PDF')`.
  Немецкого у модуля по-прежнему нет: словарь на ru/uk/en/pl. Чтобы включить
  `de`, нужно перевести ~500 ключей `cp.*` и убрать `de` из `NEAREST` в мосте.
  Не переводятся намеренно: названия событий по умолчанию и расписания
  («Серединное собрание», «Ср 19:00») — это данные; шаблоны писем — документ;
  примеры в таблице плейсхолдеров; эндонимы языков.
- **⚠️ Разметку Клиндария нельзя патчить наивным поиском `>ТЕКСТ<`.**
  Один такой проход уже испортил `index.html`: получились теги вида
  `<label class="small<label data-i18n=…` и 78 паразитных
  `<span data-i18n="cp.event_templates"></span>` — файл пришлось откатывать
  к апстриму. Правильный алгоритм (проверен на Конгрессах): ОДИН проход по
  исходной строке, для каждого вхождения смотреть открывающий тег перед ним
  и то, закрывается ли элемент сразу после текста; если да — вешать атрибут
  на сам тег, если нет — оборачивать в `<span>`; повторно обработанные
  вхождения не трогать. После прогона проверять `<[a-z]+[^<>]*<[a-z]` — таких
  совпадений должно быть ноль. И ещё две ловушки, на которых этот проход
  спотыкался: (1) в словаре есть ключ с ПУСТЫМ значением (`cp.event_templates`) —
  если не отфильтровать пустые строки, альтернация матчит каждое `><` и
  засыпает документ пустыми `<span>`; (2) атрибут можно вешать на тег только
  если сам тег ещё не попал в вывод (`open_start >= pos`), иначе срез уходит
  в минус и рвёт разметку.
- **`letterLanguage` в Конгрессах — это язык ПИСЬМА, не интерфейса.**
  Интерфейс Конгрессов локализован отдельно (фаза 3), и эти две настройки
  живут в разных местах намеренно: секретарь может работать в польском
  интерфейсе и рассылать украинские письма. Не путать их при планировании.
- **DEFAULT_TEMPLATES писем Конгрессов**: шаблоны для `ru` и `de` были
  байт-в-байт идентичны украинскому `uk` — переключатель языка механически
  работает, но реального перевода для этих языков нет; не считать это
  автоматически исправленным без проверки.

## Наработанные приёмы (использовать не изобретая заново)

- **Проверка на посторонние правки перед сборкой**: свежий `git clone`,
  затем `diff -rq` рабочей копии против апстрима — выявляет, что реально
  изменилось, до паковки архива.
- **Playwright для визуальных багов**: реальный headless Chromium ловит
  баги, которые не видны при чтении кода (неверные формулы масштабирования,
  двойной скролл и т.п.). Рендерить через `file:///` с `--no-sandbox`
  (bash-сессии изолированы, локальный HTTP-сервер не поднять);
  `wait_until="domcontentloaded"`, `timeout=6000`; для Клиндария —
  `page.on('dialog', lambda d: d.dismiss())` (на первой загрузке всплывает
  `confirm()`). Если сеть блокирует скачивание Chromium — явно фиксировать
  ограничение «только статическая верификация», не выдавать её за полную.
- **Точная замена CSS-классов**: наивный `sed` ломает омонимичные классы
  (`icon-btn`, `modal-card`, `cal-empty` и т.п.). Использовать Python с
  `re.compile(r'class=(["\'])((?:(?!\1|\$\{).)*)\1')` для точного совпадения
  по всему значению атрибута `class="..."`.
- **AST-инструменты для безопасных правок JS**: acorn/acorn-walk для
  построения графа импортов/экспортов и валидации после рефакторинга;
  jsdom — для smoke-тестов без браузера.
- **Множественная замена по файлу**: загрузить файл целиком, пройтись по
  списку кортежей `(old, new)`, отслеживать, какие не нашлись, записывать
  обратно только если все замены прошли успешно.
- **npm ESM в Node**: `@material/material-color-utilities` и подобные
  extensionless-ESM пакеты нужно предварительно бандлить —
  `esbuild --bundle --platform=node --format=cjs` — иначе Node не резолвит
  импорты.
- **Субсеттинг шрифтов**: `pyftsubset` (fonttools) по unicode-кодпоинтам —
  Material Symbols ужимается с ~3.9МБ до ~18КБ.
- **Дисциплина диффов**: `git status --short` перед паковкой — подтвердить,
  какие файлы реально изменились, прежде чем класть их в архив.
- **Тестовые PDF для отладки импорта**: ReportLab для генерации управляемых
  тестовых PDF, воспроизведение реального пайплайна (та же версия pdfjs-dist,
  что и в приложении) вместо рассуждений по коду вслепую.

## Стиль общения и рабочий режим Алекса

- Пишет кратко, часто императивами («Давай», «Соединяй», «перейти к...»),
  иногда по-немецки («Weiter» = «продолжай»); ожидает, что Claude сам
  спланирует, предупредит о рисках и исполнит.
- Визуальные редизайны — сначала интерактивный мокап/превью, только потом код.
- Ловит несоответствия сам и просит закрепить их как постоянное правило —
  такие правила фиксировать здесь и в `memory_user_edits`, а не только
  проговаривать в чате.
- Подтверждение перед архивами — по умолчанию обязательно; полная
  автономность — только по явному запросу, и то не отменяет базовые правила
  файлового обмена (раздел выше).
