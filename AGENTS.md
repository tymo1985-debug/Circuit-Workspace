## Что это

Circuit Workspace — PWA-хаб, объединяющий инструменты для организации районного
служения под одним интерфейсом и общим слоем данных. Стартовый экран
(`index.html`) показывает плитки модулей; клик открывает модуль внутри того же
приложения.

- **Документы** (`documents/`) — шаблоны писем; своих данных нет, правит `CWDB.templates`
- **Конгрессы** (`congress-project/`) — программы, письма участникам; 14 ES-модулей
- **Клиндарий** (`circuit-planner/`) — календарь, S-302, письма; монолитный `app.js` (IIFE)
- **Школа пионеров** (`pioneer-school/`) — студенты, расписание, формуляры, экспорт
- **Назначения** (`appointments/`) — письмо о назначении; `window.print()`, PDF не собирается
- **Журнал** (`journal/`) — записи, связи, защищённые записи; IndexedDB `journalNodes/Entries/Links/Meta` (`journal/AGENTS.md`)
- **Архив** (`archive/`) — просмотр конвертов служебных годов и конгрессов; своих данных нет, конверты пишут модули-источники (`archive/AGENTS.md`)

«Формуляр посещения» **сознательно исключён** — поглощён Клиндарием.
Полный текст — `docs/journal/misc.md`.

## Стек

Vanilla HTML/CSS/JS, без фреймворков и сборки. IndexedDB — целевой общий слой
(`shared/db.js`), localStorage — легаси внутри модулей. GitHub Pages, офлайн
через Service Workers. PDF — jsPDF + jspdf-autotable, интерактивные формы —
pdf-lib. Языки RU/UK/EN/PL/DE.

## ⚠️ Единственный источник правды

Монорепо: **`https://github.com/tymo1985-debug/Circuit-Workspace.git`**

Отдельные репозитории модулей (`Assembly-Programm-`, `Circuit-Planner`,
`Pioneer-School-Workspace`) могут быть устаревшими. Годятся **только** как
источник новой логики, никогда как основа итоговых файлов: иначе риск откатить
хабовые интеграции (`nav.js`, MD3-стили, `version.js`) старой версией.

Перед подготовкой файлов — свежий `git clone --depth 1`; при длинной сессии
реклон перед самой сборкой архива.

Сверка модуля с хабом — **не** шаг любой задачи: только когда правка бралась
из отдельного репо модуля. Живёт в `docs/rules/delivery.md`. При обычной
локальной правке хаб не читается — это +156 КБ контекста даром.

## ⚠️ Инвариант общего origin

GitHub Pages: все репозитории `tymo1985-debug` (хаб, Current-Exchange, прочие
PWA) живут на одном origin `tymo1985-debug.github.io`. Общие у них
IndexedDB, localStorage и Cache Storage. Следствия: service worker удаляет

ключей и кэшей получают префикс приложения/модуля; чужой ключ не читается и не
чистится.

## Версии

`shared/version.js` — единственное место объявления: `CW_VERSION` (хаб) и
`CW_MODULES` (модули). В разметке номеров версий нет; версия модуля видна в
топбаре. Цепочка подъёма, исключения Клиндария, патч-бамп при правке
`shared/*` — **`docs/rules/release.md`**, читать только при подъёме версии.

## Статус миграции на общий слой

Не путать «спроектировано» и «внедрено» — проверять кодом. `CWDB`
(`shared/db.js`) используют Клиндарий, Конгрессы, Документы и Журнал; MD3-слой
и локализация (5 языков) внедрены везде. PIN Клиндария — отдельный слой,
решение о слиянии с входом хаба не принято. Подробности — `docs/journal/misc.md`.

## 🎯 AI context budget

**Use the smallest sufficient context.** Цель — не минимум токенов любой ценой,
а **минимальный достаточный контекст без снижения надёжности результата**.
Близнец на выходе: **minimal context / minimal patch / changed files only** —
минимизируется и читаемое на входе, и изменяемое на выходе.
**Local task → local context → local patch.**

1. Сначала определить минимальный набор файлов, нужный задаче. Список
   расширяется по факту находки, а не «на всякий случай».
2. Не читать файл целиком, если хватает функции, секции или диапазона строк.
3. Не открывать без прямой необходимости: `CHANGELOG.md`, `docs/journal/*`,
   архивы Done, generated-файлы, шрифты/base64/binary/data-only, крупные файлы
   других модулей.
4. Не перечитывать уже изученные файлы без причины.
5. Для локальной задачи сначала ограничиваться текущим модулем.
6. `shared/*`, хаб и другие модули — только при реальной зависимости (семь
   признаков ниже).
7. Перед расширением области спросить себя: **«нужен ли этот файл для принятия
   решения или проверки изменения?»** Нет — не читать.
8. Задача решается локальным patch — общий аудит Workspace не проводить.
9. После задачи показывать `Read:` и `Changed:`.
10. Прочитано более **8 исходных файлов** или затронуто более **2 модулей** —
    кратко объяснить, почему это было необходимо.
11. Контекст расширяется неоправданно — остановить и вернуться к минимальному
    достаточному набору.

### Семь признаков выхода за пределы модуля

Общая архитектура · общий слой (`shared/*`) · интеграция между модулями ·
версионирование · release · service worker/cache · общая схема данных.

Вне этих семи хаб, `shared/*` и соседние модули не читаются. **Локализация,
CSS и печать в список не входят** — правка словаря или стилей остаётся внутри
модуля: подгружается профильный журнал, но не чужой код.

## 🛑 Когда останавливаться и спрашивать

По умолчанию Claude принимает технические решения сам и доводит фазы до конца:
**lowest risk first / minimal patch / preserve behavior / one slice per
delivery**. Отдельный план перед каждым шагом не показывается.

Остановка и вопрос нужны в трёх случаях:

1. есть несколько **архитектурно разных** вариантов с заметными последствиями;
2. изменение может затронуть формат или схему данных, миграцию,
   совместимость, backup/restore/export, сохранность пользовательских данных,
   IndexedDB/localStorage, service worker или **observable behavior**;
3. требуется продуктово-функциональное решение, а не технический выбор.

**Критерий — последствия, а не имя файла или блока.** Касание кода, связанного
с бэкапом или хранилищем, само по себе остановки не требует: безопасный
механический рефакторинг без изменения поведения и данных выполняется
автономно. Останавливает риск для данных и поведения, а не близость к ним.

## 🎚 Model / Effort escalation policy

**Start with the lowest sufficient model and effort. Escalate only when
needed.** Близнец бюджета контекста: минимальный контекст, effort, модель и
patch — вместе, без просьбы подтвердить.

### Pre-flight — до начала дорогого шага

Перед существенным анализом, чтением многих файлов, большим patch, сборкой
ZIP или долгими проверками — короткая оценка **до**, а не после:

```
Complexity:         Low / Medium / High
Recommended model:  Haiku 4.5 / Sonnet 5 / Opus 5
Recommended effort: Low / Medium / High / Extra / Max
Thinking:           On / Off
```

Подходит — работать дальше без вопроса. Не подходит — остановиться **до**
дорогой работы:

```
Recommended switch before execution:
Sonnet 5 Medium → Opus 5 High
Reason: изменение затрагивает схему данных и backup/restore.
```

**Evaluate first, execute second.** Можно переключиться самому — переключиться.
Нельзя — сообщить и не начинать анализ, пока режим не станет подходящим.

### Модели

| Модель | Когда |
|---|---|
| **Haiku 4.5** | тексты, переименования, точечные CSS/HTML без логических зависимостей, простой поиск |
| **Sonnet 5** — default | обычные багфиксы, UI/CSS, логика одного модуля, локальный рефакторинг, Phase 3 и подобные контролируемые срезы |
| **Opus 5** | сложная архитектура, тяжёлые cross-module правки, миграции данных, IndexedDB/localStorage со сменой схемы, backup/restore/export, service worker/cache, несколько архитектурных вариантов с серьёзными последствиями |

### Effort

Low (механика, тексты, локальный CSS) → **Medium (default)** → High (сложная
логика, несколько зависимостей) → Extra (редко) → Max (не для обычной
работы). Thinking — не автоматически, а когда риск для данных/сложная
миграция/архитектурный выбор реально требуют рассуждения.

### Лестница эскалации

`Sonnet 5 Medium → High → Extra → Opus 5 Medium/High`. На `Opus 5` сразу не
перескакивать, пока Sonnet 5 не проверен недостаточным. Понадобился один раз —
не становится default: следующая задача снова с `Sonnet 5 + Medium`.

Оценка оказалась неверной — остановиться перед следующим дорогим шагом:
`Escalation needed: Sonnet 5 Medium → Sonnet 5 High` + `Reason: …`
(или `De-escalation recommended: …`).

### Отчёт после задачи

После `Read / Changed / Added / Delete`:

```
Complexity:   Low / Medium / High
Model used:   …
Effort used:  …
Thinking:     On / Off
```



## ❌ Что не читать

Эти файлы — данные, а не код. Читать в них нечего, а стоят они десятки тысяч
токенов: **65 % байт репозитория (7,5 МБ из 11,6)** приходится на них.
Открывать, только если задача прямо про сам файл.

- `shared/vendor/**` — минифицированные библиотеки, 3,8 МБ. Хеши — `sri-lock.json`.
- `**/fonts/**.js` — base64-шрифты (Клиндарий 4 × ~290 КБ, Школа 2 файла).
  Пересобираются `scripts/build-pdf-font-subset.mjs`.
- `circuit-planner/forms/s302-form.js` — 730 КБ, две строки, base64-PDF бланка
  S-302. Дороже, чем весь этот файл целиком.
- `**/icons/*.png`, `icon-*.png`, `apple-touch-icon.png` — растр, 9 наборов:
  изображение занимает контекст целиком, а прочитать из него нечего.
- `*.min.js`, `*.min.css` — сборочный вывод.

**Машинный признак:** строка длиннее 5000 символов, или `window.*_B64 = '`, или
путь в `vendor/`/`fonts/`. Тогда: наличие — `ls`, размер — `wc -c`, строка —
`grep -n` с узким шаблоном. **Правится генератор, а не его вывод.**

**Крупные, но осмысленные файлы — по фрагментам:** `circuit-planner/app.js`
(5466 строк) по диапазону, карта — `circuit-planner/AGENTS.md`;
`circuit-planner/i18n/dict.js` (188 КБ) и `pioneer-school/i18n/dict.js`
(141 КБ) только `grep` по ключу; `shared/style.css` (74 КБ) — по секции.

Список продублирован в `.aiignore`. `.gitignore` при этом НЕ заводится: все
перечисленные файлы обязаны лежать в репозитории — без них нет офлайна.

## Рабочий процесс с файлами (правило Алекса, обязательное)

1. **Репозиторий подключён по умолчанию** (10.10.2026): в начале технической
   задачи Claude сам вызывает `add_repo` (`tymo1985-debug/Circuit-Workspace`,
   `push`) и читает HEAD. Отказ — одна строка Алексу. Отключить доступ можно
   в настройках GitHub-коннектора.
2. **Файлы готовит Claude сам**: только изменённые/новые, пути от корня. По
   ходу ничего не отправляется и не коммитится. Автономное исполнение всех
   фаз — только по явной просьбе.
3. **В конце один вопрос:** «Файлы, ZIP или push в `main`?» До ответа ZIP и
   коммит не делаются. Push рекомендуется; полный ре-зип — по явному запросу.
4. **Push:** `git diff --stat` без лишнего; удаления — `git rm`, в DELIVERY.
   **Файлы/ZIP:** путь назначения к каждому; удаления — строкой `DELETE: path`.
5. **Пост-проверка обязательна:** после ручного залива — сверка файлов
   (drag&drop удаляет отсутствующие в папке: инцидент 06.08.2026); после
   push — HEAD против коммита.

Полный протокол сборки и рецепт пост-проверки — **`docs/rules/delivery.md`**.

## Проверки перед выпуском

Точка входа — `node scripts/check-all.mjs`, а не отдельные скрипты: набор
растёт, и запуск по памяти рано или поздно пропустит нужную проверку.

Коды: `0` — прошло; `1` — провал, выпускать нельзя; `2` — провалов нет, но
часть проверок не выполнена. Двойка намеренно не равна успеху: «не смогли
проверить» ≠ «проверили, всё хорошо».

Зависимости: `npm i jsdom jspdf acorn acorn-walk fake-indexeddb`.
Клон `--depth 1` даёт пропуск проверки патч-бампа — ожидаемо.

Новая проверка заводится по правилу «этот класс багов уже ломался повторно».

**Живой прогон обязателен перед выдачей файлов** (Chromium, `live-run.mjs`,
скриншот 430×900). Правка не касается кода — прогон не нужен, но сказать об
этом прямо, не выдавая статическую проверку за полную.

Для правок update pipeline обязателен отдельный `live-update-pipeline.mjs`:
один Chromium profile, прогретые SW/cache версии A, затем одно действие до
версии B. Успех — только по handshake фактически active-версий всех
модулей; исчезновение `waiting` само по себе не доказывает активацию.

Обоснование каждой проверки и наработанные приёмы — **`docs/journal/gate.md`**.
