# Инструкции для ИИ-ассистентов

Короткий файл. Рабочие правила — в `AGENTS.md` (ядро, читается всегда),
история решений — в `docs/journal/` по темам, устройство приложения — в
`ARCHITECTURE.md`. Здесь только то, как вести проект.

## Перед началом любой задачи

1. Свежий клон монорепо — единственного источника правды.
2. Прочитать `AGENTS.md` — теперь это ядро на ~12 КБ, целиком.
   Профильный журнал из `docs/journal/` — только по теме задачи.
3. Правка внутри одного модуля — прочитать `<модуль>/AGENTS.md`.
4. Назвать минимальный набор файлов, нужный задаче, до того как читать.
   Область расширяется только по семи признакам из «AI context budget».
5. Не предполагать содержимое файлов — открыть и посмотреть. Но не открывать
   то, что перечислено в «❌ Что не читать» и `.aiignore`.

## Главное правило

Не создавать хаос. Документация поддерживается в актуальном состоянии по ходу
разработки, а не отдельным подходом «когда-нибудь потом».

## Работа с идеями и задачами

- Пользователь высказал идею **не по текущей задаче** — не переключаться на её
  реализацию, а записать в `IDEAS.md`. Дубликаты не плодить; похожая идея уже
  есть — объединить.
- Решили реализовать идею — перенести из `IDEAS.md` в `TODO.md`.
- Задача выполнена — отметить, перенести в раздел Done, добавить запись в
  `CHANGELOG.md`. В обоих файлах хранится только текущее: старое уходит в
  `docs/todo-archive/` и `docs/changelog/`.
- Изменение крупное — обновить `ROADMAP.md`.
- Изменилось устройство приложения — обновить `ARCHITECTURE.md`.
- Принято значимое решение или найдена новая ловушка — запись идёт в
  профильный файл `docs/journal/`, а НЕ в `AGENTS.md`. В ядро попадает только
  то, что нужно перед каждой задачей; его размер стережёт
  `scripts/check-context-budget.mjs` (предупреждение 16 КБ, провал 20 КБ).
  Правки — диффом, а не пересозданием файла.

Разделы `TODO.md` фиксированы: Inbox, Next, In Progress, Done. Свои разделы не
заводить. Идеи из `IDEAS.md` без просьбы пользователя не удалять. В
`CHANGELOG.md` писать только реально внесённые изменения, каждая запись — дата
и краткое описание.

## Файловый обмен

Возвращать **только** изменённые и новые файлы: один файл — отдельно,
несколько — ZIP только с ними и с сохранением относительных путей. Полный
ре-зип репозитория — исключительно по явному запросу. К каждому файлу
указывать путь назначения от корня монорепо.

Перед выдачей — отчёт `Read / Changed / Added / Delete`. Удаления в архив не
кладутся: строка `DELETE: path/to/file` в тексте ответа.

Полный протокол сборки архива — `docs/rules/delivery.md`, подъём версий —
`docs/rules/release.md`. Оба читаются только тогда, когда до них дошло дело.

## Инженерная позиция

Думать как senior software architect: предлагать улучшения, сообщать об
архитектурных проблемах, предлагать упрощение кода и рефакторинг повторов.
Но **архитектуру не менять без подтверждения пользователя** — сначала
предложение с рисками, потом реализация.

## Token / Chat discipline (постоянное правило)

Чат — не журнал проекта. Состояние хранится в репозитории: `git status/diff/
HEAD`, `CHANGELOG.md`, `TODO.md`, `ARCHITECTURE.md`, `AGENTS.md`,
`docs/journal/*`.

- При лимите, переходе в новый чат или незавершённой фазе — только компактный
  HANDOFF, максимум 10–15 коротких строк, без списка изменённых файлов,
  команд, успешных проверок, промежуточных рассуждений и того, что уже
  записано в проектных файлах.
- Формат:
  ```
  HANDOFF
  HEAD: ...
  VERSIONS: ...
  GATE: ...
  DONE: ...
  PENDING: ...
  STOP POINT: ...
  ```
  Ненужные строки пропускать.
- В новом чате HANDOFF не пересказывать пользователю — сразу продолжать со
  STOP POINT.
- Во время работы — без progress report после каждого шага. Сообщать только
  при важном риске, неожиданном падении проверки, необходимости решения
  пользователя, завершении задачи или окончании доступного контекста.
  Обычные технические действия — молча.
- Не читать весь `AGENTS.md`, если нужное правило определяется через
  индекс/секцию/профильный `docs/journal/*`.

**Chat output must be concise by default. Project state belongs in the
repository, not in conversation summaries.**
