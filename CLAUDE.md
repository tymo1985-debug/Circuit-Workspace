# Инструкции для ИИ-ассистентов

Короткий файл. Рабочие правила, ловушки и приёмы — в `AGENTS.md`, устройство
приложения — в `ARCHITECTURE.md`. Здесь только то, как вести проект.

## Перед началом любой задачи

1. Свежий клон монорепо — единственного источника правды.
2. Прочитать `AGENTS.md` — разделы «Рабочий режим» и «❌ Что не читать»
   обязательны. Профильные разделы открывать по мере надобности, а не
   подряд: файл большой, и до фазы 2 аудита контекста таким и останется.
3. Назвать минимальный набор файлов, нужный задаче, до того как читать.
   Область чтения расширяется только по семи признакам из «Рабочего режима».
4. Не предполагать содержимое файлов — открыть и посмотреть. Но не открывать
   то, что перечислено в «❌ Что не читать» и `.aiignore`.

## Главное правило

Не создавать хаос. Документация поддерживается в актуальном состоянии по ходу
разработки, а не отдельным подходом «когда-нибудь потом».

## Работа с идеями и задачами

- Пользователь высказал идею **не по текущей задаче** — не переключаться на её
  реализацию, а записать в `IDEAS.md`. Дубликаты не плодить; похожая идея уже
  есть — объединить.
- Решили реализовать идею — перенести из `IDEAS.md` в `TODO.md`.
- Задача выполнена — отметить, перенести в раздел Done, добавить запись в
  `CHANGELOG.md`.
- Изменение крупное — обновить `ROADMAP.md`.
- Изменилось устройство приложения — обновить `ARCHITECTURE.md`.
- Принято значимое решение или найдена новая ловушка — обновить `AGENTS.md`
  диффом, а не пересозданием файла.

Разделы `TODO.md` фиксированы: Inbox, Next, In Progress, Done. Свои разделы не
заводить. Идеи из `IDEAS.md` без просьбы пользователя не удалять. В
`CHANGELOG.md` писать только реально внесённые изменения, каждая запись — дата
и краткое описание.

## Файловый обмен

Возвращать **только** изменённые и новые файлы: один файл — отдельно,
несколько — ZIP только с ними и с сохранением относительных путей. Полный
ре-зип репозитория — исключительно по явному запросу. К каждому файлу
указывать путь назначения от корня монорепо.

Перед выдачей — отчёт `Read / Changed / Added / Delete`. Удаления в архив не
кладутся: строка `DELETE: path/to/file` в тексте ответа.

Полный протокол сборки архива — `docs/rules/delivery.md`, подъём версий —
`docs/rules/release.md`. Оба читаются только тогда, когда до них дошло дело.

## Инженерная позиция

Думать как senior software architect: предлагать улучшения, сообщать об
архитектурных проблемах, предлагать упрощение кода и рефакторинг повторов.
Но **архитектуру не менять без подтверждения пользователя** — сначала
предложение с рисками, потом реализация.
