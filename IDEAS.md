## Интерфейс

- **Пустой год в сетке недель (Клиндарий) — слишком много кнопок «+».**
  Когда в году ещё нет событий (например, следующий служебный год), каждая
  пустая ячейка дня показывает кнопку добавления — на весь год это десятки
  одинаковых «+» подряд, визуально шумно. Разобрать варианты: показывать «+»
  только по hover/tap на ячейку (как задумано для десктопа — см. правило
  `.day-cell:hover .day-add-btn`), а не всегда видимой; либо более лёгкий
  визуальный вес кнопки в пустых неделях.

## Функции

- **Раздел «Маршрут посещений» в Клиндарии** (подпись в UI: «Визуализация
  текущего календаря») — read-only представление уже составленного
  календаря с необязательным вторым уровнем — анализом и моделированием.
  Данные читаются через `CWPlanner`/`CWDirectory` (координаты собраний уже
  есть — схему `shared/db.js` менять не нужно, блокер снят R0-разбором).

  Согласованные фазы:
  - **R1 — только просмотр.** Новый пункт меню, список реально
    запланированных недель в календарном порядке. Никакого редактирования.
  - **R2 — карта.** Нумерованные точки + линия по текущему календарному
    порядку (прямые линии как временное приближение).
  - **R3 — реальные автомобильные расстояния/время.** Routing-провайдер
    поверх линий из R2, без изменения UI.
  - **R4 — ручной черновик порядка.** Кнопка «Изменить порядок» →
    drag-and-drop/↑↓ → ничего не пишется в календарь. Черновой порядок и
    session-only locks (🔒 на время сессии, не постоянное поле записи) —
    **в `sessionStorage`** (решено).
  - **R5 — Compare.** Текущий ↔ Мой вариант.
  - **R6 — Optimized.** Алгоритмическое предложение порядка.
  - **R7 — Apply to Calendar.** Черновик пишется в реальный календарь
    только по явному подтверждению.
  - **R8 — mobile polishing.** [Список]/[Карта] вместо колонок.

## Архитектура

- **Продуктовый принцип (согласовано):** Calendar остаётся единственным
  местом, где пользователь первоначально планирует район. «Маршрут
  посещений» — вторичное, по умолчанию read-only представление уже
  составленного календаря; редактирование порядка — необязательный второй
  этап, доступный только через явное действие, и не меняет календарь без
  явного `Apply`. Постоянное поле блокировки записи (`entry.routeLocked`
  и т. п.) сознательно не вводится на первом этапе — блокировка живёт
  только как свойство черновика сессии (см. R4 выше).
