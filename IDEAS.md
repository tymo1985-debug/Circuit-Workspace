## Интерфейс

- **Пустой год в сетке недель (Клиндарий) — слишком много кнопок «+».**
  Когда в году ещё нет событий (например, следующий служебный год), каждая
  пустая ячейка дня показывает кнопку добавления — на весь год это десятки
  одинаковых «+» подряд, визуально шумно. Разобрать варианты: показывать «+»
  только по hover/tap на ячейку (как задумано для десктопа — см. правило
  `.day-cell:hover .day-add-btn`), а не всегда видимой; либо более лёгкий
  визуальный вес кнопки в пустых неделях.

## Функции

- **Маршрут: дом по датам (смена района).** Сейчас дом — один адрес из
  настроек; движок R10 берёт его через одну функцию `home()`. При переезде
  или смене района прошлые полугодия пересчитаются от нового дома. Если
  понадобится — периоды «дом с даты» в настройках, `home()` выбирает по
  дате слота. Схема настроек меняется — отдельное решение.
- **Маршрут: исключение на одной записи календаря.** Сейчас «где я» и
  «после события» задаются на шаблоне события (`event.route`), а отдельный
  перерыв — ручным выбором по его периоду. Если понадобится, что один
  конкретный конгресс ведёт себя иначе, чем шаблон, — то же поле `route`
  на записи календаря (`entry.route`), с приоритетом над шаблоном. Схема
  записей меняется — отдельное решение.

- **Журнал: пункт «на следующее посещение» без посещения.** Кнопка
  «Добавить на следующее посещение» прямо в карточке собрания/группы, когда
  мысль пришла между визитами. Сейчас пункт переноса — всегда запись
  посещения (`fields.visitId` = источник), поэтому нужен либо пункт узла
  без посещения, либо черновое «следующее» посещение. Модель данных
  меняется — отдельное решение (22.10.2026).

## Архитектура

- **Разделить реестр версий (аудит 04, вариант C).** Worker модуля не должен
  зависеть от версии хаба: каждый модуль подключает только свой файл версии,
  версия хаба уходит из имён кэшей, бамп модуля — только при изменении его
  файлов. Выпуск переустанавливал бы один worker, а не восемь. Меняется
  контракт обновления (`CW_MODULES`, рукопожатие, `release-manifest.js`,
  оркестрация) — отдельным разбором. Вернуться, если время установки станет
  заметным: после `precache.js` трафик уже минимален.
- **Content-Security-Policy (аудит 03, H-1).** Ни на одной странице нет
  `<meta http-equiv="Content-Security-Policy">` — защита в глубину при импорте
  чужих файлов. Нужен разбор: инлайн-скрипты страниц, Google Maps, вендорные
  библиотеки.
- **Шифрование резервной копии фразой (аудит 03, H-1).** Копия содержит
  имена, телефоны, адреса открытым текстом (кроме защищённых записей Журнала)
  и ездит почтой. Продуктовое решение, не техническое.

- **Продуктовый принцип (согласовано):** Calendar остаётся единственным
  местом, где пользователь первоначально планирует район. «Маршрут
  посещений» — вторичное, по умолчанию read-only представление уже
  составленного календаря; редактирование порядка — необязательный второй
  этап, доступный только через явное действие, и не меняет календарь без
  явного `Apply`. Постоянное поле блокировки записи (`entry.routeLocked`
  и т. п.) сознательно не вводится на первом этапе — блокировка живёт
  только как свойство черновика сессии (см. R4 выше).
