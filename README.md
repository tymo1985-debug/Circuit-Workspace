# Circuit Workspace

PWA-хаб, объединяющий инструменты для организации районного служения под одним
интерфейсом, единым визуальным слоем и общей локализацией. Стартовый экран
(`index.html`) показывает плитки модулей; каждый модуль — самостоятельная папка
со своей версией, своим service worker'ом и своим хранилищем.

**Единственный источник правды — этот репозиторий.** Отдельные репозитории
модулей (`Assembly-Programm-`, `Circuit-Planner`, `Pioneer-School-Workspace`)
могут быть устаревшими: они годятся как источник новой логики конкретного
модуля, но никогда как основа итоговых файлов.

---

## Документация

Вся документация лежит в корне репозитория — подпапок с документами нет.

| Файл | Что внутри | Когда открывать |
|---|---|---|
| `README.md` | Этот файл: обзор, структура, деплой | Первое знакомство с проектом |
| `ARCHITECTURE.md` | Устройство хаба, общий слой, модель данных, границы модулей | Перед изменением `shared/*` или добавлением модуля |
| `AGENTS.md` | Рабочий журнал: правила, известные ловушки, наработанные приёмы | Перед любой задачей по коду |
| `ROADMAP.md` | Что в работе, что в следующем релизе, что в далёких планах | Планирование |
| `TODO.md` | Конкретные задачи: Inbox / Next / In Progress / Done | Ежедневная работа |
| `IDEAS.md` | Идеи без сроков и обязательств | Появилась мысль — записать сюда |
| `CHANGELOG.md` | Что и когда реально изменилось | После выпуска |
| `CLAUDE.md` | Инструкции для ИИ-ассистентов | При работе через Claude |

Короткое правило: **что делать** — в `TODO.md`, **как устроено** — в
`ARCHITECTURE.md`, **обо что не споткнуться** — в `AGENTS.md`.

## Структура репозитория

```
Circuit-Workspace/
├── index.html                 ← хаб: плитки модулей, версии читаются в рантайме
├── manifest.json, service-worker.js, icon-*.png, apple-touch-icon.png
├── shared/                    ← общий слой (меняется осторожно: затрагивает всех)
│   ├── style.css               ← MD3-токены поверх фирменных --cw-* переменных
│   ├── db.js                   ← IndexedDB: communities, people, meetings, roles
│   ├── nav.js                  ← кнопка возврата в хаб для модулей
│   ├── sender.js               ← данные отправителя, общие для всех документов
│   ├── doclang.js              ← язык документа (независим от языка интерфейса)
│   ├── i18n.js                 ← движок локализации (ru/uk/en/pl/de)
│   ├── i18n/common.js          ← общие словари: хаб, статусы, названия модулей
│   ├── version.js              ← CW_VERSION + CW_MODULES
│   ├── fonts/                  ← Roboto + Material Symbols (сабсет), офлайн
│   └── brand/                  ← исходники иконок (SVG)
├── congress-project/          ← Конгрессы (14 ES-модулей, js/main.js — вход)
├── circuit-planner/           ← Клиндарий (монолитный app.js, IIFE)
├── pioneer-school/            ← Школа пионеров
└── appointments/              ← Назначения
```

Общие данные экосистемы лежат под ключами `cw-sender` (отправитель),
`cw-lang*` (язык интерфейса) и `cw-doclang*` (язык документа). Модуль никогда
не читает хранилище другого модуля.

Актуальные номера версий — только в `shared/version.js`. В этом файле и в
разметке хаба их намеренно нет, чтобы они не расходились с реальностью.

## Модули

| Папка | Название | Что делает | Хранилище |
|---|---|---|---|
| `congress-project/` | Конгрессы | Программа конгрессов, распределение заданий, письма участникам в PDF | localStorage `congress-pwa-v34-speakers` |
| `circuit-planner/` | Клиндарий | Календарь служебного года, посещения, формуляры S-302 | localStorage `service-year-planner-v9-4-2` |
| `pioneer-school/` | Школа пионеров | Учащиеся, расписание, учебники, S-253, экспорт | IndexedDB (собственная база модуля) |
| `appointments/` | Назначения | Письмо о назначении и вычёркивании старейшин и служителей собрания (uk/ru/de) | localStorage `cw-appointments-v1` |

Когда-то планировавшийся модуль «Формуляр посещения» **исключён сознательно**:
его функционал полностью поглощён Клиндарием.

## Версионирование

`shared/version.js` — единственный источник версий на стороне хаба:

- `CW_VERSION` — версия оболочки хаба. Отображается в шапке и формирует имя
  кэша service worker'а, поэтому её нужно поднимать при любой правке хаба.
- `CW_MODULES` — версии модулей для плиток.

**Чек-лист выпуска модуля:** поднять версию внутри модуля →
обновить то же значение в `CW_MODULES` → поднять `CW_VERSION`.

Где живёт версия внутри модуля:

| Модуль | Файл и константа |
|---|---|
| Конгрессы | `congress-project/service-worker.js` → `APP_VERSION` |
| Клиндарий | `circuit-planner/app.js` → `App.config.version` |
| Школа пионеров | `pioneer-school/js/app.js` и `sw.js` → `APP_VERSION` |
| Назначения | `appointments/sw.js` → `APP_VERSION` |

## Деплой

GitHub Pages: Settings → Pages → Deploy from branch → `main` / root. Один URL
на весь хаб, модули открываются как подпапки того же сайта. После коммита
GitHub Actions публикует изменения за 20–40 секунд.

---

## Локальный запуск

Service worker и `fetch` не работают по `file://`, поэтому нужен любой
локальный сервер:

```bash
python3 -m http.server 5173
# затем http://localhost:5173/
```
