# journal/AGENTS.md — Журнал

Правила модуля, не история. История — `CHANGELOG.md`.

## Хранение

- Одна физическая база: `circuit-workspace-db` (с v6). Второй IndexedDB
  у Журнала нет и быть не должно.
- Журнал владеет четырьмя хранилищами: `journalNodes`, `journalEntries`,
  `journalLinks`, `journalMeta`. Доступ — только через `CWJournal`
  (`js/data.js`), не через сырой `CWDB.journal*` из экранов.
- Никаких доменных данных в `localStorage` и `CWState`. `shared/state.js`
  не подключается: его блоб зеркалится в localStorage при закрытии вкладки.
- Строки, а не блоб: одна запись = одна строка хранилища.

## Модель

- Узлы: `circuit → congregation → group|pregroup`. Район — рабочий объект,
  а не папка.
- `kind` и `parentId` узла неизменяемы после создания (J3a). `nodes.update()`
  отклоняет попытку сменить любое из двух на другое значение — переноса
  подузлов/смены вида пока нет и не должно возникать частично (иначе узел
  мог бы стать сам себе родителем или увезти детей с устаревшим `circuitId`).
- Идентичность собрания — в `CWDirectory`, узел хранит только
  `communityId`. Расписание встреч и прочие рабочие/презентационные поля —
  собственные поля Журнала (`fields`), в справочник не пишутся.
- Записи — универсальные, `type`: `note|project|question|todo|visit|observation`.
  Значения `kind/type/status/rel` — канонические данные, не подписи.
- Архив — `status`/`archivedAt`, не отдельное хранилище.
- Посещение (J4a) — `journalEntries` с `type:'visit'`, только через
  `CWJournal.visits`; общие `entries.add/update/remove` посещение отклоняют
  (`journal-visit-use-facade`), чтение через `entries.*` не ограничено. Родитель — собрание/группа/предгруппа; `type/nodeId/
  circuitId` неизменяемы; `dateFrom/dateTo` — `YYYY-MM-DD`, `dateTo ≥ dateFrom`,
  пересечения разрешены. Статус `open ↔ completed`, любой → `archived`
  (`archivedAt`, возврат к прежнему) — только через complete/reopen/archive/
  unarchive. Записи внутри посещения несут `fields.visitId`; `visits.remove()`
  отказывает, пока есть записи или связи. Сезонная подпись («весна 2028») —
  производная от `dateFrom`, не хранится.
- Записи посещения (J4b) — `journalEntries` с `fields.visitId`, только через
  `CWJournal.visitRecords`; общие `entries.add/update/remove` их не создают,
  не правят, не удаляют и не «приписывают» к посещению
  (`journal-visit-record-use-facade`). Типы `note|observation|question|todo`;
  `nodeId/circuitId/fields.visitId` берутся из посещения и неизменяемы.
  Текст пользователя — только `body`; `fields` = `{ visitId, format, seq }`,
  без копии текста и без HTML. `format`: `paragraph|heading2|list|quote`,
  у задачи — `checklist`. Задача `open ↔ done` только через `complete/reopen`,
  превращение в задачу — явный `convertToTodo`. Правка возможна только в
  открытом посещении (`journal-visit-readonly`). Порядок — `fields.seq`.
  Удаление отказывает при связях (`journal-visit-record-has-links`).
- Задачи (J5) — один цикл todo для всего Журнала: `CWJournal.tasks`
  (самостоятельные задачи узла + задачи посещений). `open ↔ done` только
  `complete/reopen`; `dueDate` — верхнее поле, снятие срока удаляет поле.
  Задача посещения меняется только пока посещение открыто — экран «Задачи»
  это правило не обходит. `visitRecords.complete/reopen` делегируют сюда.
- Перенос (J5) — `CWJournal.carry`, одна строка на пункт через все посещения
  (не копируется, `fields.visitId` = источник). Открыт: `carryKey`; закрыт:
  поля НЕТ физически (`replaceEntry` через `mutate`, никогда null/''/false).
  `touches[]` = `{ visitId, at, action }`, `raised|kept|deferred|closed`, без
  текста. Входящие для V — из более ранних посещений узла; поднятое в V —
  только в «помечено» V. Общий фасад не трогает задачи и поля переноса
  (`journal-task-use-facade`, `journal-carry-use-facade`). Посещение, на
  которое ссылается история переноса, не удаляется.
- Маршрут — `journal/js/route.js` (`CWJournalRoute.parse/build`), один роутер;
  неполный хвост сводится к ближайшему валидному контексту.
- «На следующее посещение» — строка `carryKey = '<nodeId>:open'`; у закрытых
  записей поле отсутствует. Булево значение ключом IndexedDB не является.
  Пункт не копируется между визитами — история лежит в `touches[]`.
- Поиск (J6) — `CWJournal.search`: только чтение, по требованию, в памяти.
  НИКАКОГО сохранённого индекса, истории/недавних запросов, кэша открытого
  текста — ни в хранилищах, ни в localStorage/CWState. Запрос не пишется в
  хэш/историю. Строка с `sec` не ищется, только считается. Подпись
  справочника (имя/номер/адрес/контакт) — через `resolveCommunity`, в
  памяти. Подсветка — сегменты `{text, hit}`, разметка только текстовыми
  узлами. Нормализация и ранг описаны в заголовке блока в `js/data.js`.
- Архив (J6) — узел только через `nodes.archive/unarchive` (`update` со
  статусом/`archivedAt` → `journal-node-use-lifecycle`), посещение — через
  `visits.archive/unarchive`. Каскада нет ни в архивации, ни в
  восстановлении. «Архивен в контексте» (свой статус, предок, посещение-
  источник) — вычисление при чтении, не запись. Выполненная задача и
  закрытый перенос — не архив. `CWJournal.archive.list()` — только напрямую
  архивные объекты; восстановленный объект под архивным предком доступен по
  дереву, в поиске остаётся архивным до восстановления предка.
- Связи (J7) — только через `CWJournal.links` / `CWJournal.projects`. URN:
  `journal:entry/<id>`, `journal:node/<id>`, `cw:<module>/<kind>/<id>`
  (module ≠ journal; id без `/`, `|`, пробелов). Строка — ровно
  `id/from/to/rel/createdAt`: ни подписей, ни текста, ни данных
  справочника. Локальный конец обязан существовать, внешний — только
  синтаксис; самосвязь и два внешних конца — отказ. Дубликат
  (from/to/rel) не создаётся: `add` идемпотентен, id детерминирован
  `jl_<rel>|<from>|<to>`. Связи неизменяемы (сменить = снять + добавить).
  Связь с посещением или его записью меняется только в открытом
  посещении (`journal-visit-readonly`), с архивным проектом — никогда,
  новая связь с архивным узлом — отказ. Правила держит `data.js`, не
  кнопки. Второго индекса/кэша обратных ссылок нет — индексы from/to/rel.
- Проект (J7) — `journalEntries` с `type:'project'`, только через
  `CWJournal.projects` (общий фасад → `journal-project-use-facade`).
  Владелец — район: `nodeId = circuitId`; `type/nodeId/circuitId`
  неизменяемы. Текст — только `title` (обязателен) и `body` (пусто — поля
  нет). Описание — обычный текст: строки «## » и «- » экран показывает
  заголовком и списком, HTML не хранится. `active ↔ completed`, любой →
  `archived` (`archivedAt`, `fields.statusBeforeArchive` — только enum);
  `unarchive` удаляет оба физически. Архивный — только чтение.
  Отношения — только связи проект → цель того же района: узел
  (собрание/группа/предгруппа) `covers`; посещение, запись, задача
  `relates`; `cw:` — `external`. Никаких `projectIds/linkedItems`.
  Задача проекта — обычная задача района (`CWJournal.tasks`) + связь;
  `addTask` откатывает задачу, если связь не записалась. Прогресс,
  счётчики, история — вычисление при отрисовке. `remove` — только без
  связей в обе стороны, без каскада.
- Маршрут проекта — `#districts/<c>/project/<p>`, в хэше только id.

- Клиндарий (J9a) — только через `CWJournal.planner` (`set/clear/get`):
  `journal:entry/<visitId> → cw:circuit-planner/entry/<entryId>`, rel
  `external`. Особая связь-СЛОТ: одна строка с постоянным id
  `jl_planner|journal:entry/<visitId>`, перепривязка — `put` в тот же ключ
  (меняется только `to`), поэтому две вкладки не оставят двух строк; id
  намеренно не тройной id J7 (у обычных связей он прежний). Строки
  Клиндария вне слота `set/clear` удаляют. Общий `links.add/remove` →
  `journal-planner-use-facade`. Дат/заголовка/
  `plannerId` в Журнале нет — живое чтение через `shared/planner.js`
  (`CWPlanner`, только чтение канона `state/circuit-planner`, маячок
  `cw-state-rev:circuit-planner`). Блоб Клиндария и прежний ключ Журнал не
  читает. Нет записи → «не найдена», связь не удаляется. Выбор — только
  явный. Глубокая ссылка — `#calendar?entry=<id>`.

## Защита (J8)

- Шифрование при хранении ЯВНО защищённого текста: проект — `title`+`body`,
  задача/запись посещения/перенос — `body`. Посещение не защищается.
  Метаданные (id, type, status, nodeId, circuitId, даты, dueDate, carryKey,
  touches, fields, archivedAt, метки времени, связи) открыты. Узлы и
  идентичность собраний (CWDirectory) — вне J8.
- Только Web Crypto (`js/crypto.js`, `CWJournalCrypto` — примитивы и сессия,
  без домена). Фраза → PBKDF2-SHA256 (600 000, соль 16 байт) → KEK →
  AES-256-GCM-обёртка случайного DEK (32 байта). AAD обёртки
  `cw-journal-dek|v1`, записи — `cw-journal-entry|v1|<id>` (перенос `sec`
  на другую запись не проходит проверку). iv 12 байт — новый на КАЖДОЕ
  шифрование, тег 128. Изменяемые поля в AAD не входят.
- Хранится: `journalMeta` `crypto:v1` = `{id, v:1, kdf{alg,hash,iterations,
  salt}, wrap{alg,iv,ct}, createdAt, changedAt?}`; строка —
  `sec {v:1, alg:'AES-GCM', iv, ct}` (base64url). Фраза, KEK и DEK в
  открытом виде не хранятся нигде; DEK в памяти — неизвлекаемый CryptoKey.
- Инвариант строки: `sec` и `title`/`body` вместе не хранятся никогда —
  `assertEntryPersistable` на каждой записи `journalEntries` в `data.js`
  (add/update/replaceEntry/пакеты), не в кнопках. Кривой `sec` не пишется.
- Чтение при открытой сессии отдаёт временные копии: `title`/`body` —
  неперечислимые, их не переносят IndexedDB, JSON и спред. Экраны только
  читают копии (`isLocked/isUnreadable`), сами ничего не расшифровывают и
  `CWJournalCrypto` не трогают.
- Правка текста защищённой: расшифровать → зашифровать новым iv → записать
  только шифротекст. Метаданные (complete/reopen, срок, архив, перенос,
  тип/формат) — без ключа, `sec` байт в байт. Удаление — без ключа. Правка
  текста, защита и снятие — только разблокированным; правила «только
  чтение» посещения/архивного проекта действуют и здесь.
- Запись защиты — `CWDB.batch`: сейф и строка одним пакетом; предусловия —
  строка не менялась с чтения и сейф тот же, от которого ключ сессии
  (иначе блокировка, `journal-vault-changed`). Первая защита заводит
  `crypto:v1` тем же пакетом, что и первую зашифрованную строку.
- Блокировка: старт всегда заблокирован; `lock()`, `pagehide` (и BFCache).
  Скрытие вкладки НЕ блокирует. PIN, passkey, таймер — вне J8.
- Сломанное (шифротекст без сейфа, испорченный сейф, нечитаемая строка)
  не чинится автоматически и не перезаписывается посторонними операциями.
  Забытая фраза = текст не восстановить.
- Поиск: заблокировано — защищённые не ищутся, только `protectedCount`;
  разблокировано — расшифровка в памяти на один `run()`, ничего не пишется.
- Смена фразы — тот же DEK под новой солью; записи не перешифровываются.
- Открытый текст, записанный ДО защиты, мог остаться во внутренних файлах
  хранилища браузера до их уплотнения — это вне модели угроз J8 (как и XSS,
  скомпрометированное устройство и текст на экране при открытой сессии).

## Фикстуры

- Обзор — статическая визуальная фикстура в разметке, кроме блока
  «Проекты района» (реальные данные с J7). Фикстура — не данные: в базу
  ничего «для красоты» не записывается.

## Копия

- Реестр `shared/backup.js`: четыре хранилища целиком + `communities`.
  С J8 четыре хранилища Журнала — набор ЗАМЕНЫ (`restoreReplace`): копия
  модуля заменяет их вместе, одной транзакцией; `communities` сливается.
  Слияние двух сейфов дало бы шифротекст, который не открывает ни один ключ.
- Копия — сырые строки базы, то есть шифротекст; расшифровки при снятии нет.
  `inspect()` до записи проверяет форму `sec`/`crypto:v1`, отсутствие
  открытого текста рядом с `sec` и полноту набора (без фразы).
- Полная копия хаба, снятая до v6, хранилищ Журнала не содержит и при
  восстановлении их не очищает — известная асимметрия, не дефект.

## Код экранов (с 0.9.1)

- Классические сценарии, строго по порядку (`index.html`, прекэш `sw.js`):
  `js/app/core.js` → `districts.js` → `visits.js` → `tasks.js` →
  `projects.js` → `search-archive.js` → `js/app.js`. Без ESM, сборки и
  динамической загрузки; `js/route.js` — единственный маршрутизатор.
- `core.js` — общие помощники (`$`, `t`, `esc`, `svg`, `el`, даты,
  `errorMessage`, `refreshCurrentView`, `destFor`, меню). Экраны — в своих
  файлах; `js/app.js` — только `applyRoute`, FAB, язык/версия, запуск.
- Общий объект — `self.CWJournalApp`: файл публикует только то, что зовут
  другие файлы (`A.x = x`), и берёт чужое через переходник позднего
  связывания `function x() { return A.x.apply(this, arguments); }`.
  Изменяемое состояние экрана (`editor`, `carryView`, `taskTab`,
  `projectUi`, `searchUi`, `archiveTab`, готовность справочника) живёт в
  файле экрана и наружу отдаётся функциями, не переменной.
- Экраны работают с данными только через `CWJournal`; `CWDB`,
  localStorage/sessionStorage — нет. Структуру стережёт
  `scripts/check-journal-app-split.mjs`.
